# 黒猫の日替わり画像をフォルダーから用意する

公開用として確認したAI黒猫JPEGを1〜60枚、専用のローカルフォルダーに入れると、1枚を1日分として連続した配信候補を作れます。60枚なら60日分です。準備後の毎日の編集作業はありません。公開・有効化はこのコマンドでは行いません。

## 用意するもの

- 位置情報、EXIF、コメント、サムネイルなどを除去した公開用JPEG。拡張子は `.jpg` または `.jpeg`、各4 MiB以下、縦横それぞれ1〜2048ピクセルです。見やすさの目安は正方形の1536〜2048ピクセル、顔を中央寄りに置いた画像です。これは画像の変換・メタデータ除去ツールではありません。PNGしかない場合は、その旨を添えて元画像を渡し、ローカルで公開用JPEGを作ってから使います。
- ファイル名を `001.jpg`、`002.jpg` …のように付けた専用フォルダー。ファイル名の文字順で日付を割り当てます。例えば `01.jpg` → `10.jpg` → `2.jpg` です。画像以外のファイル、サブフォルダー、リンク、同一JPEGの重複がある場合は停止します。
- 所有者が承認した開始日、表示するクレジット、画像の公開許可。切り替えは日本時間0時に固定しています。表示クレジットは所有者指定の「ねこのまど」です。

フォルダーと出力先には絶対ローカルパスを指定してください。UNC共有とリンクを含むパスは受け付けません。出力先は既存フォルダーを上書きせず、入力フォルダーの外側に新しく作ります。親フォルダーは先に用意してください。

## 準備する

所有者からの受け渡しは、専用フォルダー（例: `C:\Users\soya_\Documents\Codex\black-cat-images`）に `001.jpg`〜`060.jpg` を置き、フォルダーの場所を伝えるだけです。リポジトリやオンライン共有に画像を入れる必要はありません。開始日と実際に公開する画像は別途確認します。画像を渡すこと自体は公開許可ではありません。

`OfficialWindowService` で実行します。次は書式の例です。日付を所有者が承認した値に置き換え、すべての画像の公開許可を得てから `--publication-approved` を付けてください。

```powershell
node tools/prepare_black_cat_days.mjs --input "C:\public-black-cat-jpegs" --output "C:\black-cat-candidate" --start-date "2026-12-01" --credit "ねこのまど" --publication-approved
```

各画像の公開日は開始日から1日ずつ進み、前日の15:00 UTC（日本時間0時）に切り替わります。実行日の時計は使いません。

## 確認してから公開する

1. `schedule-review.json` の日付・元ファイル名の対応、時刻、クレジット、最終終了時刻を確認します。この確認用ファイルは公開用 `assets` の外側です。
2. 元の画像を順に確認し、黒猫の内容、公開権限、意図した順序を所有者が承認します。ツールは黒猫かどうか、画像の権利、見た目の重複を判定しません。
3. 所有者が候補全体を承認した後、用意された候補を既存の公開手順でデプロイします。このツールはデプロイも、公開先の切り替えも行いません。

公開カタログにはその日の1枚と過去6日分だけを含めます。各画像は最長7日、計画の終了時刻まで表示できます。未来の画像は早い日の配信フォルダーに入りません。同一JPEGの再利用は禁止して、後日の画像が前日に既に配信できる状態を防ぎます。

候補は `schemaVersion: 2` の黒猫専用プログラムです。`assets/__program/index.json` と日別のカタログ・ハッシュ名JPEG、Workerのソースと設定を出力します。公開カタログには元ファイル名や元パス、キャプション、撮影日を入れません。他の公式チャンネルをこの候補に追加しません。

終了時刻を過ぎると、この有限の計画による配信は終了します。自動補充・自動延長はありません。続ける場合は次の公開用画像をまとめて確認し、新しい開始日で次の候補を準備・承認してください。書き込み途中に失敗した出力は使わず、原因を直して別の新しい出力先で作り直してください。
