# 保存済み1枚の縮小・余白比較

## 判断と範囲 — 2026-09-08

Build 8の実機結果は基準3枚が1/1/2候補でCIと一致。保存済み1枚は読み取り成功後にraw候補0件。Build 7では同じ写真を8bit sRGBへ変換しても0件だった。実機で検出器が常に失敗する説は支持されないが、写真内容と取得・縮小後の入力をまだ分離できていない。

本人から提示された画像では1匹の猫の顔が大きく見える。近接構図の影響は仮説であり、根本原因と断定しない。添付画像をリポジトリ、CI、公開成果物へコピーしない。WindowsでApple Visionを実行したとは扱わない。

変更は独立検証アプリの既存「まとめて確認する」のみ。元のraw候補が0件の場合、保存済みA先頭の同じ読み取り済み画像で追加比較する。写真選択・本線プロフィール・個体所属・元の検出条件・ONNXモデル・閾値は変更しない。

## 比較条件

- 画像形式を一度だけ8bit sRGB/RGBXへ統一。原画像と同じ縦横サイズ（最大1024px）のキャンバスを使う。
- 100%は形式統一済み画像そのもの。75%と50%は縦横比・向きを保って中央へ縮小し、灰色RGB(128,128,128)の余白を付ける。切り取り、拡大、回転、個別の明るさ補正をしない。
- 全条件で既存Vision revision 2 / exact Cat / confidence 0.5。比較順100/75/50、3回固定。基準画像3回＋元の保存画像1回＋条件成立時3回の最大7回。各比較前後に取消を確認する。
- raw結果なし、低信頼度などのraw候補あり、画像取得失敗の場合は追加比較しない。保存した画像がなければ従来の基準3枚のみ。
- 形式変更と大きさ変更を区別できる100%対照を置く。ただし縮小では余白と画素補間も変わるので、差が出ても「サイズだけが原因」とは言わない。全て0件でも検出器変更の有効性まで確定しない。

## データと表示

- 既存結果は上書きしない。共有JSONは`pet-detector-controls-v2`で、`savedPhotoScaleComparison`へ各条件の形式・候補数・状態を追加する。
- 比較の結果には切り抜き座標、写真ID、画像、特徴量を含めない。元の保存写真は引き続き端末内の一時サムネイルのみ。取得・保存・共有の範囲を拡大しない。
- 正常な候補0件、変換失敗、検出例外、結果なしを区別する。エラー文字列に含まれる可能性がある私的情報は書き出さない。
- 比較で候補が出ても、元の`cropUsable`や`inputIssue`、`allControlsHaveSingleUsableCrop`を成功へ変えない。個体識別へのfallbackではなく、`modelExecuted` / `identityEvaluated` / `productValidated`はfalseのまま。
- 画面離脱・背景化・選択変更で既存ストアが一時結果を破棄し、遅い完了を受け付けない。選択アーカイブは書き換えない。

## 必要な検証

1. 非正方形の非対称RGB画像で向き・余白・寸法・色形式・100%無再補間を確認。
2. raw0だけの起動、正確に3回、取消で残りを中止、エラーと0件の区別、共有項目と元結果の保持を確認。
3. 既存生成猫画像で全3条件をApple Visionに通し、100%陽性を維持。これは本人写真の再現確認ではない。
4. 対象候補SHAで独立アプリCIを1回実行。実機の保存写真による比較結果と、内部TestFlightの配布状態は別に扱う。
