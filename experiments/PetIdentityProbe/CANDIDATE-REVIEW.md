# 確認付き候補の小さな試作

2026-09-10。Build 14の自動確定No-Goを変更しない。今回は本体ではなく、既存の独立検証アプリで「候補を見て確認する操作」を試す。

最新の提供範囲・保存仕様はBuild 19節、候補表示はBuild 20節を優先する。Build 18以前の「確認結果を保存しない」は当時の仕様であり、過去の本人確認を復元できるという意味ではない。

## 範囲と受け入れ条件

- 保存済みの猫A/B各5枚を見本として再利用。写真は猫別に分けず、1回の選択で最大24枚。利用者に過去の選択や別場面の記憶・自己申告を求めない。選択後に現在保存されている旧評価写真・見本と同じIDだけを自動で外し、残りをそのまま採用する。全部が該当した場合は元の今回用選択を残し、除外件数と次の操作を案内する。キャンセルや不正なIDでも元の選択を保持する。
- 再表示時も、今回用選択と現在の見本・旧評価の重なりをメモリ内で自動除外する。読み込み時に保存ファイルを上書きしない。過去の全選択履歴は存在しないため、保存されていない過去写真までの排除や独立性は保証しない。履歴の蓄積や写真ライブラリ全件走査は追加しない。
- 従来の2番目に近い見本との距離でA/Bの候補を作る。新しいモデル・学習・閾値調整はしない。順位は個体確定ではなく、未登録猫にも候補が出る。
- 猫A/Bの見本と候補写真を表示。違う写真を一括確認から外せる。写真は全体表示で拡大でき、A/B/両方/別の猫/わからないへ個別訂正できる。確認するまで所属を作らず、確認後も本体・Photosへ一切書き込まない。直前の確認は取り消せる。
- 同一burst、近似画像は候補から外し「個別に確認」へ残す。取得・検出失敗や同点も同様。読み取れない写真をA/Bへ一括確定しない。全選択枚数を分母に保持する。近似判定は独立性の証明ではなく、厳密な派生画像検出も保証しない。
- Build 17は既存の `noSingleCat` 件数を維持し、元の入力理由と既存の50％追加検出の結果を組み合わせた内訳 `noSingleCatBreakdown` を追加（共有protocol v2）。未検出、検出範囲が複数、切り抜き不能、画像準備/検出処理エラー、結果未取得を区別する。範囲の複数検出は同じ猫の重複検出も含み、実際の頭数を断定しない。新しい検出・切り抜き・モデル・順位・閾値の処理は追加/変更しない。
- 内訳は個別画面内で表示し、共有には固定カテゴリの組み合わせと件数だけを含める。全内訳件数の和を `inputIssues.noSingleCat` と一致させ、未記録も省かない。写真ID・画像・枠座標・元エラー文字列・個別結果を共有しない。選択が残っていれば同じ写真から再開し、再分類せず「候補と検出結果を共有」で内訳だけを送れる。過去の本人確認結果は保存していないため復元/再推定しない。
- 新しい選択IDだけを保護・バックアップ対象外の固定ファイルに保存。画像・特徴量・候補・確認結果・履歴は保存しない。写真取得は選択分のみ、ネットワークなし。画面終了/バックグラウンドで中断し、画像・個別結果を破棄。遅延完了が画面へ戻らない。
- 集計は「候補のまま本人確認」「本人訂正」「未確認/わからない」と操作件数のみ。確認バイアスがあるため正解率と呼ばず、未登録猫の拒否精度も主張しない。1枚ずつラベルを押すN操作は仮定上の比較目安で、実測した手動操作数・時間ではない。選択・スクロール・見る時間は別であり、タップ数だけで楽になったと判定しない。

## 今回の完了条件と次の判断

保存済み見本の再利用、候補グリッド、除外・個別訂正・取り消し、未確認の保持、限定的な集計共有を専用アプリで試せること。既存判定・保存・本アプリの境界と新しい操作を対象に専用CIを1回実行し、生成画像の画面を確認する。

利用者の新しい写真と実際の確認負担はこのPCでは計測できない。集計と「まとめて確認する方が楽だったか」の回答を受けて判断する。別写真・未登録猫を含む独立した精度評価、実測の手動比較、本体への導入は未完了のまま。現在の試作を製品採用や識別完成と報告しない。

## Build 18：複数の検出範囲にも参考候補を表示

- 対象は候補確認の試作のみ。元の検出が `multipleCats`、追加検出が `originalIneligible` の写真で、既存の枠を再利用する。範囲を追加検出・統合・抑制したり、最大の枠だけを選んだりしない。単一範囲の写真、見本の処理、既存の50％追加検出、モデル、順位・閾値は変更しない。
- 既存と同じ最小32pxの切り抜きを範囲ごとに行い、同じ見本各5枚・2番目に近い距離で参考候補を表示する。処理量は1写真4範囲まで。これは対応頭数の制限ではない。超過、不整合、無効枠は全体を手動確認へ残し、一部だけを成功扱いしない。モデル実行エラー・中断は途中の結果を表示せず既存の中断境界へ戻す。
- 写真全体に番号付き枠、その下に同番号の切り抜きとA/Bの参考候補を表示。同じ猫への重複枠を別の猫と数えず、範囲ごとの候補を写真の一括確認へ昇格しない。本人が写真単位でA/B/両方/別猫/不明を選ぶ。未登録猫もA/Bに近い候補が出る旨を明記。複数範囲の確認ボタンは画面下に固定し、スクロール中も選べる。
- 共有protocol v3。旧 `proposed` は従来どおり写真単位の一括確認候補だけ、旧 `inputIssues.noSingleCat` と内訳も維持する。追加の `multiRegionReview` で写真数・準備できた範囲数・参考候補のある範囲数・本人が選んだカテゴリの件数を分離する。範囲数は頭数でも正解数でもなく、両方の選択も写真1枚として数える。画像・枠座標・各範囲の個別候補・特徴量を共有/保存しない。
- 選択保存方式は変更せず、既存選択をそのまま再利用。従来の写真を選び直したり、既に確認した全写真を再分類したりする必要はない。複数範囲の写真だけを開いて参考候補を確認できる。
- 受け入れ条件：既存の単一範囲処理維持、重複枠を残す、複数猫を一括確定しない、両方と別猫の分離・取消、枠と切り抜きの座標一致、処理量上限/不正枠/中断の安全側処理、写真分母維持、集計だけの共有、既存保存の再利用。検証は対象Swiftテスト・合成画像での通常/小型画面・既存の専用CIを1回とする。実写真の改善や識別精度は未検証。

## Build 19：対象を限定し、確認を保存して再開

- 提供は独立検証アプリの既存内部TestFlightに限定。対象は猫A/Bの2匹、一度の選択は24枚まで。「2匹なら識別できる」という精度保証ではない。3匹以上の個体識別、自動所属、未登録猫の確実な拒否は未対応。1写真4検出範囲は内部の処理量上限であり、4匹対応ではない。本アプリのプロフィール数・手動の複数猫所属に、このA/B制限を適用しない。新しいテスターの招待や公開は別途判断する。
- 今回の1バッチだけに、選択ID、本人の確認、まとめて確認からの除外、直前の取消用の確認結果、A/Bを区別した見本IDの指紋を保存する。画像・特徴量・モデルの出力・履歴は保存しない。従来と同じ独立アプリ内の固定ファイルを原子的に更新し、Complete保護・親フォルダのバックアップ除外を維持する。本人確認は本アプリやPhotosへ書き込まない。
- 保存の成功後にだけ画面の確認状態を変更する。容量不足・古い画面からの更新・破損時は上書きや確認済み表示を行わない。再開時はIDで本人確認を写真へ戻す。表示順を猫の識別根拠にせず、A/Bの見本が変わったら旧結果を保存したまま再開を止め、利用者が明示的にリセットした場合のみ新しい見本で進める。
- 旧schema1の選択は読み取り互換で、読み込みだけでは書き換えない。新しい保存はschema2。古いアプリへ戻した場合は新しい確認情報を黙って落とさず、読み込みエラーとして扱う。Build18以前に共有した集計から個々の写真への確認は復元できない。再分類を必須にせず、残っている選択を利用して、これから行う確認を保存する。
- 再開後も直前の取り消しと、確認した写真からの個別取消・訂正ができる。写真選択の変更では旧確認を捨てる前に確認ダイアログを出し、キャンセルや背景移行で記録を消さない。明示的な消去は今回の選択と確認だけを対象にし、猫A/Bの見本・旧評価選択・原本を残す。
- 「個別に確認」の見出しは0枚でも残す。確認を終えた写真は「確認した写真」にあると案内する。最初の画面で2匹・24枚・本人確認が必要・本体へ反映しないという限界を表示する。
- 共有protocolはv4。復元した本人確認は`previouslyConfirmed`として分離し、今回生成した候補に対する同意・訂正として再集計しない。操作数は画面を開いてからだけで、総所要時間や精度を表さない。共有に写真ID、見本の指紋、取消履歴、個別結果は含めない。
- 新しいモデル、閾値調整、猫数拡張、学習、全写真走査は追加しない。これは確認負担と継続性の改善で、識別精度の改善ではない。次の判定は確認負担、未登録猫を含む別写真での誤候補、似た猫・3匹以上の対象拡張を分けて行う。現在の2匹の結果を他の家庭や3匹以上へ一般化しない。

## Build 20：見本から離れた写真へ候補を強制しない

本人から「UIUXは改善余地があるが、基本的には楽になりそう」との感触を受領。確認作業の有用性を示す定性的な初期反応であり、手動比較・精度合格ではない。今回は候補の表示を控える制御を1点追加する。独立TestFlight・2匹・24枚の範囲は据え置く。

- 旧候補はsecond-nearest順位だけの閉集合A/B検索だった。両方の見本から遠くてもA/Bのいずれかに候補が出る。新候補は最上位猫との距離が、その猫の既存の見本内leave-one-out半径×1.25を超えたら候補を控える。半径0・比較不能も個別確認へ。最上位が範囲外でも、2位へ付け替えない。
- 値1.25は既存基準の再利用であり、未知猫を拒否できると実証された閾値ではない。過去の2枚は半径内で比率の差だけが不足していたため、候補画面に0.70の比率条件は導入しない。旧heldout・診断判定・旧順位比較・既存関数は変更しない。
- 単一範囲写真と複数検出範囲の参考候補に同じ制御を適用する。画像取得・検出・切り抜き・モデル実行の回数を増やさない。複数範囲を写真の一括所属に昇格しない。保留も選択枚数に残し、既存の「個別に確認」に理由を表示する。別の猫と断定しない。
- 見本各5枚だけで半径を計算し、今回の選択・本人確認・以前の評価写真を見本や閾値調整へ入れない。保存済みの本人確認はBuild19の照合と復元を維持する。候補の表示が変わっても、本人の所属判断や写真選択を消さない。新規保存情報・自動学習なし。
- 共有v5 `distanceFiltering` に、旧順位なら候補が出る写真数・今回候補を出す数・控えた数と理由を分離。範囲数は別に集計し、猫の頭数として数えない。前回までの本人確認と旧順位の一致/不一致/両方/別猫/不明を、候補を保持/保留の2行で照合する。今回新しく選んだラベルはこの事前確認照合へ戻さない。Build19以前の未保存確認からラベルを捏造しない。
- 本人確認は候補を見た後であり、上記照合も独立精度ではない。少数の集計から1枚の結果を推測できる場合がある点を既存UIで案内する。写真・ID・個別候補・距離・半径値・枠・特徴量は共有しない。集計のためだけの写真の選び直し/再分類は不要。

### 採用の判断と限界

同じ猫の写真を保留し過ぎたり、別猫をそのまま候補に残したりする可能性がある。候補を減らしただけで精度向上と報告しない。既存の本人確認との照合で、控えることで避けられそうな誤候補と、失う有用な候補を分ける。未登録猫の確認例がなければ拒否性能は未評価のまま。効果が乏しい/負担増なら同じデータへ値を合わせて緩めず、採用を見直す。正式採用には、ルール固定後の別写真・未知猫を含む評価が必要。

設計参考：[Selective Classification for Deep Neural Networks](https://arxiv.org/abs/1705.08500)の「保留により候補を出す割合と誤りを併せて考える」という枠組み。論文の学習・校正手順や性能保証を実装したものではなく、猫識別への有効性を示す資料でもない。現方式との差を明示し、本アプリへの自動振り分けは引き続き導入しない。

受け入れ条件は距離境界/半径0/同点/不正値/2位への付替え禁止、旧判定維持、両経路の適用と追加推論なし、本人確認保存の維持、集計の分母と非公開情報境界。対象テストと小型/通常幅の生成画像を既存専用CI1回へまとめる。
