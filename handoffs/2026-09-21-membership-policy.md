# 会員プランと利用終了時の体験

2026-09-21。制作中LPの無料・有料の区分を、本線の販売準備に採用する。根拠は利用者の「その方針にしようと思う」「すすめて」と、`C:/dev/neko-lp-clarity-alpha-20260918/app/ExhibitionLanding.tsx` の料金・FAQ（同日確認）。価格・体験期間は検証案。以下の終了時の詳細は今回具体化した実装仕様であり、販売済みの契約条件ではない。

課金開始、既存TestFlightの機能制限、既存データ移行は行っていない。LPは別作業中のため編集しない。ADR-026の目的とデータ保全を引き継ぎ、現在の商品条件は本書を優先する。旧「課金と商品化の導線」の物販中心・2匹目課金・年額優先、ADR-026採用時の未決定項目には、本書の現在仕様を適用する。

## 1. 買うもの

**自分の猫の写真に毎日出会い、出来事を書き添え、あとからまた楽しめる体験。**

Widget → 個別写真 → 任意のメモ → アルバムやメモ一覧で再会、を一続きにする。ひとりで使える。猫登録・共有・毎日の入力は必須にしない。機能名を増やさず、現行のアルバム／写真／まどの3タブを維持する。

無料の招待相手も、そのまどで写真と文章を送り返せる。個人メモを共有する場合は、現行どおり送信時に本人が明示して添える。会員加入によって私的なメモを自動公開しない。

## 2. 機能表

| 操作 | 無料 | 会員・有効な体験期間 |
|---|---|---|
| 自分の写真を見る、検索する、お気に入りを付け外しする | 利用できる | 利用できる |
| 作成済みの個人メモを読む・修正する・削除する | 利用できる | 利用できる |
| 保持されている自分の写真・記録の持ち出し | 課金を条件にしない | 同左 |
| 自分の写真の自動アルバム・ピックアップを継続利用 | 体験期間後は会員案内 | 利用できる |
| 自分の写真を表示するWidget・一日一回の選び直し | 体験期間後は会員案内 | 利用できる |
| 新しい写真に個人メモを付ける | 体験期間後は会員案内 | 利用できる |
| 非公開のまどを作り、相手を招待する | 会員案内 | 利用できる |
| 招待されたまどで送り合う・文章を添える | まどの有効な会員支援があれば利用できる | 同左 |
| 届いた写真の閲覧・受信Widget・ハート・保存 | 保持中の写真で利用できる | 同左 |
| 運営の公開まどの閲覧・受信 | 利用できる | 利用できる |

「既存メモの修正」は既存記録に対する操作であり、新しい写真へのメモ作成とは分ける。写真の画質・プライバシー・通報・ブロック・削除を有料の解除機能にしない。

無料で読めることは、サーバーで写真を無期限に保管する約束ではない。通常配送の受領後7日／未受領30日、端末キャッシュの最長90日・500枚・256MiBなど、現行の保持条件は会員権と別に扱う。保管した記録と通常の配送写真を混同しない。持ち出しUIは現在非表示のため、販売前には既存データへの実用的な持ち出し方法を整える。

## 3. ひとつのまどを、ひとつの契約で支える

- 招待相手は、そのまどのために体験申込みや契約をしなくてよい。自分の個人アルバム・個人Widget等を使う場合は、その人の会員権が必要。
- 支払いを止める操作と、利用できる期間の終了を分ける。自動更新を止めても、購入済み期間とApple／サーバーが認める請求猶予中は利用を継続する。
- 利用期間が終了し、まどの有効な支援がなくなった場合、新しい写真・共有文章の追加を止める。既存写真・文章・ハート・保存・本人による削除は、それぞれの保持期間とアクセス権の範囲で維持する。購読終了だけでまど・参加者・写真・鍵を削除しない。
- 受付済みの送信・再試行は追加課金で止めたり二重送信したりしない。どの時点で送信権を確定するかを、サーバーの受付と結び付ける。権利切れを通常の通信再試行待ちにしない。
- 相手の契約で同じまどを継続できる。既存のowner同意・支援世代一致・新支援者の有効契約を用いる。写真の移動、まどの作り直し、招待のやり直しを基本手順にしない。
- 相手へ支払者の課金ID・請求失敗・価格を開示しない。課金上の支援者と、写真・共有鍵の権限を持つownerは別。
- 現行基盤には一契約で最大3まどの支援上限がある。初期販売仕様もまずこの範囲で整合させる。無制限とは訴求せず、上限はLP・購入画面に販売前に明記する。既存βのまどを削除して移行させない。

終了時の表示は、送ろうとした場面にまとめる。まど全体を警告画面で塞がない。

> このまどへの送信はお休み中です。届いている写真は引き続き見られます。
>
> ［送信を再開する］ ［あとで］

「送信を再開する」の先で、自分の契約で続ける／既に契約している人が支える方法を提示する。相手の購入を勝手に開始しない。期限切れと通信・確認不能は別表示にする。

## 4. 最初の体験と購入の流れ

1. 自分の猫で使う人と、招待を受けた人の行き先を分ける。招待から来た人を有料体験へ誘導しない。
2. 自分用の人には、写真権限の目的を伝え、最初の猫写真・アルバムの例が表示できてから会員体験を案内する。写真0件・権限未許可・準備失敗を、体験を開始すれば解決するように扱わない。
3. 会員案内は一画面。本人の猫写真と「毎日の一枚」「猫らしいアルバム」「写真に添えるメモ」、任意の招待を示す。新しい機能分類やタブは作らない。
4. 対象者のStoreKit商品から、実価格・期間・無料体験対象可否を表示する。明示申込みとApp Storeの確認で開始。インストールだけで開始しない。
5. 購入とサーバー確認が完了したら、求めていた写真・アルバムへ戻る。取消なら同じ画面へ戻り、編集中の文章を保持する。確認待ちを購入成功と誤表示しない。
6. 設定から契約管理・購入を復元へ進める。購入の復元は写真・iCloud記録の復元と分ける。写真を開くたびに勧誘を出さない。

初期の検証案は**一種類の会員、月額980円、対象者の初回7日間無料**。年額は今回の販売準備に必須としない。980円を最適価格、7日間を最適期間とは断定しない。Appleの商品情報と対象可否が取れないときは、仮価格や全員対象の「無料」を購入ボタンに表示しない。

## 5. 終了・通信不調の境界

| 状態 | 必要な挙動 |
|---|---|
| 更新停止、利用期間中 | 期限まで継続。即座に機能を止めない |
| 無料体験終了・利用期間満了 | 表の会員機能に限定して案内。私的記録を消さない |
| 確認中・オフライン | 過去データを表示し、取得済みの有効な権利／猶予の範囲で扱う。確認不能を未契約と決めつけない |
| 返金・失効が確認された | 新しい有料利用を止める。写真・文章の削除とは連動しない |
| Widgetの個人利用期間終了 | 空白や無関係な公式猫へ切り替えない。既に表示している写真とその閲覧入口を維持し、新しい選定の停止を控えめに示す |
| 別端末へ機種変更 | 購入権、写真への権限、個人メモ／保管記録、まどの端末資格を別々に復元する |
| 同じまどの支援者交代 | 新しい支援権・owner同意・世代を確認し、既存の写真と共有範囲を維持する |

共有終了・相手の取り下げ・写真権限の取消など、安全上の失効は会員状態より優先する。「過去写真を表示する」を理由に失効した共有資格や取り下げ写真を復活させない。

## 6. 現行実装との対応と、次の実装順

| 順 | 既にあるもの | 追加するもの／完了条件 |
|---|---|---|
| A | `PlusPurchaseStore`、Apple署名＋サーバー権利確認、購入復元 | 月額だけで構成できるようにする（現行は月額・年額の両ID必須）。実商品由来の価格・体験資格を表示する会員案内。販売前は内部検証の入口だけで使用 |
| B | `PlusEntitlementState`、`BillingWindowPlusAccessState` | 本文の操作別権利へ接続。個人契約とまど支援を混ぜない。βには制限を適用せず、検証状態で期限内／終了／確認不能を確認 |
| C | まどの支援・owner解除・支援者交代と世代保護 | 両者の送信・受付済み処理にサーバー側の権利判断を接続。過去閲覧・本人削除・ハートを保護。端末の見せ方だけで有料権利を成立させない |
| D | メモ、個人保管、共同記録の実装 | 実2台の復元／共有反映、保管容量・保持・終了時救済・持ち出しの未確認を確定。確定前は「無制限の保管」を会員特典へ追加しない |
| E | LPと既存StoreKit基盤 | LP／購入画面／App Store条件／実挙動を一致させる。既存β移行と外部提供範囲を決める。販売開始は別の明示依頼後 |

現時点では課金基盤は無効で、通常画面・Widget・送信の制限には接続されていない。本書を更新しただけでA〜Eの実装完了とは扱わない。

## 7. 評価と必要な検証

- 有料体験の評価：本人の写真を初めて楽しめるまでの到達、別日の自然な再訪、Widgetからの閲覧、任意のメモと再閲覧、招待相手の参加、体験からの有料転換、その後の更新と解約理由。毎日の入力数を目的にしない。
- 採算：実際の有料継続と、写真配送・保管・サポート・獲得費から判断。LPのクリックや7日間の好評だけを、継続課金の証拠にしない。
- 実装検証：操作別の権利・期限境界はロジックテスト中心。本人と相手／権利確認不能／支援交代／過去データ保持を独立レビュー。画面操作は購入案内→取消または復元→元の目的へ戻る代表経路に絞る。機能と関係ない既存画面の一式を繰り返さない。
- 今回は設計文書のみ。差分・参照整合と既存の開発フロー検査を使い、ネイティブビルド、画面操作テスト、TestFlightを起動しない。最初のpreflightで`NekoWidget/docs`内の文書更新まで未分類full-v1（過去64〜98分）になることが判明したため、製品文書への編集は戻し、従来のhandoffsに現在仕様を集約した。最終差分はこの仕様と台帳のみ。製品・検証コード・CI判定を変更せず、重いCIは起動していない。
