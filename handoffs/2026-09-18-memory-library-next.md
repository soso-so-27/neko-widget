## 入口と読書体験：一案に決める

既存「アルバム」の本文先頭、ピックアップより前へ、**「思い出のメモ　12件 ›」という画像なしの44pt以上の一行**を置く。メモがある時と読込失敗時だけ表示し、未使用の人の画面に空の棚を増やさない。お気に入りは現在の右上bookmarkを維持する。新タブ・大カード・新しいrootの猫別入口は追加しない。写真を楽しむ主部を押し下げすぎず、書いた言葉へ直接戻れ、写真0件・権限なしでも入口を同じ場所に保てるため。件数は保存メモの件数であり、現在見える写真数ではない。読込失敗を「0件」と表示しない。

`LikedPhotosView.body`（現在1050行付近）の `hasPhotoAccess` 分岐**外**に配置。`MemoriesRoute.memoryNotes` / `.memoryNote(recordID:)` を `MainTabView.memoriesDestination` で解決する。本文をrouteへ詰め込まない。`AppRootView.regularContent` は拒否時もMainTabを表示するため接続可能。

一覧「思い出のメモ」は更新順の行。本文2行、日付、利用できる場合だけ小さな写真を添える。行からまず**メモ本文を主役にした詳細**へ入り、「写真を見る」で既存PhotoBrowserへ。原本がなくても同じ詳細で全文・編集・削除・書き出しを使える。空状態は「写真に思い出を添えると、ここで読み返せます」＋既存写真入口。猫登録は不要。N26では猫filterや検索を増やさない。

## 記録と写真を分離する

`PhotoMemoryNoteStore`（現在schema 1）は写真ID→`text / updatedAt / revision`のみ。**updatedAtを「書いた日」や「撮影日」に流用しない**。schema 2の保存レコードへ、安定した記録UUID、任意の初回記入日時 `writtenAt`、任意の撮影日時snapshot、本人が指定した猫参照（profile UUID＋指定時の名前）を追加する。写真のローカルIDは独立した参照として保持し、一覧・詳細・削除は記録UUIDで動く。

新規は初回保存時にwrittenAtを記録し、編集では維持する。既存v1は原記入日時が分からないためnil、「書いた日不明／更新日…」と表示・出力する。撮影日・本人指定の猫は写真からメモを保存する際に初回だけ補い、取得できなければ不明のまま。一覧からの本文編集では写真情報を補完・再判定しない。v1→v2は一度だけatomic migrationし、失敗時はv1 bytesを保持して再試行可能にする。将来schemaを古い形式へ変換しない。

猫は**写真で本人が既に指定したプロフィール**を参照する。メモを書くたびに別の猫選択を要求せず、AIの推定や共有相手の猫を補わない。プロフィール削除・改名・写真の所属変更でメモを消したり別猫へ付け替えたりしない。削除済みは同名の新プロフィールへ自動再結合しない。現在 `AppRootView.mainTabContent` は権限なしでidentityをnilにするため、写真・猫が解決しなくても本文を読める状態を保つ。

## 原本がない場合と持ち出し

| 境界 | 挙動 |
| --- | --- |
| 写真権限なし／限定権限から外れた | 本文を表示し、写真は出さない。設定は既存のアプリ設定から変更可能。記録は保持する |
| 写真IDが現在解決不能 | 「元の写真を開けません」。削除と断定せず、別写真・似た写真・同名猫で代用しない |
| アプリの写真対象／猫候補から除外 | 記録自体は残す。写真表示は既存の認可・対象判定を尊重し、メモ一覧から迂回表示しない |
| メモ削除 | 対象本文の確認後、記録UUID＋期待revisionで削除。原本・お気に入り・猫プロフィールは変更しない |
| 破損／未来schema／読込失敗 | 空扱い・部分上書き・削除・通常exportをしない。再試行またはアプリ更新の案内。元bytesを保持する |

明示操作「書き出す」で、詳細はその1件、一覧は全記録を対象として件数と含む情報を確認する。**写真なしでも本文を持ち出せる**ことを必須にする。UTF-8の `memories.json` と読みやすい `memories.txt` を一つのbundleにし、本文・書いた日（不明はnull）・更新日・分かる撮影日・本人指定の猫名を含める。書式version、日時のUTC offset、記録ごとのexport IDを付ける。PhotoKit ID・端末パス・内部profile ID・共有tokenは出さない。猫の同名区別が必要ならbundle内だけの猫参照を使う。

N26の一括書き出しは**メモと日時等の記録のみ**と画面に明示する。写真の書き出しは既存の個別写真の経路を維持する。原本・Live Photoを含む完全なアーカイブは、N29の保存・復元設計で扱う。加工JPEGを原本と呼ばず、この段階のメモexportを完全バックアップとして案内しない。

export開始時に対象・revision・本文をsnapshot化し、保存中の別メモへ切り替わらない。取消・sheet終了・失敗で専用一時ファイルと処理を片付け、元の記録に印を付けたり変更したりしない。途中ファイルは保護＋backup除外、完成bundleは明示した共有先へだけ渡す。共有先に渡ったコピーの削除まではアプリが保証しない。

## APIの接続先と完了条件

- `Services/PhotoMemoryNoteStore.swift`：既存 `note/save` の写真ID入口は維持し、`records()`、`record(id:)`、`delete(id:expectedRevision:)`、本文とmetadataを同時更新する保存口を追加。列挙はPhotoKitアクセスを要求しない。全体のread-modify-atomic-writeと競合検出を継承する。
- `Views/PhotoMemoryNoteView.swift`：写真必須のeditorを記録必須・写真任意へ拡張。一覧／詳細presentationで「確認中・利用可・利用不可」を管理する。写真解決は画像読込と分離し、限定権限の失敗を永久削除へ変換しない。
- App専用のexport service：保存schemaそのものを公開せず、上記portable schemaへ変換。既存JPEG/PDF exportの「共有captionへ個人メモを流さない」境界は維持する。`AppPresentationModels` のスキャン用PhotoPresentationやWidgetManifestへ本文を追加しない。
- 現在の保存先は**OS backup対象**（主担当修正済み）。OS設定・実行状況によってバックアップされることと、アプリ同期／端末間PhotoKit ID再結合は別。本文ファイルが復元されても写真再結合は未保証。exportにも復元・import機能の完成を表示しない。

完了確認は、(1) 登録なしでアルバム→記録→元写真→戻る、(2) 権限拒否／限定解除／原本消失でも全文・編集・明示削除・メモexportが可能、(3) v1日付を捏造せず移行し猫profile消失でも残る、(4) export内容・取消で本文漏出／別記録混入／残留一時物がない、(5) 未来schema・書込失敗・競合で保全、の境界に絞る。既存保存verifierを拡張し、既存写真詳細UI fixtureに一覧往復と写真なしの代表ケースを接続する。標準／最大文字の製品描画を確認。N27以降の年表・共同編集・クラウド同期・価格検証は追加しない。

## 実装記録（2026-09-18）

- `PhotoMemoryNoteLibraryView`：アルバムの小さな入口、更新順一覧、本文詳細、写真なしの編集・削除、明示した1件／全件のZIP書き出し。写真はcurrent source・除外とPhotoKitの実在／権限で絞る。
