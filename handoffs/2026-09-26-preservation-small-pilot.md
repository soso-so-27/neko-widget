# 有料化前の小規模検証枠・費用・停止条件

2026-09-26。利用者は「先に小規模な検証枠を決め、その枠での費用と停止条件を具体化」に同意。
この資料は検証の設計。**有料化・遠隔への上限設定・一般公開は未実施。請求の絶対上限ではない。**

## 1. 最初の検証枠

| 項目 | 枠 |
| --- | --- |
| 対象 | 運営の指定した最大3人。一般の申込受付なし |
| 期間 | 初回7日。自動で期間延長・人数増加しない |
| 現行写真・メモ | 1人1GiB、全体3GiB（約3.2GB）。写真と同量の復旧コピーを別途保持 |
| 保存件数 | 1人200件以内。全体の新規保存試行は1日50回、月300回以内 |
| 新規データ受付 | 月3GiB以内。失敗・新規保存の再試行も枠を消費。写真+最大メタデータ分を予約 |
| 編集等の追加処理 | 全体1日100回・月500回。新規・編集・同じ保存の再試行をすべて予約する制御をローカル検証済み |
| アクセス | 本人単位30回/分を設計値とする。既存IP制限を人数/全世界の厳密上限に読み替えない |
| 自動再試行 | 保存要求の自動無限再試行なし。修復・通知queueは別に上限/遅延/失敗隔離を確認 |
| 画像検証 | basic 1台、無通信1分で停止。月10稼働時間で見直す。10時間の強制停止は未実装 |

これは商品容量ではない。撮影原本・動画を全保存する計画でもない。
期間終了は新規受付を止める意味で、保存済みの写真を勝手に消す期限ではない。

## 2. 月額の条件付き計画（1週間でも固定費は1か月分で計上）

仮定：1米ドル180円、税相当10%を加算。月額の実請求/為替を保証する数字ではない。
クラウドは同じアカウントの他用途と無料枠を共有するため、次の2例を分ける。
スクリプト `node NekoWidget/PreservationService/scripts/estimate-pilot-budget.mjs` で再計算可能。

| 内訳 | 月の計画額 |
| --- | ---: |
| Workers基本料金 + KMS鍵1個（$5 + $1） | 1,188円 |
| R2写真3GiB + S3復旧写真3GiB・履歴仮枠0.5GiB | 約30円 |
| 画像検証サーバー10時間（含まれる無料分を差し引かない） | 約60円 |
| AWS操作・転送・DB・通知などの予備費 | 500円 |
| R2操作が共通無料枠内に収まる場合の合計 | **約1,800円** |
| R2操作無料枠なしでA/B各100万回の有料単位が新たに発生する場合 | **約2,700円** |

500円は実測料金でも処理費の上限でもなく、予備の割当。履歴0.5GiB、画像検証10時間、
R2 A操作1万/B操作5万は検証シナリオであって実測結果・保証最大値ではない。
KMSは鍵1個・追加ローテーション版なし、原本を劣化させる変更なし。
S3東京のStandard容量は$0.025/GiB月。R2容量は十進GB単位に切上げている。
R2操作は少量でも無料分超過時に100万単位へ切上げるため、$4.50+$0.36を別に計上。
他用途の既存有料単位に余りがあればこの全額が増分になるとは限らない。

参考の異常例：同じbasic 1台がCPU上限で30日間動き続けると、無料枠を除外した
上記方式では予備費込み約6,700円。これは起きると予測した額でも請求の最大額でもない。
**1台にしただけでは月3,000円を保証できない**ことの例。

## 3. 停止条件

- 月末費用の見込み1,800円：警告と内訳確認。基本料・実在庫・履歴・操作/転送を含める。
- 同2,200円：新規保存と検証枠の拡大を停止。3,000円との差800円を未反映請求等の余裕とする。
  余裕があっても超過ゼロの保証にはならない。
- 1人/全体容量、日/月試行数、月受付bytesのいずれかに到達：新規保存を拒否。
- 費用/在庫の確認が24時間以上途切れた場合：新規受付を再許可しない。
- S3履歴が試算枠0.5GiBを超えた場合：予算内と推定せず、実在庫と月末見込みを再計算して判断。
- 本人確認不能・課金情報不明・必要な制御欠落：提供開始しない。
- 異常な処理連続・サーバーの停止失敗：画像検証と新規書込みを止め、原因確認後に手動再開。
- 通常の閲覧・持ち出し、保管のためのKMS復号を、予算到達だけで一括無効化しない。
  ただし大量連打の短時間制限は別。写真の破棄を費用削減策にしない。

約2,700円側の見込みになれば、2,200円の開始/継続条件を満たさない。
その場合は**そのまま開始しない**。枠の空き・実際の費用内訳と構成を再検討する。
利用量を減らしてもR2の追加100万単位課金が比例して安くなるとは計算しない。

## 4. 実装済みと未完を混ぜない

| 制御 | 現在 |
| --- | --- |
| 1人/全体の現行保存量 | サーバーの既存コードあり。今回の数値は実環境に未設定 |
| 日/月の新規受付回数・月bytes | ローカル実装済み。上表の数値で競合時の境界検証成功。遠隔未適用 |
| 運用確認が古い場合に新規受付拒否 | ローカル実装済み（24時間）。費用取得・判断の自動化は未接続 |
| 3人の本人限定・初回7日終了 | ローカル実装・競合試験済み。Apple検証済み本人のHMACを最大3件許可し、DB上も4人目を拒否。本人リスト/遠隔設定は未登録 |
| 編集/再試行・全体の処理枠 | 全PUTを日100/月500回まで単一SQLで予約。失敗も消費。ローカル実装・試験済み、遠隔未反映 |
| 個人単位のアクセス制限 | 準備が必要。Cloudflareの既存RateLimitは拠点ごとの概算で厳密課金計数ではない |
| Container台数・無通信停止 | 既定OFFの設定あり。実配備後の停止確認と異常時停止は未確認 |
| 1,800円警告/2,200円新規停止 | 運用確認の予測額2,200円以上で新規登録/全PUTを拒否するローカル制御あり。各社通知・実費集計との接続は未設定 |

開始前に、無料枠の残量・対象アカウント/通知先・上表の制御を実環境で照合する。
確認できない条件を「設定済み」と扱わず、費用制御が整う前にPaid化しない。
この計画の了承を、無制限の費用超過や公開・利用者課金への了承と読み替えない。
