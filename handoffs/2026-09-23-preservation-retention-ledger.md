# 個人保管：期限時計の安全な土台（候補、2026-09-23）

利用者指定は「会員期限切れ後、12か月の閲覧・持ち出し期間と事前通知後に削除」。この候補は `0005_retention_ledger.sql` と `RetentionLedger` に期限時計だけを実装し、`RETENTION_TRACKING_ENABLED=YES` のcronで本人リンク済み会員の状態を少数ずつ確認する。既定OFF。メール送信、最終消去、バックアップ内消去を一切起動しない。

- `expired` を確実に確認した時点から12暦月。解約・自動更新停止の日ではない。2月29日は翌年2月28日とする。
- `active` / `grace` への復帰で時計と通知記録を取り消す。次に期限切れになれば新しいエピソード。
- `unknown` や請求照会の失敗は時計を一時停止。復旧時に停止分だけ予定日を後ろへ延ばす。照会失敗を期限切れとして扱わない。
- 「最終通知」は将来の通知providerが実配送のreceiptを得た時だけ記録し、その時点から最低30日を確保する。旧エピソードのreceiptや異なる再送receiptで上書きできない。
- 消去可否関数は、新鮮な会員状態、12か月経過、最終通知30日前、保留なしの条件を満たしても**助言値だけ**を返す。まだ削除workerへ接続しない。実際の削除には課金再確認、primary/backupの対象棚卸し・削除・証跡・失敗時再試行が必要。
- migrationはデータの削除・既存行の推定をしない。会員リンク済みownerのみ台帳行を作る。競合更新はrevisionで拒否する。

ローカルD1の5ケース（期限切れ、確認不能、遅い通知、再加入、うるう日、未リンクを含む）が成功。実Apple/購入provider、通知、実R2/バックアップの証拠ではない。公開文言への反映は禁止。通知先と運用については[保持・鍵設計](2026-09-23-preservation-retention-key-decision.md)を正本とする。
