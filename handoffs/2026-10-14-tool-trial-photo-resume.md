# ツール試験保存の写真再開

## 変更

試験保存の入力 fingerprint が JSON のプロパティ順に依存し、同じ内容の再送でも受付停止になっていた。新しい試験保存では toolBackup の7項目を固定順で hash する。

既存 slot は書き換えない。元の順序の再送は従来の hash で照合し、写真だけは空 payload・既存タグ・バイト数の一致を先に確認して最大7!順を逐次照合する。元の文書全体と写真 SHA の hash が一致した場合だけ旧 fingerprint を引き継ぐ。JSON/index の大きい payload を列挙しない。旧 JSON の順序変更まで復旧する機能ではない。

所有者、期限、消費済み枠、確定済み記録、署名・暗号化・通常受付条件を維持する。migration、試験枠の再発行、counter reset、新規契約、定期タスク、native の変更はない。

## 直接検証と未確認

- 修正前に同一内容・順序変更だけで PILOT_WRITES_PAUSED になることを workerd/D1 の owning test で再現した。
- 修正後の型検査と owning 15件が成功（8.98秒）。旧写真の未確定再開・確定済み再送・文書/日付/写真/所属の拒否境界、旧 JSON の元順序だけの互換を含む。
- 写真の全5040順を必要とする、400文字の日本語を含む合成文書で10秒未満を確認した。実AWS処理や端末での完了時間の測定ではない。
- 初回追加テストの失敗は、既存の再認証に伴う owner recovery 呼び出しを「ゼロ」とした想定違い。写真再暗号化なし・revision維持の検査へ訂正し、製品の保全条件は変更していない。
- 保存・暗号化境界の独立レビューで blocker なし。実端末の送信本文の順序は取得しておらず、実機原因が確定したとは扱わない。

## 配布条件

別の control 候補で `preservation-tool-trial-fingerprint-v1` を main に登録してから、製品同 SHA の owning Preservation 全チェックと iOS plan を実行する。native/JPEG等の入力不変を閉包で確認する。CIは実端末の保存成功ではない。

最初の再現候補は2026-10-14 13:43:13 UTC。直近の別scope実績は control plan約50秒、製品plan約48秒、backend約99秒。今回scopeは初回で未計測。2段階のCI実行約2.5分にqueue・レビュー・統合・クラウド反映の時間を加える計画とする。

クラウド反映は固定bundleだけ。既存account/Worker/D1/R2、設定・secret参照・公開範囲・cron・試験枠/slot fingerprintの前後一致を照合する。不明な反映結果を自動再試行しない。実端末の再開と全件完了は反映後の別確認として残す。
