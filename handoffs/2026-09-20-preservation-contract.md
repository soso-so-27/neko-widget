# N29：保管と引き継ぎの約束

2026-09-20。基点 `a082d6b`。既存の個人保管を使う人が「何を残し、何を取り戻せるか」を確認するための整理。N29全体の完了や販売開始を意味しない。家族共同記録の保持・復旧条件は別契約であり、このiCloudの説明を流用しない。

## 現行の事実

| 確認すること | 現在の提供範囲 |
|---|---|
| 保管対象 | 本人が明示して選んだ写真の閲覧用コピーとメモ。記録にある撮影日・記入日・猫名を含む。メモ作成や案内の閲覧だけでは保管を開始しない |
| 写真と容量 | JPEG長辺最大4,096px、1枚 `20 * 1024 * 1024` bytes以下、本文500文字以内。原本・動画・Live Photosの動き・元写真の位置情報は保管対象外 |
| 総容量 | 個人保管にアプリ独自の総件数・総bytes上限は設けていない。本人のiCloud容量を消費し、空き不足では未完了になる。「無制限」の提供保証ではない。現UIは総使用bytes・iCloud空き容量を取得していない |
| 機種変更・紛失 | 同じApple Accountで、アプリの「iCloudから読み込む」から保管済み記録を取得する機能。未保管の端末メモや未送信の変更は、この機能の復元対象に含まない。別端末のPhotoKit IDに自動で結び直す保証もない |
| 編集・削除 | 反映を明示同意したメモの変更だけを保管先へ反映。保管コピーの削除は写真アプリの原本・元メモ・他の共有コピーの削除とは別。未完了・異なる変更を保管済みと扱わない |
| 現時点の試験 | 現在はテスト利用。189の利用者端末で保管済み表示を確認。空ローカル復元と保存境界の自動試験はあるが、別の実iPhoneへの復元・実2端末の反映は未実証 |

実装根拠は `PersonalArchiveImage` の画素数/bytes上限と再エンコード、`PersonalArchiveStore.maximumCharacters` / `maximumJPEGBytes` / `PersonalArchivePayload.validate`、`PersonalArchiveCloudClient` のprivate database・アカウント確認・全ページ取得・quotaエラー。読込の `resultsLimit: 100` は一ページの件数であり、100件の保存上限ではない。

本人のiCloud容量を使用する仕様は、2026-09-20に確認した[Apple公式 privateCloudDatabase](https://developer.apple.com/documentation/cloudkit/ckcontainer/privateclouddatabase)に基づく。運営終了後の読出しや無期限保持の根拠にはしない。

## 採用済みの商品原則

[ADR-026](../NekoWidget/docs/ADR-026-うちの子との時間と会員体験.md)と本バッチの利用者指示を維持する。

- 過去の記録の閲覧を有料で閉じず、解約だけを理由に自動削除しない。
- 本人が残した記録へのアクセスと持ち出しを守る方針で設計する。
- 原本保管や、無期限・無制限のクラウド保存は約束しない。
- 利用者指定で非表示にした本文ZIPの持ち出しUIは復活させない。保管写真を含む持ち出しを実装済み・提供済みとは表示しない。

今後の方針を、現在存在する課金・解約機能や運営終了時の持ち出しサービスと取り違えないよう、商品原則と未確定条件はこの引継ぎ資料で管理する。製品の案内は、現在の保存対象・復元対象・容量と画質・編集と削除だけに絞り、販売準備や内部の検証状況は表示しない。実別端末の未実証という状態は、以下の開発完了判定に残す。

## このバッチの変更と残る実証

2026-09-21更新：製品 `6f63740` の候補 `35539105210` で、保管案内と未反映本文→再試行、既存メモの編集/再開、共同記録の作者・取り下げ・退出を含む関連10操作が成功した。本線反映済み。下記の初期時点の実行待ち記載は経緯として残す。別の実iPhoneへの復元、実2台での反映、支払意思は引き続き未実証。

通常の保管画面は、この端末で確認した保管済み件数・要確認件数と読込・再試行を中心にした。詳細は「保管と引き継ぎについて」へ分離し、画質の具体値も必要時に開く。件数はクラウド全体の照会結果ではない。

端末メモのoutboxにだけ反映待ちが残る場合も、現在のアカウントとの照合後に要確認へ数え、既存の再試行を表示する。旧保管コピーがstoredでも最新の本文まで保管済みとはしない。pendingとinFlightが同じ記録にあれば1件として数える。現在アカウントの最終確認・画面世代の確認・アカウント通知時の表示破棄を維持する。Store/Coordinator/CloudKit/共有側の保存処理・schemaは変更していない。

主担当の独立レビューを反映し、再試行の表示条件は従来の `pendingOperationCount() > 0` と端末メモの反映待ち集合のORを使う。削除待ちが写真・本文の一覧に現れない場合でも、archive outboxの再試行入口を失わない。件数取得後も同じアカウントを最終確認する。

既存 `SoloMemoriesUITests/testPersonalArchiveRestoresPhotoAndTextAndExplicitlySavesNewText` に、案内画面と保存範囲の描画、案内閲覧で保管記録を読み込まないこと、端末outboxのみの未完了→再試行→最新本文の確認を追加した。fixtureは一時store・mock transportだけを使用する。

- Windowsで差分と `git diff --check` を確認。Swift/iOSの実行環境がないため、追加したUI操作と製品描画の確認は主担当の候補CIへ引き継ぐ。未実行のテストを成功済みとしない。
- 実iPhoneでの引き継ぎは、アプリ削除や記録の作り直しを求めず、既存の保管記録を別端末で読み込む証拠が必要。現在の自動試験やmock成功では代替しない。
- N30で実利用・保管原価を確認し、価格、販売時の容量、保持期間を確定する。解約後・運営終了時の持ち出し方法、受付期間、アプリが利用できなくなる場合の救済手段は、その実装・検証とともに販売前に確定する。
- 課金・一般公開・新たな保存契約・自動削除・Apple契約同意・live CloudKitの操作は実施していない。
