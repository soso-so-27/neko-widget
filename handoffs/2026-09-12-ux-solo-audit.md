# 一人利用・写真導線の限定 UX 監査

対象: `e273e72` の Home / ローカル写真詳細 / Monthly / Growth / Seasonal / 初回 / ローカル写真 Widget 遷移。以下の行番号は変更前。まど・共有の仕様は主担当の監査に委ねる。既存 native 画像はシミュレーターの fixture であり、今回の実機操作や実写真の表示品質を確認したものではない。

## 優先修正

### SOLO-01 写真詳細が操作欄に場所を使い、拡大できない

- 確定: `LikedPhotosView.swift:1790–1915` は写真と最大260ptの常設操作欄。`PhotoAssetImageView.swift:118–121` は `scaledToFit` のみで、ピンチ/ダブルタップ操作はない。月の便りも同じ非拡大画像を使用 (`MonthlyWindowView.swift:48–56`)。
- 画像: [同日の2枚目を保存した詳細](C:/dev/neko-visual-simplify-20260912/output/visual-simplification/matrix/ios-26-2/composer-screenshots/506C27CC-AF2D-4E30-B751-C6A03623D7D0.png) で、日付・同日一覧・大きい保存済み表示の縦積みを実見。拡大不可はコード判断。
- 影響: 写真の細部を確認できず、毎回使わない説明と操作が鑑賞領域を圧迫する。
- 修正: ローカル写真詳細は共通の写真レイアウトと既存 zoom 表示を再利用。日付/同日導線、保存、送信をコンパクトに配置。Widget の更新説明は写真メニューから開く。保存の意味と送信先確認は維持する。Monthly の読書型構造変更は今回保留。
- 確認: 縦横写真、通常/最大文字、横スワイプ→拡大→パン→等倍→次の写真。拡大中は別写真へ移動しない。保存/送信が表示中の写真 ID を使うこと。

### SOLO-02 同日一覧を繰り返し積める

- 確定: `LikedPhotosView.swift:1818` はどの写真詳細でも同日一覧を push。`2246–2264` は同日一覧の写真から同じ `PhotoBrowserView` を作り、`2593` でさらに push する。既に同日一覧配下である文脈がない。
- 影響: 写真→同日一覧→写真→同日一覧を繰り返すと、元の写真へ戻る手数が増える。
- 修正: 同日文脈の日付を子ブラウザーへ渡し、その日と同じ一覧を開くリンクは表示しない。別の日への導線、写真の順序、元のページ選択は維持する。
- 確認: 同日一覧から2枚目を開いた詳細に重複リンクがなく、戻る1回で同日一覧、さらに1回で入口の写真に戻ること。撮影日不明でも正常表示。

## 候補として保留

### SOLO-03 保存の取り消しが重い

- 確定: 保存は1タップ (`LikedPhotosView.swift:1857`)、解除はメニュー→解除→確認 (`1837`, `1978–1997`)。月の便りは保存後ボタンが無効 (`MonthlyWindowView.swift:167–183`)。
- 影響: 誤って保存した写真を、その場で簡単に戻せない。
- 最小案: 保存状態変更の副作用/台帳境界を確認した上で、解除+Undo等を検討する。写真削除や候補除外の確認とは分ける。今回は確認を維持。
- 確認案: 月の便りで保存→取り消し→再保存、元写真の存続、同じIDへの反映、思い出一覧の位置維持。解除の実データ処理は未監査。

### SOLO-04 写真が多いと「もっと見る」を何度も押す

- 確定: Home は初期24枚 (`HomeView.swift:27`)、24枚ずつ手動追加 (`180`, `197–206`)。400枚目のサムネイルへは16回の追加操作を要する計算。
- 影響: スクロール途中に同じ操作が繰り返される。詳細内の横送りは既に別経路としてある。
- 最小案: 下端で次の小さいバッチを自動表示し、既存の遅延描画・キャッシュ上限を維持。年月ジャンプは追加の設計候補。
- 確認案: 400枚で下方移動、詳細→戻るの位置、追加時のID重複なし。大量ライブラリの実機性能は今回未計測。

### SOLO-05 写真の読込失敗から同じ画面で再試行できない

- 確定: `PhotoAssetImageView.swift:132–142` は失敗説明だけ。読み取りは `155–170` の固定 LoadKey で開始し、失敗を `443–445` で確定。画面内の再試行操作/ネットワーク復帰トリガーはない。
- 影響: 「通信できるときに再度読み込みます」を見て待っても、同じ詳細に留まるだけではアプリ側は新しい要求を出さない。実ネットワークでの再現は未実施。
- 最小案: 写真詳細の失敗状態に同じIDの再試行を置き、世代管理・キャンセルをそのまま再利用。削除/権限不足と通信失敗の断定は避ける。
- 確認案: fixtureで失敗→再試行成功、連打/離脱後の遅延結果で別写真を表示しない。

### SOLO-06 対象外になった Widget 写真のタップを無言で捨てる

- 確定: `MainTabView.swift:175–185` は除外済み/現在の対象外ならディープリンクを消して return。タブ移動や「開けない」表示は行わない。
- 影響: Widgetに残っていた写真をタップした際、アプリが開くだけで理由が分からない。該当する実機状態は未確認。
- 最小案: 既存の対象外拒否を保ち、「この写真は現在の表示対象外です」等の短い到達不能画面と写真一覧へ戻る操作を出す。別写真へ置き換えない。
- 確認案: 正常IDはその写真、除外/対象アルバム変更後は明示した空状態。許可範囲を広げず、別写真を表示しない。

## 採用された SOLO-01/02 の実装前受け入れ条件

1. 通常文字の操作欄は内容に必要な高さのみ。大文字では共通 PhotoDetailLayout の上限内で操作欄だけスクロールでき、写真領域/戻る/保存/送信が失われない。
2. PhotoKitからの要求は表示サイズに制限した画像のまま。既存1600pxの要求・近傍キャッシュ範囲を保ち、原本の無制限decodeを追加しない。
3. ピンチ/ダブルタップとVoiceOverの拡大操作を提供。等倍で横送り、拡大中は写真のpanのみ、等倍へ戻すと再び横送り。ページ変更時は拡大状態を引き継がない。
4. 表示中の写真IDを保存/配送に使い、既存の配送先凍結・失敗再試行・書き出しキャンセル/終了後削除に触れない。保存解除/候補除外の確認は残す。
5. 同日一覧を親に持つ写真から同じ日の一覧をpushしない。普通の写真/Widget/思い出入口からは同日一覧へ進める。戻る位置とページ順序を保つ。
6. ローカルではdiff/対象静的境界を確認する。iOSのビルド、gesture、最大文字/VoiceOverの実行確認は主担当の候補CIにまとめる。製品変更はLikedPhotosView/PhotoAssetImageViewに限定し、UIテストは主担当へ具体的ケースを渡す。
