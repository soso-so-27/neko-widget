# 共有終了後の通報を対応不要として完了する

共有写真が削除済み・期限終了でも、通報用コピーの保存期間中は確認結果を残せるようにする。写真の非表示・解除に必要な有効共有の条件と、通報の対応不要判断を分ける。

- `no_action` だけが `deleted/expired` と確定済み `closed_at` を認める。active space、同じ report/source、本人/session/counter/revision、未失効の閲覧受領証と新署名の条件は保持する。
- 非表示・解除は従来どおり有効な共有または有効な album copy が必要。完了処理は写真・delivery・TTLを復活させず、退役写真の変更通知も作らない。
- 返答は同じ report の reporter に固定する。通報コピーの失効や変更後は判断と返答を確定しない。
- 前進用 migration0038 が current challenge view と event apply trigger だけを更新する。既適用の0032は変更しない。owner policy・権限・鍵・runtime gateは追加しない。

関連9件のD1/実署名試験とmigration互換性はローカルで成功。原写真のdownload/ACK拒否、reporterだけの返答取得、既存有効album copyの操作、source失効時の原子的拒否を確認した。残る49件はこの局所実行では省略しており、成功とは数えない。

実ブラウザでは1px合成画像と合成認証を使い、共有終了の説明、非表示選択の無効化、対応不要の選択、確認チェック後の確定ボタンを観測した。これは本人の実認証や実通報への確定成功ではない。

候補の独立レビューは阻害事項なし。実環境へのmigration・候補反映、本人署名による確定とアプリでの実結果表示は未実施。CIは製品入力を固定し、native入力不変の専用制御を先に確認してから既存backendの必須検査を行う。
