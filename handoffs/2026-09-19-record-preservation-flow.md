## 確認できた接続差

- 個人メモには本文、書いた日、更新日、撮影日、明示した猫名、安定したメモIDがある。写真との対応は端末のPhotoKit IDで、写真がなくても本文は編集・削除できる。[PhotoMemoryNoteStore.swift](../NekoWidget/NekoWidget/Services/PhotoMemoryNoteStore.swift:3)
- 保管側には独立UUID、本文、保管日、撮影日、JPEGがある。書いた日・更新日・猫名はなく、現在の作成画面は撮影日もnilで渡す。写真と本文を別途選択・入力するため、普段のメモとつながっていない。[PersonalArchiveStore.swift](../NekoWidget/NekoWidget/Services/PersonalArchiveStore.swift:32)、[PersonalArchiveView.swift](../NekoWidget/NekoWidget/Views/PersonalArchiveView.swift:239)
- 保管側は追記のみ。同じUUID・同じ内容の再試行、アカウント別の待ち行列、写真の部分取得時に本文と健全なローカル画像を残す仕組みはある。既存メモへの復元書込み、保管の編集・削除はない。

## 推奨する体験

**既存メモ詳細 → 写真・言葉を引き継いだ確認 → 明示保管 → 元メモへ戻る → 空の端末でも同じ記録を読む。**

通常の「保存」は引き続きこのiPhoneへの保存だけにする。同じメモの詳細から「iCloudに保管」を開き、保存済み本文と現在の写真を引き継ぐ。写真の再選択・本文の再入力は求めない。本文を直す場合は元メモ編集へ戻し、第二の編集欄を作らない。

確認画面では「この写真のコピーと言葉を、自分のiCloudに保管します。相手には送られません」と説明し、一件の「保管」で確定する。写真の取得失敗時は黙って外さず、「言葉だけ保管」か再読込を選べるようにする。原本ではなく鑑賞用コピーであることも初回に伝える。

元の記録には「このiPhoneのみ／保管待ち／この内容は保管済み／保管後に変更あり」を表示する。新端末では既存の記録一覧から「iCloudから取り戻す」へ進み、写真権限・猫登録なしでも戻した写真と言葉を読む。設定は管理用に残し、新タブを増やさない。

## この一経路に必須のデータ契約

1. **文脈を保持する。** 保管本文に、書いた日（不明はnil）・本文更新日・撮影日・猫名の当時の控えを添える。保管日を記入日に代用せず、旧データの不明値を推測で補わない。
2. **対応は端末内に置く。** 独立した保管UUIDと、元メモID・変更番号・写真IDの対応をApple Accountごとに保持する。PhotoKit ID・個人メモID・猫プロフィールID・パスはクラウドへ送らない。
3. **対象を固定する。** 確認画面で本文・写真・元の変更番号・アカウントを固定し、保管直前に変化を再確認する。画像取得には現在の対象範囲・除外・Photos権限を使い、過去の写真IDだけで迂回しない。[現在の写真範囲](../NekoWidget/NekoWidget/Views/MainTabView.swift:1481)
4. **再試行で増やさない。** 送信前に操作IDと内容の対応を端末へ残し、終了・応答喪失後も同じIDと確定済み画像bytesを使う。既存のJPEG変換を再利用する。通常のメモ保存・閲覧・猫名変更で通信を始めない。

| 変化 | 保持するもの・初回の扱い |
|---|---|
| メモ編集 | 端末の本文だけ更新。保管済み内容を自動変更せず、変更ありと示す。同IDの別本文拒否を解除しない。 |
| メモ削除 | iPhone内削除と保管削除を分け、保管コピーが残ることを短く示す。保管先への対応を見失わせない。 |
| 写真消失・権限喪失 | 本文・日付・猫名・保管対応を残す。既に明示保管したコピーは原本とは独立して読める。新たな原本取得や除外解除には使わない。 |
| 復元 | 保管IDで重複を防ぐ。写真取得失敗でも本文を戻し、写真まで完了と表示しない。既存メモへ自動上書きしない。 |
| 復元後の編集 | 現メモstoreは写真ID必須。架空のPhotoKit IDを作らず、初回は保管記録として閲覧する。写真と独立した編集契約は未実装。 |
| アカウント変更 | 入力を残して送信停止。旧一覧・画像・送信待ちを新アカウントへ混ぜず、普段の端末内メモは消さない。 |
