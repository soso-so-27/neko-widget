## 1. まず決める一枚

### 目的

**猫の写真を楽しみ、メモを書き残す。その大切な記録を、新しいiPhoneでも読み返せる。**

「猫写真が画面に並ぶこと」「サービスに写真実体を残すこと」「原本を丸ごとbackupすること」は別。初版は2つ目までを成立させ、原本・全写真・永久保存は約束しない。

| 論点 | 進める方向／未確定の境界 |
|---|---|
| 料金 | 対象者7日間無料、その後月980円という既存案に一定の個人保管を含める。保管のためのiCloud追加契約は必須にしない。実販売条件はStoreKitと照合後 |
| 対象 | 本人が残すことを選んだ猫写真の閲覧用コピー＋個人メモ＋撮影日・記入日＋関連付けた猫のID/名前。猫登録・メモ入力を保管の必須条件にしない |
| 選び方 | 写真のみの明示選択・複数選択を用意。本人が同意した後だけ「以後メモを書いた写真」「以後お気に入りにした写真」を自動保管する候補 |
| 自動アルバム | 検出・分類・未選択の写真は端末内で扱う。表示された全写真を自動アップロードしない |
| 保管場所 | 本人専用のサービス側保管。共有のまどとは所有者・権限・保存期限を分離 |
| 課金終了 | 新規保管を停止しても、既存記録の閲覧・メモ編集・削除・書き出しを課金で塞がない。無料編集を新規の画像追加に流用させない |
| 容量 | 未決定。5/10/20GB等は比較入力にとどめる。画質・平均/P95容量・解約後在庫を確認するまで上限を購入画面に掲載しない |
| 初版対象外 | 全写真の原本、動画、Live Photosの動き、位置情報の自動転記、すべての設定の復元、完全自動双方向同期、公開窓拡張 |

「猫の一生を全部守る」ではなく、まず「ここに残した写真と記録を引き継ぐ」。選んでいない写真は含まれないことを、長文免責だけでなく状態表示で分かるようにする。

### 許可と普段の操作

1. 初回は私有保管がOFF。猫写真の閲覧やメモ作成は、保管への同意前でも既存の権利どおり使える。
2. 「この写真とメモを保管」から、保存先・コピーの画質・保管範囲・容量・解約後の扱いを一画面で案内する。受信者や家族へ公開される操作ではない。
3. 今後の自動対象は「メモを書いた写真」「お気に入りにした写真」を別々に選べる。過去分の一括投入は件数と対象を確認して別途実行。既存お気に入りを無断で全アップロードしない。
4. 有効な新規保管権がある間は、同意した操作に続けてバックグラウンドで保管。お気に入りを外す・メモを消す操作では、保管済み写真を連鎖削除しない。
5. 自動保管をOFFにすると、その同意に由来する未受付の新規アップロードを止める。保管済み記録の削除とは分け、受付済み操作の状態も説明する。
6. 課金終了後にお気に入りを追加しても端末の操作は成功するが、新規保管はしない。過去に保管した記録のメモ修正は従来の無料編集を維持する。再契約時も未保管分を無断一括投入しない。

初版の自動対象は本人の写真と個人メモ。受信写真・共同記録を無断で個人の長期保管へ複製しない。受信写真の明示保存後の保持権、相手の取り下げとの関係は共有契約の別判断とし、今回変更しない。

## 3. 再利用できるもの／別途必要なもの

- 既存のJPEG生成・メモ表現・保管状態・再試行の考え方は再利用候補。ただし現行20MiB上限は平均サイズではない。共有の暗号文上限約1MiBとも別であり、どちらを新契約へ流用するかは未決定。
- Workers/D1/private R2の運用経験、署名検証・nonce・本文hash、受付の冪等性は再利用候補。今回は既存実装を変更しない。
- **共有の送信期限を延ばして長期保管にしない。** 専用の保管領域・台帳・削除処理・権利を設ける。通常配送は未受領30日／受領後7日の削除がある。
- **購入の復元と、記録の本人アクセス復旧は別。** `billing-recovery.ts` は有効契約／請求猶予を要求するので、期限切れの記録閲覧へそのまま転用しない。安全条件を緩めて流用する方法も採らない。
- **署名鍵の再発行と写真の復号鍵の復元は別。** 現行共有のThisDeviceOnly鍵・相手経由の復旧は、ひとり利用で全端末を失った場合の解決にならない。

### 最初の技術判断：本人確認と鍵

保管領域の所有者は、特定のiPhone、まど、支払者、購入トランザクションから独立した安定IDにする。新端末で本人を確認でき、解約後も本人の保管領域へ到達できることを最初に試作する。

候補は、復旧可能な本人認証とサービス管理の暗号化鍵、または本人が復旧できるE2EE。前者は運営側で復号し得る範囲・アクセス制御・監査の説明が必要。後者は全端末紛失時の鍵復旧を証明できなければ採用しない。**現行の公開説明よりプライバシーを弱める変更や、新しいIDプロバイダーの導入は、方式・影響を示して決定してから接続する。独自暗号方式は作らない。**

## 4. 接続前に固める保存契約

将来の最小データ一式は、`archiveOwnerID`、端末内PhotoKit IDから独立した`recordID`、`revision`、写真objectのhash/bytes/format、個人メモ、撮影日と精度・時差の情報、記入日、任意の猫ID/名前、同意version、作成元、削除世代。値が不明な日付・猫名を捏造しない。

- 新規受付で本人・同意・有料権・予約容量を確認。保存対象は最初から本人の領域に固定し、送信先のまどIDで推測しない。
- 写真アップロードと台帳の確定を二段階に分ける。サイズとhash、写真実体、メモの版が揃うまで保管済みにしない。DBだけ成功／objectだけ成功を扱う。
- 同じ操作の再試行は二重課金・二重記録にしない。容量予約は並行端末間で競合させず、未完了objectと予約の片付けを設計する。
- 受付済みかつ有効な予約の完了は、途中の契約満了だけで失わせない。ただし取消・本人認証失効・削除世代更新を無視して完了させない。権利不明は未契約と区別する。
- 新端末は台帳をページ取得し、画像は必要に応じて取得する。全写真をメモリへ一括展開する方式は使わない。PhotoKit IDが変わっても保管記録単体を読めるようにする。
- 記録のメモ編集はrevision条件付き。古い端末の未送信データで新しいメモや削除を上書き・復活させない。既存記録のメモ修正と新規画像追加をAPIでも分離する。
- 写真アプリの原本削除、お気に入り解除、保管コピーの削除、まどの退出、契約終了は別操作。連鎖させない。
- primary保管成功と、運営の災害復旧用backup成功は別の内部指標。R2の冗長化だけで、誤削除・台帳破損から戻せるbackupが完成したとは扱わない。

## 5. 解約・容量・誤削除・運営終了

既存原則の「解約だけで記録を削除しない」「既存メモの編集と持ち出しは無料」を引き継ぐ。以下は販売契約の未決定事項で、値を仮置きしただけで自動削除を実装しない。

| 決めること | 推奨する検討条件／合格基準 |
|---|---|
| 保管上限 | 一般的な猫写真を確認して閲覧画質を決め、平均/P95 bytesで枚数の目安を出す。例示枚数と保証容量を混同しない。満杯では追加停止、既存を自動削除しない |
| 解約後の在庫 | サービス提供中の既存閲覧・編集・搬出を基本案とし、非課金で残る在庫を累積して採算評価。途中で削除期限を後出ししない。維持困難なら販売前に提供範囲を再設計 |
| 体験期間・不正利用 | 同じ保管品質・対象を試せるようにしつつ、受付の認証・容量予約・レート制限で大量投入を制御。実体験の制約は申込み前に表示し、隠れた低容量trialにしない |
| 誤削除 | ごみ箱／取消期間と、全端末からの削除反映を設計。期間・副コピーからの最終消去期限は未決定。古い端末・復元backupからの復活を防ぐ削除履歴を保持 |
| アカウント削除 | 契約解約とは別。本人確認、他データへの影響表示、主・副コピーと台帳の削除完了を追跡。公開ポリシーの期限と一致させる |
| 書き出し | 写真＋UTF-8メモ＋日付＋対応manifestをまとめて搬出できる候補。無料。欠けた写真を件数と理由で知らせ、完了を偽らない。元の非表示本文ZIP UIを勝手に復活させない |
| 運営終了 | 事前通知方法、搬出受付期間、アプリが動かなくても本人確認して取り出せる手段を決める。永続URLや永久無料運営を約束しない |

月980円から原価を直接引いて利益としない。Store手数料、税、問い合わせ・復旧、集客、非課金保管、画像以外の台帳・副コピーも別途必要。

### D1ローカル試作の追記（2026-09-22 01:31 JST）

利用者の「進めて」により、同じ専用ブランチで実行可能な[復元試作](../experiments/ManagedPreservation/README.md)を追加した。基点は引き続き `184b4cd`。並行Cの課金・共有ファイルや台帳は編集していない。

確認した流れは、合成本人ID → 明示同意・有効権のある新規保存 → 暗号化SQLiteを閉じる → 旧セッションを捨てる → 契約切れ・新セッション → 同じ写真バイト列/メモ/日付を読出し・搬出、である。サーバー鍵は試験用Mapから再注入しており、実Apple認証やKMS鍵復旧をしたという意味ではない。

- 本人確認は `jose 6.2.12` のRS256検証とローカルJWKS。合成issuer・合成RSA鍵だけを使用。新規依存は実験フォルダ内に閉じ、インストールスクリプトを無効化した。実行時に外部へ通信しない。
- 保管は標準JWEの `dir` / `A256GCM`。サービス管理鍵の候補でありE2EEではない。現行プライバシー説明を変更したり、この方式を本線へ採用したりしていない。
- 本人以外の読取/編集/削除を拒否。契約切れの既存記録の読取・メモ編集・削除・搬出は維持。鍵/DB欠落を空の復元成功にせず、失敗として返す。
- SQLiteの版管理とtombstoneで古い編集・再送による復活を防ぐ。同じ保存内容の成功再確認は契約切れでも可能で、後から直したメモを巻き戻さない。
