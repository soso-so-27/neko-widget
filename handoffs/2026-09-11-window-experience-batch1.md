# まどの体験整理：第1バッチ

ユーザーがUI/UX改善案を確認し「それですすめて」と指示。2026-09-11に着手。

## 作業範囲と受け入れ条件

- 最新`origin/main`は`68fd1f4`。それを包含し、検証済み・未配布の公式Widget直接表示を含む`0b103f0`から、別worktree `C:/dev/neko-window-experience-20260911` / `codex/window-experience-20260911`を作成した。旧研究worktreeと、前タスクの未コミット資料は編集しない。
- 利用中の非公開まどと受信中の公式まどを写真中心の一覧にまとめる。大きな文字では一列。未受信の公式まどは「探す」から開く。
- 非公開まどの作成・招待・機種変更は「身近な人とつなぐ」に残す。設定中1個・合計3個の既存条件は非公開だけに適用する。カタログを確認できないときの切替抑制を維持し、公開まどまで操作不可にしない。
- 受信開始の保存成功を詳細画面で伝え、任意のWidget設置案内・あとでを用意する。設置済みの人には表示元変更の手順を案内する。
- 写真詳細の拡大・移動は既存の`MomentZoomablePhoto`を再利用。最近の写真、提供元・撮影日・掲載日、Widget写真の直接表示・閉じる1回を維持する。読み込み中を失敗と表示しない。
- 非公開まどのハート・送信を維持。公開写真の反応送信基盤は未実装なので、ローカル表示だけで「ハートを送った」と装う操作は追加しない。

## 一覧の写真

非公開の表紙は、対象`localWindowID`の接続状態、そのまど用の安全確認済みWidget出力、現在の受信台帳を同じライフサイクルロック内で照合する。アクティブまどを切り替えて画像を取得しない。削除済み・写真がない・設定中・失敗・期限切れでは中立の表示にする。他の猫や別まどの写真で埋めない。表示期限の時刻にも再描画する。

既存の公式ストアは受信開始前の写真取得に対応していない。今回、未受信の「探す」には実在する公式まどの説明を表示し、勝手な購読や作例の配信写真への見せかけは行わない。受信前の実写真プレビューは、公開まど共通化時に読み取り専用の取得経路として扱う。

## 続くバッチ

公開まどごとの取得・購読・画像・最近の掲載写真・Widget表示元を共通化してから、お題窓、猫のまどを追加する。未対応の窓をこのバッチで選択可能にしない。公開反応や投稿受付も表示と送信基盤を一緒に扱う。外部公開、課金、審査提出は行わない。TestFlightは関連修正をまとめて扱う。

第2バッチの着手順を読み取りで整理した。以下は未実装。

1. `OfficialWindowCatalog.swift`：公開まどのID・表示名・運営元・取得URLを定義し、応答のまどIDを検証する。まず運営定義の一覧を使い、探索APIを先行して増やさない。
2. `OfficialWindowStore.swift`のStore/Client：購読・取得中処理・画像を対象まどごとに分離する。既存の`official-cats`は保存先と購読を維持し、新まどだけ個別保存先にする。Aの停止・遅延応答がBに影響しないことを確認する。受信前プレビューは購読とは独立した読み取り経路として扱う。
3. `MainTabView.swift` / `OfficialWindowView.swift` / `AppRootView.swift`：まどIDと写真IDを一覧・詳細・リンクに通す。旧`nekowidget://official-window?photo=…`は旧公式だけを指す。
4. `NekoWidgetConfigurationIntent.swift` / TimelineProvider / ManifestReader / Entry / View：既存Widget表示元のIDを保持して公開まどを追加する。停止・削除済みIDも空状態として解決し、個人写真や別まどへ切り替えない。アプリで開く対象とWidgetの選択を独立させる。
5. `OfficialWindowService`とcatalog生成ツール：旧`/catalog.json`を維持してまどごとの配信に対応する。まず2まどのローカルfixtureで共通化を確認し、実際のお題配信は第3バッチへ。既存のHTTPS・redirect拒否・容量/hash・期限・App/Widget設定一致の検証を残す。

完了条件は、旧保存データ・旧Widget・旧リンクの互換、2まどの画像隔離、片方の停止と遅延応答、期限終了。新たな会員制度・投稿受付・公開反応を共通化の前提にしない。
