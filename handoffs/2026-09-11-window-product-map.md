## 整理する問題

これまで「公式（誰が運営するか）」「公開（誰が受け取れるか）」「猫・お題（何が届くか）」「Widget（どこに表示するか）」を同じ階層で並べた。また、公式まどに好みを混ぜる案と、猫のまどを別に追加する案を続けて提案し、家族との既存まどと自分の写真の位置づけが抜けていた。

## 一つの定義

**まどは、写真を届けたり受け取ったりする場所。Widgetは、選んだ写真をホーム画面へ映すもの。**

まどの大分類は二つに揃える。

| 分類 | 利用者がすること | 例 |
| --- | --- | --- |
| 非公開まど | 招待した相手と写真をやり取りする | マイファミリー、実家とのまど |
| 公開まど | 見つけたまどを追加して写真を受け取る | どこかの猫、むぎの窓、今週のお題 |

公開まどという分類は、任意の利用者が無審査で公開できる機能を採用したという意味ではない。初期の作成者・写真提供者・掲載確認は運営が管理する案。見る人の受信参加と、写真を提供できる人・経路は別に扱う。

## 公開まどの中にあるもの

| まどの例 | 内容 | 更新の意味 |
| --- | --- | --- |
| どこかの猫 | 運営が選ぶ、いろいろな猫。最初の出会いに使う | 次の紹介写真へ替わる |
| むぎの窓 | むぎ一匹の掲載写真 | その猫の新しい掲載写真が出たら替わる |
| 今週のお題 | 今のお題に合う、いろいろな猫の写真 | 開催中のお題に合う写真が紹介される。お題を週替わりにするのは開始案 |

この三つを別々のアプリ機能やトップタブへ増やさない。公開まどとして同じ基本の表示・追加・受信停止の操作を使い、写真の集め方と対象が異なる。全種類を追加する必要はない。

「公式」は窓の種類ではなく運営元の表示。アプリ運営が編集する窓に公式と表示する。運営が確認しただけの投稿者を公式の運営者として扱わず、猫の飼い主・写真提供者と編集する運営を区別する。

例：

- 「どこかの猫」— 公式の編集。
- 「今週のお題」— 公式の企画。写真は希望する提供者から集められる。
- 「むぎの窓」— むぎの飼い主による写真。運営が配信を代行する場合も、その関係を明示する。

## アプリ全体の役割

現行の写真・思い出・まどの三つを軸にする。

| 場所 | 役割 |
| --- | --- |
| 写真 | このiPhoneの猫写真・アルバムを楽しむ |
| 思い出 | 時間をさかのぼり、月や季節の振り返りを楽しむ |
| まど | 自分が追加したまどを開く。相手へ届ける、公開まどから受け取る |

「自分の猫写真」を新たな公開まどへ変換する必要はない。猫をアプリ内で登録すること、写真を持っていること、猫の公開まどを持つことはそれぞれ別。登録からの自動公開は行わない。

まど画面の初期案は、利用中のまどを中心に並べ、追加の入口を二つにする。

- **まどを探す**：公開まどから追加する。どこかの猫・猫の窓・お題窓はここで見つかる。
- **身近な人とつなぐ**：既存の非公開まどを作成・招待・参加する。

大分類は整理のための軸で、利用者に毎回「非公開／公開」を判定させる操作にはしない。利用中のまどは、写真と名前を主に見せる。猫・お題・会員などを独立したトップタブとして増やさない。

## Widgetとの関係

Widgetには次のどちらかの表示元を指定する。

1. このiPhoneの猫写真。
2. 自分が追加したまどの一つ。

アプリでまどを追加する操作と、ホーム画面でWidgetを追加する操作は別。例えばアプリで五つのまどを受け取っていても、Widgetは一つだけでよい。二つ置いて実家とむぎを表示することもできる設計にする。

アプリ内で別のまどを開いても、既に置いているWidgetの表示先を変えない。利用できなくなった表示元を、別のまどへ勝手に差し替えない。

## 操作の意味

| 操作 | 対象・意味 |
| --- | --- |
| ハート | この写真が好き。猫の継続受信や自動公開の許可ではない |
| このまどを受け取る | 利用中のまどへ追加し、この場所から写真を受け取る。ホーム画面への配置は別 |
| Widgetに表示 | 置いたWidgetの表示元に、そのまどを指定する |
| お題へ写真を提供 | 公開企画への任意の参加。非公開まどへの送信とは分け、提供先・範囲を確認する |

猫を継続して受け取る操作は「むぎの窓を追加」と表現できるので、別の「また見たい」管理機能は必須ではなくなる。単一のおまかせ窓へ全員の好みを混ぜる選定も、本構成の初期条件にしない。

お題窓は見るだけでもよく、写真の提供・撮り下ろし・投票・返信を受信条件にしない。まず一つの週替わりのお題を提案しているが、週替わりか常設テーマかは別の運用判断。

## 実装状態との対応

- **既存の土台**：このiPhoneの猫写真、複数の非公開まど、どこかの猫という固定の公式まど、Widgetごとの表示元選択。
- **追加案**：複数の公開まどを探して追加する一覧、猫の公開まど、お題窓、公開写真の提供受付・反応返却。
- **今回行ったこと**：資料上の分類と役割の統一。アプリのラベル、公開権限、保存先、配信、Widget設定は変更していない。

コード上の根拠：`NekoWidget/NekoWidget/Views/MainTabView.swift` は写真・思い出・まどを構成し、まど一覧に非公開まどと公式まど入口を表示する。`NekoWidget/NekoWidgetWidget/NekoWidgetConfigurationIntent.swift` の `WidgetPhotoSource` は個人写真・公式・非公開まどごとの表示元を持つ。現在、任意の公開まどを選ぶ汎用カタログが完成しているという意味ではない。

## 今後の資料の扱い

分類・操作・画面の役割は本書を優先する。[運用案の比較](2026-09-11-official-window-recommendation-summary.md)は、写真提供の動機・供給・費用の候補として参照する。以前の「公式・猫・お題を三種類として並べる」「一つの窓でまた見たい猫を優先する」は比較した旧案として扱い、現在の分類と混ぜない。

次に設計を進める対象は「まど一覧 → 公開まどを探す → 追加 → 写真を開く → Widgetの表示元に選ぶ」の一周。新しい種類や会員制度を足す前に、この構造で必要な既存操作と新しいお題窓を扱えることを確認する。
