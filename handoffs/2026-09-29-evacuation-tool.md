# 避難に備える：初版候補

## 目的と範囲

利用者が設計案を承認し、実装継続を依頼。最新 `origin/main af7ec68` から独立worktree/branchで作業。
目的は「持ち物の置き場所が分かり、猫の写真と必要な記録を家族や避難先へ渡せる」。
長い必須フォーム、猫登録、会員・保管サービス接続を前提にしない。

現在は候補実装。ネイティブ検証・本線採用・TestFlightはまだ完了していない。
進行中の迷子PR #87には混ぜず、CatPreparednessView/StoreとLostCatDraftは無変更。

## 変更した動作

- ツールの避難タイルから、持ち物／猫の情報／行き先へ進む。
- 持ち物の量・置き場所・猫別/共通・対象外を編集。今回のチェックを独立保存し、再起動後に再開。
- 猫未登録でも避難用記録を作れる。既存プロフィールは本人が名前を選んだ場合だけ利用。
- 写真候補はこの子の写真、その他の猫写真、システムの写真選択。元ライブラリや猫の所属は変更しない。
- 顔・全身・飼い主との写真を選択して端末にコピー。写真を新規ラスタライズしてメタデータを引き継がない。
- ごはん・接し方・病歴/薬・家庭の連絡先を任意記入。病歴/薬は未確認となしを区別。
- 病歴/薬・連絡先・飼い主との写真は初期OFF。選択後のスナップショットだけを画面と書出しへ渡す。
- 大きく表示、家族向け画像、A4 PDF。長文はページ分割し、固定枠へ縮小/黙って切捨てしない。
- 候補施設・条件・情報源・確認日・家族の集合メモ。受入状況や避難の要否は判定しない。
- 基礎情報の編集日と、本人が確認した日を分離。送った控えは自動更新しない。

## データ保全

専用 `Application Support/EvacuationPreparation` のみを所有。既存サービスの移行や写真削除なし。
manifestが不明・破損・将来versionなら新しい空データで上書きしない。
manifest不在でも専用ディレクトリが空でなければ、残存写真を消さず読み込みを止める。
写真の新規保存→manifestの原子的書込み→参照が外れた写真の清掃の順序。
正常なmanifestがある場合のみ、専用ディレクトリ直下のUUID.jpg通常ファイルを再照合する。
symlink・別名ファイルは対象外。削除失敗は表示し、次回保存/起動で再検出する。
データ・写真・一時書出しはiOS complete file protection。削除は避難用コピーだけ。

独立レビューで「削除失敗後の孤立写真」と「manifest不在時の清掃」のP2を指摘され修正。
独立レビュアーの再確認でも両指摘の解消を確認。iOSコンパイル・出力描画はレビューの成功に含めない。

## 初版として残る確認

診断1回目 `36446843415` / `f5050b4` はビルド失敗（実行248秒、runner 3.55分）。
`EvacuationPreparationView.swift` の「必要なことだけ」で、見出し文字列付きSectionにfooterを併用した
初期化呼び出しの誤り。headerクロージャへ修正。テスト本体は未実行であり失敗を成功扱いしない。
開発フロー12検証（96.4秒）は対象入力に変更がないため維持し、同じ3操作の診断で型・描画を確認する。

コード上では既存のオンボーディングに写真アクセスをスキップする経路があり、
権限なしでもMainTabViewへ進む。ただし通常起動の実画面での到達は未確認。

- 端末の実写真をPhotoKit/PhotosPickerで読み込み、顔・柄・縦横写真の判読性を見る。合成fixtureだけでは成功としない。
- 画像とPDFの受信側の表示、A4の印刷結果、VoiceOver、オフライン起動・写真権限取り消し後の読み戻し。
- 通常起動のオンボーディング/権限拒否下でツールが塞がれないこと。専用fixtureから直接開く証拠とは区別。
- 初版は1匹単位の表示/書出し。複数猫の一括PDF＋家庭共通ページは未実装。
- 単独1匹でも猫一覧を1回通る。直接開きつつ対象を変えられる最終導線は実画面で判断する。
- 保存画面/共有画面は追加済みだが、実測前に「迷わない」「何秒で作れる」と主張しない。
