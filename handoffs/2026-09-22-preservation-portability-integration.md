## 記録項目の契約

基準は `PersonalArchiveContext` と `PhotoMemoryNoteExporter.createArchive`。端末メモ一括の `memories.json`（records/cats/exportID）とは別形式。

| 項目 | こちらの接続用試作 |
|---|---|
| 単件の公開JSON | `formatVersion: 1, text, capturedAt, writtenAt, updatedAt, catNames, photoFile` |
| 日付 | 撮影・記入・更新を別々に保持。未知は明示的null。UTC小数秒ISO 8601へ正規化。保管した日から記入日を推定しない |
| 猫名 | 最大100件の配列。重複・順序を維持。各名非空、200文字かつUTF-8 800bytes以下。個体IDだとは扱わない |
| メモ | 保存・編集時に前後空白を除去、500書記素かつUTF-8 65,536bytes以下。JSの文字列lengthで絵文字を分断しない |
| 写真 | コピーの上限を本線の20MiBに合わせる。写真なしはnull。本文も写真もない記録は拒否 |
| 写真なしの持ち出し | `photoFile: null`。空のJPEGを作らない |
| 公開JSONに含めないもの | 保管owner、Apple識別子、CloudKit資格、PhotoKit ID、位置情報、鍵、内部revision |

`exportRecords()` の内部manifestは従来どおり版やhashを持つ。新しい `document` が本線の単件 `memory.json` と同じ項目構成。内部manifestを利用者向けJSONとして流用しない。

本バッチはJSONの形と保存往復を確認しただけ。ZIP生成は本線の実装を再利用する方針で、別ZIP実装を作らない。ImageIO相当のJPEG完全デコードをNode試作には足していない。合成バイトが通るため、実JPEGとの互換性・画質の証拠にはならない。20MiBは1枚の入力上限であり、販売する総容量ではない。空白除去は明示的なUnicode White_Space、文字数はIntl.Segmenterを使用する。結合絵文字・NEL・改行区切りを含む代表例は確認するが、FoundationとNode/ICUの全Unicode版の一致は実証していない。

## 会員権との境界

今回、無料範囲を狭める新しい制限を試作だけに追加しない。本線の `PhotoMemoryNoteEditor.createsNewMemo` は、既存保管記録があれば新規メモの有料判定をしない。

- **すでに保管した自分の記録**：契約終了・権利確認不能でも本人確認できれば閲覧・編集・削除・持ち出しを維持。写真だけで保管した記録への初回追記も含む。これは現行nativeとの整合であり、無料ユーザーが未保管写真を無制限に新規保管できるという意味ではない。
- **新しい保管記録**：信頼したサーバー側の有効契約、または確認済みの請求猶予と、保存同意が必要。契約切れと確認不能を別エラーにする。trialはApple／本線が確認した有効権に対応させ、クライアント申告で通さない。
- **未保管の新しい写真への個人メモ作成**：本線の会員判定を使用。この試作の既存記録編集APIで代替しない。
- メモ更新時は信頼した処理時刻でupdatedAtを更新し、撮影日・元の記入日は変更しない。元の記入日が不明なら、初回追記を含め不明のままとする。記入日取得のnative接続は別途契約を合わせる。

販売前には会員仕様・LPの「既存メモの修正」を、上の**保管済み記録への追記も含む**説明と揃える必要がある。今回その公開文言や本線の判定は変更していない。
