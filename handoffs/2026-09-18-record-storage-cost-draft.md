## 既存構成と価格

SharingServiceはCloudflare Workers＋D1＋private R2の構成。[env.ts](../NekoWidget/SharingService/src/env.ts) 2–4行に`MEDIA`/`MODERATION_MEDIA: R2Bucket`、[wrangler.jsonc](../NekoWidget/SharingService/wrangler.jsonc) 46–54行にbucket bindingがある。実際の画像処理は[moments.ts](../NekoWidget/SharingService/src/moments.ts) 687行でPUT、1252行でcommit時HEAD、1571行でGET。これはコードと設定の確認であり、本番の利用量・請求額・配備状態を確認したものではない。

[Cloudflare公式 R2 pricing](https://developers.cloudflare.com/r2/pricing/)（ページ更新日2026-08-07）を参照。繰り返し閲覧する鑑賞用写真として**Standard**を仮定する。

| 項目 | USDの公表単価 |
|---|---:|
| 保存 | $0.015 / GB-month |
| Class A：PUT・LIST等 | $4.50 / 100万回 |
| Class B：GET・HEAD等 | $0.36 / 100万回 |
| Standardの取り出し／R2からの通信量 | 追加料金なし（接続先の別サービス料金は除く） |

無料枠は一切差し引かない。公式の請求単位切り上げ（保存は1 GB-month、操作はClassごと100万回）も適用する。R2の月額は日ごとのピーク保存量を30日で平均して算出するため、下表は同じ在庫量を30日保持した比較。実請求はアカウント全体の利用・無料枠で変わり、下表を世帯ごとに切り上げて課金する意味ではない。価格改定・税・為替は未反映、円換算なし。

## 仮定と式

- `S`＝1画像当たり0.5 / 1 / 2 MB、`N`＝一世帯1,000 / 10,000枚、`H`＝100 / 1,000世帯。1 MB＝1,000,000 bytes、1 GB＝1,000 MB。
- **JPEG平均サイズは未実測。** 1画像1object・一組だけ保存する容量モデルで、暗号化manifest、派生サムネイル、追加コピー分は上乗せ前。現行は暗号文object最大1 MiBでJPEG用予算はさらに小さいため、特に1 / 2 MBは将来の容量比較用であり、現行送信可能サイズや実測分布を表さない。[MomentSharingCore.swift](../NekoWidget/Shared/Sharing/MomentSharingCore.swift) 7–10行。
- 月の代表操作：一世帯で新規30枚（1 PUT＋1 HEAD/枚）、画像取得30 GET/日×30日＝900 GET。家族全員・全端末を合わせた仮定。画面閲覧回数とは同一視せず、端末cacheの効果も仮置きしない。リトライ・LISTは未計上。
- `G = S × N × H ÷ 1000` GB-month、`A = 30H`、`B = (900 + 30)H`。
- 無料枠控除前の月額目安：`0.015 × ceil(G) + 4.50 × ceil(A / 1,000,000) + 0.36 × ceil(B / 1,000,000)`。操作を増やす場合は合計回数に対して一度だけ切り上げる。在庫Nは当月の平均相当値とし、継続追加分は翌月以降のNへ積み上がる。

## 最初の一括投入は別に計上

初回に全在庫を取り込む場合は`N×H PUT`＋`N×H HEAD`を仮定。画像サイズで操作回数は変わらない。下表はその処理だけを一月に行った場合の無料枠控除前・切り上げ後の操作費で、継続月額にそのまま足さず、同月分の回数を合算して再計算する。保存量も実際の投入日から日次ピークで計算する。

| 一世帯の枚数 | 世帯数 | 初回PUT／HEAD | 初回操作費A＋B |
|---:|---:|---:|---:|
| 1,000 | 100 | 各100,000 | $4.86 |
| 1,000 | 1,000 | 各1,000,000 | $4.86 |
| 10,000 | 100 | 各1,000,000 | $4.86 |
| 10,000 | 1,000 | 各10,000,000 | $48.60 |

新端末が全在庫を復元する際はさらに`N GET/端末`が必要。複数端末、追加のHEAD、再試行、写真一覧のLIST、サムネイルobjectを加えると回数が増える。既存の一枚配送の受信・送信期限を延ばせばこの保管契約が実現する、という試算ではない。

## この表に含まない費用と、決定前の測定3項目

**含まない：原本・Live Photo・動画、独立した冗長backup／別リージョン・世代保持、Worker、D1 catalog／削除履歴、認証／鍵復旧、通知・ログ／監視、支払手数料、集客、サポート、税。** R2自身の冗長化を、誤削除や鍵紛失から復元できる独立backupの完成と扱わない。ここから会員料金・利益率・無期限／無制限保存を導けない。

1. **画像単位の実容量**：同意した検証用写真でJPEG・暗号文・manifest・派生サムネイルのbytesとobject数を計測し、平均とP95を出す。内容・個人写真を調査用に収集しない。
2. **世帯単位の30日利用**：追加枚数、端末数、R2に到達したGET／HEAD／LIST／再試行を集計。新端末で10,000枚を復元する際の回数・転送量・所要時間も別測定する。
3. **復元可能な一式の倍率**：必要な原本範囲、独立backupと履歴の世代数を決めた検証構成で、live保存量に対する総保管bytesの倍率と削除反映を測る。費用と復旧の実証後に容量・保持／終了条件を決める。

判断材料としては、1 MB×10,000枚×1,000世帯の鑑賞用コピーが保存費$150/月になる規模感を得られた。最大の未確定要素は「そのJPEG以外に何を、何組、どれだけ復元可能に保管するか」である。
