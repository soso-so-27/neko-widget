# 課金と商品化の導線

作成：2026-09-03
状態：UXと実装境界を採用。20枚の端末内試作と無課金の購入希望UIまで実装。販売、App Store商品、Web決済、実注文は未実装

関連：[ADR-024](ADR-024-無料体験とPlusと物販.md)、[ADR-025](ADR-025-StoreKitと課金IDの境界.md)、[情報設計](情報設計.md)、[製品構造](製品構造.md)、[物販実現性・競合運営調査](物販実現性・競合運営調査.md)

## 0. 現在地

- アプリの `かたちにする` は、選んだ写真の一時PDF共有に加え、20枚ちょうどで端末内の本イメージを確認できる。どちらも商品注文ではない。
- Webの販売前試作はサンプル写真だけで動き、4,980円の価格受容性を確認する。希望はブラウザ内だけへ保存し、請求、個人情報収集、写真保存、通知、アプリとの受け渡しを行わない。
- 現在のWeb projectには注文用D1／R2がなく、Stripe Checkout／Webhookも接続されていない。
- PlusはStoreKit client、課金ID、Server entitlement、まどsponsorshipの無効状態foundationまであり、商品ID、販売UI、通常画面、実課金環境には接続していない。
- したがって、現行TestFlightには検証価格と未決済の購入希望だけを明示し、実注文・決済・住所入力を追加してはいけない。

## 1. 利用者へ見せる構造

ねこのまどには、購入理由が異なる二つの有料体験だけを置く。

| 体験 | 利用者が買うもの | 支払い | 購入場所 |
|---|---|---|---|
| **ねこのまど Plus** | 整理しなくても、ねこの時間が毎月まとまり、過去の作品も育つ継続体験 | 月額¥980／年額¥9,800 | アプリ内のStoreKit |
| **本・プリント** | 選んだ思い出を手元へ残す、または誰かへ贈る物理商品 | 商品ごとの都度購入 | 注文用WebのApple Pay／カード |

Plusはクラウド容量、写真画質、受信、通知、ハート、安全機能の解除として売らない。本・プリントはPlus特典やデジタル機能として売らない。両者を同じカート、同じ「購入を復元」、同じ契約状態へ混ぜない。

無料利用者も本・プリントを通常価格で注文できる。Plus割引、会員限定商品、ポイントは初期版へ追加しない。

## 2. 一つの言葉を一つの結果に固定する

| 表示する言葉 | 結果 |
|---|---|
| **思い出に残す** | このiPhoneにある写真へ端末内の印を付ける |
| **取り込んで残す** | まどから届いた写真を写真アプリへコピーし、通常の思い出へ入れる |
| **PDFで残す** | 選んだ写真を端末内でPDFにして共有シートを開く |
| **本のイメージを見る** | 選んだ20枚を端末内の正方形プレビューで確認する。注文や送信はしない |
| **本にする** | 注文用コピーを作り、Webのプレビューへ進む |
| **Plusを始める** | StoreKitで継続課金を開始する |
| **購入を復元** | App StoreのPlus購入権だけを確認する |
| **つくったもの** | 注文済み商品など、アプリ内に再訪可能な記録が実在する結果を見る。一時PDF共有は含めない |

現在の「かたちにする」は、写真選択後に「本のイメージを見る」と「PDFとして共有」を結果別に表示する。製造経路の確定後にだけ「本のイメージを見る」を「本にする」へ進める。「かたちにする」は説明上の総称に留め、結果が分からない最終操作名には使わない。

## 3. 画面構造

下部タブは増やさない。

```text
写真      見つける・見る・思い出に残す
思い出    残した写真と自動のまとめを見返し、持ち出す
まど      一枚を届ける・受け取る・ハートを返す
```

### 思い出

上部の `ふりかえり｜選んだ一枚` は維持する。

- **ふりかえり**：最新の便り・映画、過去のふりかえりを表示する。Plus対象の結果は、その結果を開こうとした時だけ案内する。
- **選んだ一枚**：利用者が思い出に選んだ写真を表示する。右上は抽象的な「かたちにする」ではなく「選ぶ」とし、選択後に `PDFで残す` と `本にする` を並べる。
- **つくったもの**：商品を注文した利用者にだけ、まとめ上部の小さな行として表示する。将来、再訪可能なデジタル作品を保存する場合は同じ場所へ加える。一時PDFを共有しただけでは表示せず、未作成時も表示しない。

20枚を自動選定できる場合は、まとめに販売カードを常設せず、写真一覧の入口付近へ `本にできる20枚がそろいました` という控えめな提案を一件だけ出す。閉じた提案は同じ選定内容のまま再表示しない。

### 設定

- 未加入：`ねこのまど Plus` の概要と料金をいつでも確認できる
- 加入中：`Plus利用中`、次回更新の案内、`サブスクリプションを管理`
- 確認不能：既存データを隠さず、`購入状況を確認できません` と再確認操作
- 共通：`購入を復元` はPlus欄の中に置き、写真やまどが復元されるようには書かない

設定は状態確認の場所であり、主な販売場所にはしない。

## 4. Plusの導線

Plusは起動直後や共有操作を遮って売らない。次の有料価値を利用者自身が求めた時だけ案内する。

```text
2匹目のプロフィールを追加する
2つ目の自分のまどを作る
過去の月の便りを開く
月・一年の映画を作る
1080p／素材編集を使う
検証済みの引き継ぎを設定する
        ↓
個人化したPlus説明
        ↓
年額¥9,800（推奨）／月額¥980
        ↓
StoreKit購入
        ↓
Apple署名とServer権利確認
        ↓
求めていた画面へ戻り、その場で続ける
```

購入画面で見せる価値は三つまでにする。

1. 毎月・一年のまとめが育つ
2. 複数のねこ・まどへ広げられる
3. 過去のまとめと編集結果を引き継げる範囲が増える

年額を主ボタン、月額を副選択にする。価格、更新期間、自動更新、解約方法、利用規約、プライバシー、購入復元を同じ画面から確認できるようにする。未実装の価値は表示しない。

招待された相手は、そのまどの参加・受信・ハート・通知に課金を求められない。Plus購入者が支援するまどでは、相手へ購入者の課金ID、価格、取引状態を見せない。

## 5. 本・プリントの導線

最初は小型の猫フォトブック一商品のみを実注文対象にする。管理上の仮称は `ねこの小さな本`、利用者には `しずくの20枚` のように猫名で個人化して見せる。自分用を既定とし、贈り先がいる人だけ `贈る` を選べるようにする。

```text
思い出 ＞ 選んだ一枚 ＞ 選ぶ
        ↓
本にする
        ↓
アプリ：20枚、順番、画質、表紙を確認
        ↓
注文専用コピーを作ることへ同意
        ↓
商品Server：一回限りの交換tokenを発行
        ↓
Web：tokenをHttpOnly sessionへ一度だけ交換し、24時間は再開可能
        ↓
全ページのプレビュー
        ↓
自分へ／贈る、部数、価格、発送目安を確認
        ↓
配送先・メール・Apple Pay／カード
        ↓
最終確認画面
        ↓
決済Webhookで一度だけ注文確定
        ↓
運営が入稿PDFを目視確認し、印刷会社へ手動発注
        ↓
印刷中／発送済みをアプリとメールで確認
```

初期商品仮説は15cm角、24ページ、思い出20枚とし、別の表紙画像が必要かは製造先の入稿規格で確定する。旧案の送料込み試験価格¥3,480は、一般小売価格で製造すると粗利が残らないため正式価格にはしない。送料込み¥4,980は価格受容性を調べる比較仮説とする。製造・梱包・個別直送の着地原価¥2,000〜2,200以下は一次選別の必要条件であり、税、運営工数、返金、chargeback、固定費を含む販売可能性の十分条件ではない。薄いソフトカバーでこの価格を付けず、厚手マットの合紙・レイフラットまたは小型ハードカバーを優先して試作する。詳細は[物販実現性・競合運営調査](物販実現性・競合運営調査.md)を正本とする。二冊目、カード、カレンダー、製造API連携は、最初の有償注文と再購入意向を確認してから追加する。

### AppとWebの役割

| App | Web |
|---|---|
| 端末内の写真候補を見つける | 注文用コピーだけを受け取る |
| 20枚を選ぶ・順番を整える | 大きなプレビューで全ページを確認する |
| 低解像度、縦横比、顔や耳の裁断候補を警告する | 自分用／贈り物、部数、価格、発送目安を確定する |
| 注文専用コピー作成へ明示同意する | 配送先と決済を安全に扱う |
| Webを開き、注文状態へ戻れる鍵を保管する | 法定表示、返品・再印刷条件、注文完了を表示する |
| 注文後の状態を「つくったもの」で表示する | 決済Webhookから注文を一度だけ確定する |

アプリに住所フォームやカード入力を複製しない。Webに写真ライブラリ全体への権限を渡さない。

## 6. 状態と失敗時の扱い

### Plus

```text
非加入 → 購入中 → 保留／有効
有効 → 自動更新OFF（期限までは有効）
有効 → 請求猶予 → 有効／失効
有効 → 返金・取消 → 失効
任意状態 → 確認不能
```

- 保留中に二重購入させない。
- 確認不能を非加入へ潰さない。
- 失効しても写真、まど、思い出、作品を削除しない。
- 新規の有料操作だけを止め、既存成果物は閲覧できるようにする。

### 物販

```text
端末内下書き → Web確認中 → 支払待ち → 支払済み → 入稿確認 → 入稿済み → 印刷中 → 発送済み → 到着
      ↘ 期限切れ    ↘ 決済失敗      ↘ 発注前取消／要修正／住所訂正／製造先拒否
                                                ↘ 配送紛失／返送／再印刷／返金／chargeback
```

- ブラウザを閉じても24時間は同じ下書きへ戻れる。
- 決済完了画面への遷移だけを注文確定の根拠にせず、署名済みWebhookを正本にする。
- 同じ決済通知が複数回来ても発注を一度だけ作る。
- 低画質、欠け、重複、決済失敗、住所不備をそれぞれ別状態にする。
- 運営の入稿確認前なら、写真差し替えまたは返金判断をできるようにする。
- 紛失、返送、製造先拒否、再印刷、返金、chargebackを通常状態へ押し込まず、理由と解決を監査記録へ残す。

## 7. データ境界

```text
写真ライブラリ／思い出      App内・端末内
まど、暗号鍵、まどで届ける画像  共有サービス
Plusの購入権                StoreKit＋課金サービス
注文用コピー、注文状態      商品サービス
カード情報、決済状態        決済事業者
配送先                      商品サービス＋必要な配送先
```

商品サービスへ送るのは、SKU、選んだ注文用コピー、ページ順、明示したcrop、画質判定、同意version、注文連絡先、配送先だけとする。まどID・まど名、招待コード、共有鍵、ハート履歴、写真ライブラリID、元ファイル名、位置情報は送らない。

Appが受け取るWeb用tokenは推測不能・一回限りとし、Webが最初に使用した時にSecure／HttpOnly／SameSite sessionへ交換する。sessionは操作に応じてrotationし、最終操作から24時間で失効する。Appが後から注文状態を確認するtokenは別にする。

購入済み画像と入稿PDFは、追跡上の到着から30日後、追跡できない場合は発送から45日後に削除し、バックアップ消去にさらに最大30日を許容する。不良申告、再印刷、返金、chargebackが未解決の間は削除を保留し、解決後に削除予定日を確定する。注文番号、商品、金額、税、配送・返金履歴、削除証跡は会計・問い合わせに必要な期間だけ別に保持する。カード番号は商品サービスで保持しない。

共有サービス、課金サービス、商品サービスはAPI、データベース、画像保管、秘密情報を分離する。

### 商品サービスの最小構成

| 構成 | 役割 |
|---|---|
| `POST /v1/order-sessions` | AppからSKU、枚数、同意versionを受け、24時間の下書きを一度だけ作る |
| `PUT /v1/order-sessions/{id}/assets/{slot}` | 決められた枚数・形式・容量の注文用JPEGだけを受ける |
| `POST /v1/order-sessions/{id}/finalize` | 全slot、画質、順番を確認し、一回だけsessionへ交換できるWeb用tokenを発行する |
| `POST /v1/checkout-sessions` | Server側のSKUと価格からStripe Checkoutを作る。ブラウザの金額を信用しない |
| `POST /v1/stripe-webhook` | Stripe署名を検証し、同じ決済を一度だけ注文へ確定する |
| `GET /v1/orders/{id}` | Appが自分の注文状態だけを確認する |
| 非公開の運営画面 | 入稿確認、要修正、印刷中、発送、再印刷を更新する |

Web URLへ載せるtokenと、Appが後から状態を確認するtokenを分け、Serverにはhashだけを保存する。公開Webから注文IDを順番に探索できないようにする。未決済の画像アップロードは、1端末の同時下書き数、枚数、総容量、画像形式、24時間失効で制限する。運営画面は一般ログインと共用せず、管理者だけのアクセス境界へ置く。

商品用D1には注文状態と監査event、R2には注文用JPEGと入稿PDFを置く。Stripeの価格ID、secret、Webhook secret、管理者資格情報をブラウザやAppへ配布しない。ログへ写真、配送先、メール、token、決済payloadを出さない。

## 8. 販売ページと法定表示

Webで実販売を始める前に、少なくとも次を同じ注文導線から到達可能にする。

- 販売価格と送料を含む総額
- 支払時期と方法
- 発送予定
- 受注生産品のキャンセル・返品条件
- 不良、破損、誤配送時の再印刷・返金条件
- 販売者名、住所、電話番号、責任者
- プライバシーと注文画像の削除時期
- 問い合わせ窓口

最終確認画面には、商品、部数、届け先、総額、支払方法、発送予定、返品条件、注文確定操作を一画面で再表示する。

## 9. 最小実装順

### A. 表示と言葉の修正

1. 完了：選択後の結果を `PDFとして共有` と `本のイメージを見る` に分離する
2. 完了：20枚だけを本の試作へ渡し、PDFの1〜30枚とは別policyにする
3. 完了：購入前の `つくったもの`、疑似注文済み状態を表示しない

### B. 一商品だけの注文パイロット

1. 完了：Appで20枚と順番、製造先非依存の端末内仮プレビューを確定する
2. 完了：送料込4,980円の仮説を明示した、無課金の購入希望を端末内に記録する。写真・住所は送らず、既知テスターからの希望はTestFlight feedbackで数える
3. 3〜5件の具体的希望が出たら、製造先候補へ再販、個別直送、原価、納期、保持期間を確認し、現物を試作する
4. 製造先と入稿規格を一つ決めてから、商品専用renderer、注文専用copy、24時間sessionを作る
5. 商品専用D1／R2、Webプレビュー、Stripe Checkout、Webhookを実装する
6. 手動入稿、発送状態、問い合わせ、削除処理を運用する
7. 信頼できる5〜10件だけの有償パイロットを行う

受注生産として在庫を持たず、入金確認後に1冊ずつ発注する運営は採用できる。ただし、製造可能な経路、再販許諾、現物品質、原価、具体的な発送期間を一つ確定する前には、代金を受け取らない。

### C. Plusの販売準備

1. 継続価値を実写真で確認する
2. App Store Connectへ月額・年額商品を同一groupで作る
3. 無効状態の課金基盤を隔離stagingへ接続する
4. 購入、保留、更新、解約、猶予、失効、返金、復元、機種変更を確認する
5. 既存β利用者のまどとプロフィールを維持する移行を行う
6. 条件を満たした価値だけを購入画面へ載せる

物販パイロットとPlus販売準備は技術的には並行できるが、利用者へ同時公開しない。先に一商品を手動運用し、Plusは継続価値と復元が成立してから販売する。

## 10. 今は作らないもの

- ショップの下部タブ

- 複数印刷会社への自動振り分け

最初に検証するのは、商品数ではなく `思い出から本を作り、迷わず支払い、無事に届く` 一経路である。

## 11. 根拠

- Apple App Review Guidelines 3.1.1：アプリ内で利用するデジタル機能の解除はIn-App Purchaseを使う。
- Apple App Review Guidelines 3.1.3(e)：アプリ外で消費する物理商品はApple Payやカード等、In-App Purchase以外で支払う。
- Apple StoreKit：購入権の復元とサブスクリプション管理を利用者へ提供する。
- Stripe Checkout：決済完了後の処理はブラウザ遷移ではなくWebhookを正本とし、冪等に行う。
- 特定商取引法の通信販売規定：価格、送料、支払方法、引渡時期、返品条件、販売者情報を表示し、最終確認画面でも主要条件を明示する。
