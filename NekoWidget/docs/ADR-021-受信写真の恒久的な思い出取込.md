# ADR-021：受信写真を本人の「思い出」へ明示的に取り込む

> **利用者向け語彙の更新（2026-08-26）：** 本文の「思い出に追加」は現行画面では「思い出に残す」と表示する。写真アプリへの明示取込、通常の思い出・PDF・将来の本へ統合する決定は継続する。本文は決定当時の履歴として改変しない。

日付: 2026-08-25
状態: 採用・実装済み
関連: [ADR-020](ADR-020-思い出とハートの操作分離.md)

## 背景

ADR-020で受信写真にも「思い出に追加」と表示したが、実体は共有履歴内の最長90日の印だった。この表示では、自分の写真の「思い出」と同じ一覧やPDFへ入ると受け取られやすく、実際の保持境界と一致しない。また、期限付きの印だけでは、届いた写真をあとでまとめるという製品価値を満たせない。

## 決定

- 受信写真の「思い出に追加」は、利用者の明示操作で位置情報を除いたJPEGを写真アプリへ1回だけ追加し、そのPhotos assetを通常の「思い出」へ追加する。
- 初回だけ、操作の文脈内でPhotoKitの追加権限を求める。権限がない場合は共有写真を変更せず、設定方法を案内する。
- 作成したPhotos assetのlocal identifierを、元のmoment IDと対応付けて端末内に保存する。同じ受信写真を再度追加しても写真を複製しない。
- 追加後の写真は通常の「思い出」一覧、PDF、将来の製本候補に含める。iCloud写真がオンならAppleと利用者の設定に従って同期される。
- 「思い出から外す」は通常の思い出印だけを外し、写真アプリの写真は削除しない。もう一度追加した場合は同じPhotos assetを使う。
- 共有解除、ブロック、共有履歴の期限切れ、アプリ削除は、写真アプリに取り込んだ写真を削除しない。相手への通知も行わない。
- 旧Buildの期限付き`savedMemories`は安全に読めるまま残すが、それだけを恒久取込済みとは表示しない。新しい操作が成功した時だけ取込済みとする。
- PhotoKitへ書き込む前にmoment IDと不透明なimport tokenのjournalを端末内へ確定する。書込み後にprocessが止まった場合は、写真resourceの不透明なfilenameと照合して同じPhotos assetを復旧し、再コピーしない。
- 写真アクセスが「選択した写真のみ」の場合、identifierを取得できないことは削除の証明にならない。既存mappingや未完了journalを消さず、曖昧な再取込には「すべての写真」アクセスを求めて重複をfail closedする。
- 「すべての写真」アクセス中にPhotos assetが存在しないと確認できた場合だけ古いmappingを外す。写真アプリから削除した取込写真を、アプリの思い出・PDF・将来の本へ残像として維持しない。

## Widget

Widgetの星は同じ意味を保つ。PhotoKit権限の確認や取消不能な取込が必要な写真ではHost appを開いて対象を再検証してから確定する。Widget Extensionだけで期限付きの印を恒久保存のように表示しない。

## 結果

自分の写真と届いた写真は、どちらも同じ「思い出」に溜まり、同じPDF・将来の本へ利用できる。ハートは引き続き相手へ送る反応だけで、保存とは混ざらない。ADR-020のうち、受信写真の「思い出に追加」を最長90日の印とする判断と、写真アプリへのコピーを別操作とする判断を本ADRで置き換える。
