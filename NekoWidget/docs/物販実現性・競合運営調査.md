# 物販実現性・競合運営調査

作成：2026-09-03  
状態：公式公開情報と現行実装に基づく、問い合わせ・試作開始の判断資料。価格、製造先、販売着手は未決定

関連：[課金と商品化の導線](課金と商品化の導線.md)、[ADR-024](ADR-024-無料体験とPlusと物販.md)、[製品構造](製品構造.md)

## 0. 結論

最初の物販候補として **小型のフォトブック一商品** は、技術的に試作でき、現行アプリとの接続も自然な有力仮説である。ただし、需要、支払意思、製造条件は未検証であり、販売商品としての採用はまだ決定しない。現行案の `まどの本 mini／マットなソフトカバー／送料込3,480円` は、そのまま正式商品にはしない。

採用する商品仮説は次とする。

| 項目 | 推奨する初期仮説 |
|---|---|
| 商品カテゴリ | **ねこの小さな本** |
| 個別表示名 | **「しずくの20枚」** のように猫名で個人化 |
| 利用者 | 1人利用を基本。贈り先や共有相手は任意 |
| 判型 | 約15cm角 |
| ページ | 24ページ、思い出20枚、1ページ1枚を基本。別の表紙画像が必要かは製造先確定後に決める |
| 品質 | 厚手マット、合紙・レイフラットまたは小型ハードカバーを優先 |
| 編集 | 表紙1系統、本文1系統。写真交換・順番・cropだけ |
| 選定価値 | 猫だけ、重複を除く、日付・場面を散らす。届いた写真は本人が写真アプリへ取り込み、思い出に残したものだけを含める |
| 購入用途 | 自分用を既定、贈るを任意選択 |
| 価格候補 | **送料込4,980円**を支払意思調査に使う。製造・直送の着地原価2,000〜2,200円以下は一次選別の必要条件であり、販売可能性の十分条件ではない |
| 初回販売 | 信頼できる5〜10件だけの有償パイロット |

`ねこの小さな本` は管理上の商品名であり、利用者へ常に一般名を見せる必要はない。選定完了時には `しずくの20枚を本にできます` と、すでに自分向けに作られている結果を見せる。

この商品で売るものは印刷枚数ではない。**何千枚から猫だけを見つけ、似た連写を除き、本人が残した写真を迷わず一冊にできること**である。相手から届いた写真も、本人が明示的に取り込んで残した後なら同じ候補になる。猫の絵柄を付けただけの一般フォトブックでは差別化できない。

## 1. 現時点の実現可能性

### すでにある土台

- 写真ライブラリから猫写真の候補を見つける
- 写真を思い出に残す
- まどから届いた写真を取り込む
- まどから届いた写真も、本人が写真アプリへ取り込み「思い出に残す」と通常の候補にできる
- 1〜30枚を選び、端末内でA4縦・余白付きPDFへ書き出す（[現行実装](../NekoWidget/Services/PhotoBookPDFExporter.swift)）
- Webで商品説明、サンプルプレビュー、届け先、決済完了までの見た目を体験する

### まだ実販売には使えない部分

- 現在のPDFは共有用A4 PDFであり、印刷会社の塗り足し・裁ち落とし・色・ページ順を満たす入稿PDFではない
- Webはサンプル写真と画面内状態だけで動く体験版であり、実画像、注文、決済、通知を保存しない
- 商品用D1／R2、Stripe Checkout／Webhook、運営画面、削除処理が未接続
- 製造会社との価格、直送、白ラベル、再印刷、データ保持、API条件が未確定
- 通信販売の法定表示、返品・再印刷規約、問い合わせ運用が未確定

したがって、**試作品を1冊作る実現可能性は高いが、不特定多数へ安全に販売できる状態ではない**。難所は画面作成ではなく、支払い後に写真・住所・入稿・再印刷を取り違えず運営する部分である。

初期のサーバー費用は主要障害ではない。Cloudflareの公開枠では、R2 Standardに月10GB、Class A 100万回、Class B 1,000万回の無料枠があり、D1 Freeには1日500万行の読み取り、10万行の書き込み、合計5GBがある。少人数パイロットなら収まり得る。一方、現在のWebプロジェクトはD1／R2とも未作成である。低コストで始められることと、写真・住所を安全に扱えることは別なので、共有サービスの保管領域を流用せず商品サービスを分離する。

### 成功例に共通する構造

1. **写真を集める場と買う場がつながっている**  
   注文のたびに20枚を最初から探させない。
2. **商品を探させず、作れた結果を提案する**  
   `フォトブックを買いませんか` より `20の違う瞬間がそろいました` が先に来る。
3. **製造を固定化する**  
   判型、ページ数、本文layout、梱包を固定し、例外と検品を減らす。
4. **価格以外の不安を取り除く**  
   切り抜き、暗さ、解像度を事前に警告し、全ページプレビューと再印刷保証を置く。
5. **低価格会社は規模の仕組みを持つ**  
   自社工場、固定規格、大量処理がある。新規serviceが小売価格で仕入れて低価格競争するのは持続しない。
6. **再購入理由を商品そのものの外にも持つ**  
   月次提案、期限、サブスクの購入枠、家族アルバム、追加オプションなどが次の注文を作る。

## 3. ねこのまど固有の勝ち筋

乳幼児向けserviceの月齢成長をそのまま猫へ移植しない。猫は成猫後の見た目の変化が小さいため、毎月の本を義務にすると似た写真が増え、価値が薄くなる。

代わりに、次の条件で一冊を提案する。

- 異なる日付・場面の高品質写真が20枚そろった
- 連写・近似写真の代表を一枚へまとめられた
- 寝る、遊ぶ、窓辺、家族と一緒、季節等に偏りすぎていない
- 自分が残した写真と、まどから受け取った後に本人が取り込んで残した写真が入っている
- 誕生日、迎えた日、一年、季節、見送り等の節目がある

通知例：

> しずくの、違う20の瞬間がそろいました

開いた後に初めて、本のプレビューと交換操作を見せる。購入しなくても選定結果は通常のまとめとして見られ、販売カードを居座らせない。

これにより、1人で使う人も共有する人も対象になる。共有は本の必須条件ではなく、**相手から届き、自分も残した写真まで一冊へ集まる追加価値**になる。ハートを本の選定信号として使う案は、現在の「相手へ返す反応」という意味を変えるため採用しない。将来検討する場合も、端末内処理と明示的な説明・同意を別途設計する。

### 最初の問い合わせで必ず聞くこと

1. 内容が異なる本を1件1冊、注文者ごとに別住所へ直送できるか
2. 納品書・価格・印刷会社名を出さない白ラベルと、ねこのまど名義の梱包が可能か
3. 15cm前後の正方形、24ページ、マット、合紙／レイフラットまたはハードカバーの選択肢
4. 税・梱包・送料込み単価、最低数量、初期費、月額、API費、数量割引
5. APIで入稿、注文、キャンセル、住所変更、進捗、追跡、再印刷をどこまで扱えるか
6. RGB／CMYK、ICCプロファイル、解像度、塗り足し、安全域、フォント、PDF規格、最大容量
7. 通常・繁忙期の入稿締切、製造日数、配送日数、遅延時の通知
8. 色ずれ、裁断、破損、紛失時の判定、無償再印刷、返金、写真再提出のSLA
9. 画像・PDF・住所をどこに何日保持し、削除証跡を提供できるか
10. 再販、写真の権利、秘密保持、個人情報委託、再委託先を契約で確認できるか

## 5. 目標運営フロー

```text
アプリ
猫写真を自動選定 → 交換・順番・切り抜き → 注文用コピーへ同意
  ↓ 一回限りの交換token
商品Web
tokenを一度だけHttpOnly sessionへ交換（最終操作から24時間）
全ページプレビュー → 自分用／贈る → 住所 → 総額・納期・返品条件 → 決済
  ↓ 署名済みWebhook
商品サービス
注文を一度だけ確定 → 入稿PDF固定 → 入稿前検査 → 運営確認
  ↓
印刷会社
製造 → 追跡番号 → 発送／再印刷
  ↓
アプリ／メール
印刷中 → 発送済み → 到着 → 写真・PDF削除予定
```

役割は次に固定する。

- **アプリ**：写真発見、猫専用選定、編集意思
- **Web**：大きなプレビュー、住所、価格、法定表示、決済
- **商品サービス**：注文用画像、注文状態、監査記録、期限削除
- **Stripe**：カード情報と支払状態
- **印刷会社**：製造、梱包、配送、製造不良の再印刷
- **運営者**：最終入稿前検査と例外処理。写真や住所の手転記はしない

通常状態は `下書き → 支払待ち → 支払済み → 入稿前検査 → 入稿済み → 印刷中 → 発送済み → 到着 → 画像削除済み` とする。例外状態として `決済失敗／期限切れ／発注前取消／要修正／住所訂正待ち／製造先拒否／配送紛失／返送／再印刷中／再印刷完了／返金／chargeback対応中` を持つ。決済完了画面を見たことではなく、署名を検証したWebhookだけを支払済みの正本にする。

購入済みの写真と入稿PDFは、追跡上の到着から30日後、追跡できない場合は発送から45日後を削除予定日とする。不良申告、再印刷、返金、chargebackが開いている間は削除を保留し、解決後に新しい削除予定日を確定する。注文番号、金額、税、状態、削除証跡等の非画像記録は会計・問い合わせに必要な期間だけ分離して保持する。

## 6. 躓きそうな点と対応策

| 躓き | 起きること | 対応策 | 販売開始条件 |
|---|---|---|---|
| 似た写真ばかり | 猫は同じ場所・構図の撮影が多く、本が単調になる | 知覚ハッシュ、撮影時刻、構図、場面でまとめ、代表一枚を選ぶ。20枚の多様性スコアを表示 | 連写の検証用データで同じ場面が連続しない |

| 暗い／白飛び | 黒猫が潰れ、白猫の毛が消える | 黒猫・白猫・逆光・室内を含む共通sampleを3社で印刷。明度警告と補正preview | sampleの黒・白・肌色を所有者が承認 |

| 現PDFを流用 | A4、RGB、余白、ページ構造が製造先規格と合わない | 製造先別テンプレートから専用レンダラーと入稿前検査を作る。共有PDFとは実装を分離 | PDF検査とテスト印刷を通過 |
| 決済二重処理 | Webhook再送や同時実行で二重発注 | event ID・Checkout Session・注文に一意制約、冪等な確定、`入稿済み` ロック | 同じWebhookを複数回送るテストで発注1件 |
| 住所誤り | 高額な再配送・個人情報事故 | 住所検証、確認画面、発注前の短い訂正猶予。運営の手転記禁止 | 注文dataからvendorへ一貫して渡る |

## 7. 価格と採算

### 現行3,480円が危険な理由

Photoback ROUGHの一般価格をそのまま使う仮計算では、24P 2,904円＋ネコポス290円＝3,194円である。3,480円販売時のStripe標準国内card手数料3.6%は約125円で、残りは161円しかない。再印刷引当5%を174円置くだけで赤字になり、運営時間、問い合わせ、税、返金を含められない。

この時点で、送料込3,480円には小売仕入れを使えない。梱包・送料込み製造原価1,500円以下を、次の見積を読むための厳しい一次目安として置くが、そこを下回るだけで販売可能とは判断しない。税、工数、返金・再印刷実績を含む後述の合格線も満たす必要があり、現在はその見積も実績もない。

### 4,980円の感度分析

| 税込送料込売価 | 税込製造・直送原価 | Stripe 3.6% | 仮の再印刷引当5% | 税・工数等を引く前の残額 | 売価比 |
|---:|---:|---:|---:|---:|---:|
| 4,980円 | 1,800円 | 約179円 | 249円 | 約2,752円 | 55.3% |
| 4,980円 | 2,200円 | 約179円 | 249円 | 約2,352円 | 47.2% |
| 4,980円 | 3,194円 | 約179円 | 249円 | 約1,358円 | 27.3% |

これは同じ税込金額同士で危険度を見るための感度分析である。5%は実績のない仮置きであり、表の残額・比率を貢献利益とは呼ばない。消費税、問い合わせ工数、返金手数料、チャージバック、製造先の月額／API費、販促、クラウド費を含めた正式な損益ではない。

着地原価2,000〜2,200円以下は、4,980円仮説をさらに検証するための一次選別にすぎない。販売判断前に税抜へ統一し、次を注文一件ごとに計測する。

```text
税抜売上
- 製造・梱包・直送
- 決済手数料
- 再印刷・返金引当
- 1注文あたり運営工数
- 注文保管・通知
= 注文貢献利益
```

暫定の事業合格線として、15分の運営工数を人件費に換算した後で、注文貢献利益が **1,500円以上かつ税抜売上の35%以上** 残ることを推奨する。これは業界標準ではなく、少量運営で例外対応を吸収するための内部目標である。月間固定費をこの一件貢献利益で割り、損益分岐注文数が現実的かも同時に判断する。返金・再印刷引当率は5〜10件では安定しないため、限定公開後も実績更新を続ける。

最初の本を安くする必要はない。ただし4,980円なら、一般的な薄いソフトカバーではなく、手に取った時に品質差が分かる仕様と、猫専用の選定価値、全ページプレビュー、再印刷保証が必要である。

## 8. 段階的な開始方法

### Stage 0：需要を先に確認する（決済なし）

1. アプリ内で20枚の選定・交換・順番と、製造先に依存しない正方形の仮プレビューを動かす
2. 送料込4,980円を隠さず表示した後に `この内容で注文を希望する` を置く
3. `まだ注文・決済ではありません` と明記し、写真・住所は送らず、希望と連絡先の任意登録だけを受ける
4. プレビュー到達数、価格表示後の希望率、離脱箇所、自分用／贈答、購入時期を記録する
5. 3〜5件の具体的な購入希望が集まったら、製造確認へ進む。集まらなければ製造連携を作らず、商品・価格・提案時期を見直す

無課金の希望登録は、実際の支払いより意思が弱い。そのため販売成立の証明とは呼ばず、数万円規模の試作・契約調査へ進むための足切りにだけ使う。

### Stage 1：製造先と現物を決める

1. Photoback／MONO-LINKとしまうまOEMへ、見込件数を添えて同じ質問票を送る
2. 最有力2社で、同一の検証用写真を使ったサンプルを各1〜2冊作る：黒猫、白猫、逆光、暗所、縦、横、複数猫、連写
3. 色、切り抜き、綴じ、紙、梱包、納期、再印刷対応を採点する
4. 1冊個別直送の着地原価、再販許諾、納期、データ削除条件を書面で確認する
5. 24ページに `思い出20枚＋別表紙1枚` が必要か、同じ写真の表紙再利用が可能かを製造先ごとに確定する
6. 実物を見せ、猫を飼う人5〜8人に3,480円／4,980円／6,480円の購入判断をもう一度確認する

### Stage 2：閉じた有償パイロット

- 信頼できる5〜10注文
- 1商品、1表紙、1本文layout、1注文1配送先
- 自分用を既定、贈るは任意
- 運営者が入稿前にコンタクトシートを確認
- 記録：作成完了率、支払率、1件工数、問い合わせ、再印刷、到着日、品質評価、もう一度買う契機

合格条件：誤配送・写真取り違え0、重大なプレビュー差0、運営工数中央値15分以内、製造・配送・再印刷の責任分界が書面化されていること。加えて、提示した人の反応から価格受容と作成完了の基準値をパイロット開始前に決め、実績と比較する。

### Stage 3：限定公開

- 直接製造先へ入稿・直送
- Appとemailで状態を返す
- よくある失敗を入稿前検査へ反映
- 販売価格を実原価と実工数から確定

### Stage 4：自動化

週10件超、1件15分超、または手動エラー率2%超のどれかが見えた時に、製造先API発注を優先する。30〜50件の有償注文で再購入・贈答需要を確認するまで、二つ目の商品を追加しない。

二つ目の候補は、同じ20枚packageから作れる正方形カード／卓上displayを優先する。本のサイズ違いを増やすより、猫の写真を日常で見る別の用途を増やした方が検証情報が大きい。

### 製造先決定前に入金を受けない理由

受注生産や予約販売そのものを否定するものではない。製造先、製造可能な仕様、着地原価、現物品質、再販許諾、発送可能期間を一つ確認できた後なら、在庫を持たずに注文を受け、入金後に1冊ずつ発注する運営でよい。

一方、製造手段が未確定の段階で代金を受けると、利用者との販売契約と返金責任だけが先に発生する。通信販売では、販売価格、支払時期、具体的な引渡期間、返品条件等を示す必要があり、`製造先が決まり次第` や `入荷次第` だけでは具体的な引渡時期にならない。前払い後に引渡しまで時間がかかる場合は、承諾の有無、受領額、商品・数量、引渡時期等の通知も必要になる。

カードを仮押さえして製造先決定後に売上確定する方法も、通常のオンラインカード認証は有効期間が概ね7日であり、製造先探索の待ち時間を安全に吸収する仕組みにはならない。したがって `無課金の価格付き希望登録 → 製造経路を一つ確定 → 少人数だけ実決済` とする。
