# 猫個体識別：モデル単体確認

2026-09-05。Build 129配布待ち中の独立調査。アプリ・Widget・共有サーバー・署名設定は変更しない。

## 判断

**モデル単体のI/O確認は合格。iPhone向けの独立試作候補として継続する。製品同梱・自動振り分けの提供は保留。**

純Core MLファイルをまだ作れていないことだけで不採用にはしない。[ONNX Runtimeの公式iOS対応](https://onnxruntime.ai/docs/tutorials/mobile/deploy-ios.html)を利用すれば、公開ONNXを端末内で実行する経路がある。別途、[CoreML Execution Provider](https://onnxruntime.ai/docs/execution-providers/CoreML-ExecutionProvider.html)を利用する選択肢もある。ただし本モデルのCore ML実行・演算子対応・CPUへのフォールバック割合は未検証。追加runtime、初回準備、キャッシュ、容量、メモリも評価対象になる。

現行の最低OSは`Config.xcconfig`のiOS 17.1で、公開されているCoreML EP／MLProgramの最低OS条件には合う。これだけで現行アプリへ組み込めることや、実用速度を証明しない。

## 今回の実測

[固定モデルrevision](https://huggingface.co/open-noodle/pet-recognition-small/tree/9dd4c915be29a81b116b3e30eb996c59d0e7ede0)の`recognition/model.onnx`だけを取得した。学習データ、ユーザー写真、プロフィール、PhotoKit IDにはアクセスしていない。

| 項目 | 結果 |
| --- | --- |
| モデル容量 | 89,227,604 bytes（約85.1 MiB）。アプリ容量の増分とは別 |
| SHA-256 | `6a5e2373ab348bed588cef4072f3914ca9c8bacde3e8d0651019e8dad86b24ba`。公開LFS情報と一致 |
| 環境 | Windows、ONNX Runtime 1.22.1、CPU、intra-op 2 threads、NumPy 2.4.5 |
| 入力 | 合成RGB 3種類。float32、N×3×224×224、公開mean／stdで正規化 |
| 出力 | N×512。有限値、L2 norm≈1を確認 |
| 一括／単独処理 | batch 3と各batch 1の最大絶対差0.0 |
| セッション作成 | 364.01 ms（このPCの1回の測定） |
| warm推論中央値 | 142.71 ms／入力（合成入力3件、このPCの参考値） |
| 猫の精度・iPhoneの性能 | **未測定**。上記時間から推定しない |

確認コードは[`ci/probe-pet-recognition-model.py`](../ci/probe-pet-recognition-model.py)。サイズとハッシュが異なるモデルを拒否し、合成入力だけで推論する。ネットワーク通信、モデルの自動取得、写真読み取り、特徴量の保存、アプリデータ書き込みは行わない。出力は集計だけ。一般的なCPUベンチマークや精度評価ツールではない。

再実行例（同じ環境・モデルが必要。通常のアプリCIには追加しない）：

```powershell
& '.codex-artifacts\pet-model-probe\venv\Scripts\python.exe' `
  'NekoWidget\ci\probe-pet-recognition-model.py' `
  '.codex-artifacts\pet-model-probe\model.onnx'
```

モデル・評価専用Python環境はgit対象外の`.codex-artifacts/pet-model-probe/`に分離した（合計146.63 MiB）。グローバルPythonにパッケージを追加せず、評価環境から既存NumPyを参照する。モデルのアプリ同梱、Gitへの追加、CIキャッシュ、TestFlight再作成はしていない。想定外の小さいファイルを指定した場合に、推論前に拒否することも確認した。

## 配布条件とコードの境界

モデルカードはApache-2.0を表記する。一方、作者の[Galleryリポジトリ](https://github.com/open-noodle/gallery/blob/268633b07d3da44488dc855ef5a63be4d8c97324/LICENSE)はAGPL-3.0で、モデルと同一の条件とは扱わない。今回の確認コードは公開I/O仕様とONNX Runtime APIに基づく独自実装で、Galleryコードをコピー・依存していない。

作者の[公開処理](https://github.com/open-noodle/gallery/blob/268633b07d3da44488dc855ef5a63be4d8c97324/machine-learning/pet-recognition-training/src/petid/publish.py)はONNX、README、metricsを公開する構成で、別の学習済みhead checkpointは公開一覧で確認できなかった。ONNX単体推論に追加checkpointは不要だが、純Core MLへ再構築した場合の数値一致は今回未確認。

[ATTRIBUTION.md](https://github.com/open-noodle/gallery/blob/268633b07d3da44488dc855ef5a63be4d8c97324/machine-learning/pet-recognition-training/ATTRIBUTION.md)は学習元の表記を補強するが、画像の権利処理や固定モデルとの学習来歴を独立に証明する資料ではない。商用配布時にはモデル・runtime・採用コードの条件、必要なライセンス文と帰属表示を別々に確定する。モデルカードの商用利用可能という作者の説明を、こちらが権利保証したことにはしない。

## 次の判断点と停止条件

1. 本体へ依存を追加する前に、独立したiPhone試作でCPUとCoreML EPを比較する。cold開始時間、連続推論、ピークメモリ、容量とUI応答を記録する。PCやシミュレータの結果で代用しない。CPU経路も含めて実用性が見込めなければ止める。
2. 性能の見込みが立った後、利用を許可された実写と新しい固定protocolで5枚登録・別場面評価を行う。写真を外へ送らない。合成入力は猫の正誤を評価できないため代用しない。
3. [ADR-016](ADR-016-猫個体5-shot分離実験.md)のprecision／coverage、unknown、独立episode、別家庭での最終評価という条件を維持する。旧評価写真で閾値を調整して「新たに合格」としない。
4. 合格しても最初は利用者が確定する「候補」。候補を確定所属へ自動保存しない。確認の手間が手動より減らなければ公開しない。

現行版はBuild 129の任意プロフィール、複数所属、手動指定、通常Photosアルバム連携のまま。今回の単体合格を理由に、新しい課金条件や自動識別をうたうUI／LPを追加しない。

## 追補：独立iOS試作

同日の[独立試作](../../experiments/PetIdentityProbe/README.md)で、別bundleのiPhone向け無署名コンパイル、Simulator起動、CPU／Core ML EPの合成入力実行を確認した。入力形状を1枚分へ固定することで、初回に見つかったCore MLコンパイルエラーは解消した。ただしCore ML初回準備で約1,080 MiBのプロセスメモリ観測があり、本体採用は保留。次はCPUを中心に実機性能を確認する。iPhone実機の結果、猫の精度、商用同梱の判断はいずれも未確定。本体・main・TestFlight Build 129へは反映していない。
