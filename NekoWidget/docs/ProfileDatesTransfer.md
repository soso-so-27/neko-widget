# 名前と日付だけのプロフィール引き継ぎ

Build132に含めた名前・日付だけの引き継ぎは、利用価値が十分に確認されていなかったため、設定画面の入口を取り下げた。以下は既存実装の記録であり、現在の画面から使える機能の案内ではない。配布済みBuild132には入口が残る。

## ファイルの内容

専用format/versionを持つJSON。猫UUID・名前・両日付・概算指定・成長表示の基準だけを許可リストとして書き出す。日付は年月日のまま保持し、端末の時差で変えない。同名の猫もUUIDで区別する。

写真原本、サムネイル、PhotoKit ID、猫別の写真所属、代表写真、アルバム連携、思い出の印、共有まど、購入権は対象外。アプリ全体のバックアップとして案内しない。価格や課金条件を追加しない。

利用者が標準のファイル保存画面で保存先を選ぶ。アプリ独自の一時書き出しファイルは作らない。読み込みは明示選択されたファイルのsecurity-scoped access中だけ行い、最大64KiBに制限する。内容・猫名・日付・外部ファイルURLをログへ記録しない。

## 適用条件

- 内容確認画面で「この内容を引き継ぐ」を選ぶまで保存しない。キャンセルは無変更。
- 初回適用先はプロフィール・所属・除外・対象アルバム・旧日付が空の端末。現在の設定と旧schema互換情報の両方を確認する。
- 同じUUID・名前・日付の再読み込みは無変更。既存の写真設定も維持する。
- 別の既存プロフィールや写真設定へ上書き・自動マージしない。
- 確認時のidentity/curation revisionと旧日付を適用前に再確認。関連設定変更と同じ直列化経路で、既存storeへ1回だけcompare-and-swap保存する。競合時は中断し、新しい内容へ勝手に再適用しない。
- 未対応version、不正日付、空の名前、重複UUID、大きすぎるファイルは拒否する。

写真所属までの引き継ぎは別タスク。猫個体識別研究やiCloud写真の対応付けはこの機能の条件にしない。

## 検証

既存 `verify-cat-household-identity.swift` に、日付と概算・表示基準の往復、写真情報の非出力、同名猫の保持、同一ファイルの無変更、既存設定の拒否、確認中のrevision競合、失敗時のディスク状態維持を追加。

実機ではファイル保存・同一ファイルの再読込を既存データを消さず確認できる。空の端末への実適用は、別のテスト環境がある場合に確認する。確認のために利用中のアプリを削除しない。

API根拠：[FileDocument](https://developer.apple.com/documentation/swiftui/filedocument)、[fileImporter](https://developer.apple.com/documentation/swiftui/view/fileimporter(ispresented:allowedcontenttypes:oncompletion:))。
