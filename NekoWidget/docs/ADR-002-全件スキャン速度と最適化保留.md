# ADR-002：全件スキャン速度は実機計測まで最適化しない

- 状態：承認済み
- 日付：2026-08-16
- 根拠：GitHub ActionsのiOS 18.6 Simulatorで実施した1,000枚スケールテスト
- 対象Run：<https://github.com/soso-so-27/neko-widget/actions/runs/31900178240>

## 観測結果

重複しない合成写真1,000枚（うち8000×6000pxの48MP画像3枚）を追加し、CPU-onlyのVisionを使うSimulator上で全件スキャンを実施した。

- アプリ起動から確定結果まで：123.595秒
- SharedLog上のスキャン区間：119.630秒
- 新規解析：1,000枚
- 観測スループット：約8.1〜8.4枚／秒
- 最終状態：`completed / final`
- failed / deferred：0 / 0
- lifetime physical footprintのピーク：76.147MiB
- 途中終了、クラッシュ、JetsamEvent、EXC_RESOURCE：なし

この値はHosted Simulator、CPU-only Vision、合成画像による参考値であり、iPhoneのNeural Engine、実写真の形式、iCloud状態、端末温度やライブラリ構成を代表しない。

## 判断

v1ではスキャン速度の最適化を行わない。

- ライブラリ全体の確定まで数十分かかる可能性は許容する。
- 先に処理済み枚数と猫の途中枚数を速報として出し、全件完了後だけ確定値を表示する現在の段階設計を維持する。
- 起動時とフォアグラウンド復帰時の同期を確実な経路とし、バックグラウンド処理はbest effortのままとする。
- 並列数、Vision入力サイズ、モデル呼び出し、永続化頻度の変更は、実機データなしでは行わない。

## 理由

現時点で重要なのは、「これ好き」が押されるか、猫写真の選別品質、Widget表示が実データで成立するかの検証である。Simulatorだけを基準に性能を調整すると、実機のNeural EngineやPhotoKitの挙動に対して逆効果になる可能性がある。速報と確定の分離により、全件完了を待たずに進捗と途中結果を提示できるため、実機計測前の最適化は優先しない。

## 実機で記録する値

最初のTestFlight実機検証では、同一セッションについて次を記録する。

1. 対象端末、iOS、写真総数、ローカル／iCloudの内訳
2. 起動から最初の速報表示まで
3. 500枚処理完了まで
4. 全件確定まで
5. 平均枚数／秒と、前半・後半での速度低下
6. physical footprintのピーク、温度上昇、アプリ終了やjetsamの有無
7. バッテリー消費とUIの操作可能性

## 再検討条件

次のいずれかを実機で確認した場合に最適化を再検討する。

- 最初の有用な速報が体感上遅い
- UIが長時間操作不能になる
- 全件確定が検証継続を妨げる
- メモリ、温度、バッテリー、jetsamに問題が出る
- 日常的な差分同期でも全件相当の再解析が発生する
