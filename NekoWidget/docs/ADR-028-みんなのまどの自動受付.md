# ADR-028 みんなのまどの自動受付

- 日付：2026-10-30
- 決定：1030q。1.0 のみんなのまどでは確認の言葉と手動承認を使わない。
- 前提：#631（7bfc23b9）。通常の2人用のまどの招待方式は変更しない。

## 体験と理由

リンクを持つ人が「参加する」を押すと、招待を作った iPhone が自動で迎え入れる。設定で手動承認へ切り替える選択肢は作らない。作った人が前面に戻る、参加通知を押す、OSからバックグラウンド実行機会を得る、メンバー画面が更新される時に処理する。人同士の往復を減らす一方、iOSが実行・通知を保証しないため即時参加は保証しない。通知なしでも起動時に続ける。

招待者は信頼する相手にリンクを送る。秘密を持った申し込みだけを認める方式であり、人間の実名の身元保証ではない。入る前の写真の鍵は渡さず、外した後の写真も渡さない。誤って渡した場合は招待の取消と参加者の削除で止める。

## 残す確認

- 招待を作った端末にある秘密から導く公開鍵で、NW3.JOIN の署名を独立検証する。サーバーが返す名前・IDだけで鍵を渡さない。
- 署名対象の元のchallenge、期限、operation、本人ID、端末ID、暗号化名、本人による端末の承認を照合する。消費済みchallengeの照合資料は申し込みに結び付けた別表で保存し、再送用の本文は変えない。
- 本人・端末の鍵とID、暗号化名、現在のowner、稼働状態、人数・端末数、revision CAS、招待の期限・取消、運営による受付休止を確認する。既存のロスター署名・世代更新・各端末への鍵封筒を使用する。
- 既存のownerによる管理APIの権限は変更しない。自動受付は配信停止中に新しい受付を始めない。
- 新しい照合資料のない旧申し込みは自動承認しない。既存のローカル作成記録から招待を復元できても、署名資料を捏造しない。必要なら旧申し込みを取り消し、新しいリンクでやり直す。

## 保存と通知

申し込み前にoperationと引数を端末の非同期共有をしない保護ストアへ保存する。HTTP再送は既存outboxを使い、同じリンクやプロセス再起動でも同じ申し込みへ戻る。受付側の応答紛失は、署名付きロスターの本人・端末の参加状態から回復する。結果はGroupAdmissionResultとしてモデルへ渡す。参加者はロスター・鍵の受け取りが終わってから参加済みを表示する。

参加済みの通知登録と、未参加者の申し込みに結び付いた通知登録を分ける。未参加の通知登録はメンバー行や写真へのアクセス権を作らない。通知は一般的な文言と識別子だけで、名前・写真・秘密を載せない。配信の直前にも参加状態、取消・期限、通知トークン世代、運営制限、稼働ゲートを読み直す。通知を押しても、端末の保存記録と正規のメンバー確認を通るまでは開かない。

通知の配送記録は別表で重複を防ぐ。確定済み申し込みから配送対象を導くため、遅い通知登録やWorker再起動でも取りこぼさない。通知機能の既存OFF指定は保つ。

## 招待リンク

作成直後に用意し、元の24時間の間は期限を延ばさず再利用する。ownerの認証付き照会で取消・期限・公開鍵を確認する。秘密はシェアシートだけで渡す。名前はURL fragmentの追加欄 c に暗号化して載せる。HKDF-SHA256で用途を分けた鍵とAES-GCMを使い、まど・招待・ownerの公開鍵に結び付ける。サーバーには送らず、改変された文脈は表示しない。cのない従来リンクは引き続き読める。表示名はリンク作成時の文脈であり、Apple等による本人保証ではない。

## Plusと反映境界

ADR-027 §4 のAppleファミリー共有を1.0に含める決定は取り消す。0060でgroup専用のPlus判定もPURCHASEDだけにする。適用済み0042は編集しない。0061は自動受付照合資料・通知登録・配送表を追加する。

このPRはmigrationとWorkerとアプリの候補のみ。staging/本番適用、課金操作、通知設定変更、鍵操作、配布は別の承認後。0060・0061を適用してからWorker、その後アプリを反映する。通知の実機確認にはGROUP_APNS_RUNTIME_ENABLEDと既存APNsゲートの設定確認も必要。旧Workerに戻す場合は追加表を残し、写真・メンバー・申し込みを削除しない。自動受付を止める時は既存の運営受付休止を使い、通知だけを止める時はgroup通知OFFを使う。
