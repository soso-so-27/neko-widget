# 実機技術検証チェックリスト

## 目的

TestFlightでiPhoneへ配布したビルドについて、実ライブラリ上の安定性、PhotoKit、段階スキャン、アルバム、WidgetKit、App Group、診断ログおよび猫写真の選別精度を同じ形式で記録する。

この文書では、次の2つを混同しない。

- **純粋な猫検出**：画像内に実在する猫が認識できる形で写っているか。
- **製品としての正解**：自分の実猫が主役で、「うちの子」の表示候補へ採用したい写真か。

他人の実猫や背景へ小さく写った猫は純粋な猫検出では正解になり得るが、製品としては不正解である。ぬいぐるみ、絵、テレビや画面内の猫、犬などは両方で不正解とする。

## 既知の前提

- 最低対応OSはiOS 17.1である。
- バックグラウンド同期はbest effortであり、正しさは起動時・フォアグラウンド復帰時の同期で担保する。
- WidgetKitのtimeline entryは指定時刻ちょうどの表示を保証しない。
- 写真シャッフルは設定時のアルバム内容をスナップショットとして扱い、アルバムへの後日追加を自動反映しない。この挙動は既知であり、本アプリの不具合には数えない。
- Simulatorの1,000枚テストはピーク76.1 MiBで完走済みだが、実機のjetsam安全性を保証するものではない。
- 全件スキャン速度は実機で測定する。速報表示が成立する限り、速度だけを理由に先行最適化しない。
- Build 5とBuild 6は技術検証専用だった。Build 7ではWidget再配置、full-bleed、肉球、detected無作為100枚を確認したが、Like表示不具合で1週間計測を中断した。Build 8はMedium / Largeの高解像度20件Timelineがplaceholder相当となり、Build 9でTimelineを最大2件へ修復した。Build 10の3サイズ、like／unlike即時反映、写真ブラウザの標準ページングゲートを通過するまで計測は**NO-GO**とする。計測中は別buildを測定端末へ入れず、paired probeは1週間後に番号を割り当てるInternal buildで実行する。
- Build 7のランダム100枚は`reviewNo 74`だけを製品候補から除外し、99 / 100を採用済みである。Build 10でscanner／analysis fingerprintを変えない限り、このPrecision標本を再利用し、同じ100枚をやり直さない。

## 6. ローカル取得不能の写真と大サイズ画像

1. 現行scannerの`1024×1024 / highQualityFormat / network=false`で取得不能になる写真を対象に含める。低解像度ローカル派生の有無は計測後のpaired probeまで断定しない。
2. 40MP以上、可能なら8000×6000前後の写真も含める。
3. スキャン中のネットワーク、ストレージ、端末温度を観察する。
4. 診断ログの`image-load`と最終JSONのstatusを確認する。

- [ ] スキャンは`networkAllowed=false`で大量のiCloudダウンロードを起こさない
- [ ] 現行1024px high-quality local-only requestで取得不能な写真を`unavailableLocally`として安全にDeferredへ数える
- [ ] 大サイズ写真でも1024×1024以下のthumbnail経由で処理する
- [ ] 大サイズ区間でクラッシュ、極端なUI停止、継続的なメモリ増加がない
- [ ] DeferredとFailedを猫なし判定へ混ぜない

TestFlightだけではピークメモリの実数値を取得できない。強制終了が疑われる場合は発生時刻を保存し、TestFlightのクラッシュ情報またはiOS Analyticsのjetsam記録を確認する。正確なピーク値が必要になった場合は、MacとXcodeまたはInstrumentsで別途計測する。

### 検証JSONで確認できること

- `scanState`のphase、result kind、総数、処理数、猫数、Deferred、最古日
- active settingsと`analysisFingerprint`
- assetごとの機械判定status
- detected assetのconfidence、bounding box、area ratio、cat count
- screenshot、burst、favorite、like、表示履歴
- `detectionAccuracySample`に、activeなdetected母集団から決定論的に抽出した最大100件のreview queue

```text
detectionAccuracySample

  generatedAt: ISO-8601
  containsPhotoData: false
  snapshotIsFinal: Bool
  analysisFingerprint: String
  populationDefinition: String
  sampleSeed: String
  sampleAlgorithm: String
  requestedSampleCount: 100
  populationCount: Int
  sampleCount: Int
  items[]
    reviewNumber, selectionDigest, localIdentifier, creationDate

  manualClassificationSchema
```

同じ検証JSONのrootには、診断ログのrotationに依存しない行動計測の正本として次も入る。

```text

  schemaVersion: 1
  containsPhotoData: false
  startedAt: ISO-8601 | null
  baselineLikedCount: Int
  eventCount: Int
  retentionDays: 30
```

`events.localIdentifier`は写真本体ではないが、個人の写真ライブラリに紐づくprivateな値である。検証JSONを公開しない。`assetToken`は診断ログの`asset`と同じ不可逆な短いtokenであり、時刻・操作・sourceと合わせて両方を照合する。高速な再タップでISO-8601の秒が同じでも、`sequence`と`changedAtEpochMilliseconds`で順序を確定する。1週間の集計は`startedAt`以降のeventsだけを対象にし、`historyIsComplete == true`かつ`droppedEventCount == 0`を確認する。`isLiked=true`は押下、`false`は解除であり、同じ写真の再タップを別イベントとして数える。

```text

snapshot.scanState.resultKind == "final"
asset.analysisFingerprint == snapshot.settings.analysisFingerprint
```

## 12. 検出精度の定義

### 12.1 評価対象

active fingerprintのうち、次の2 statusを混同行列の対象とする。

- **機械陽性 P**：`analysisStatus == detected && cat.detected == true`
- **機械陰性 N**：`analysisStatus == noCat`

次は混同行列へ直接入れず、別集計する。

- `unavailableLocally`：coverage gap
- `failed`：coverage gap
- `excludedScreenshot`：意図したpolicy exclusion
- `excludedBurstDuplicate`：意図したpolicy exclusion

### 12.2 人手ラベル

各写真へ次の2軸を付ける。

#### 猫存在ラベル

- `realCat`：実在する猫が認識できる形で写っている
- `noRealCat`：実在する猫が写っていない
- `uncertain`：判定不能

他人の実猫と背景へ小さく写った実猫は`realCat`である。ぬいぐるみ、絵、テレビや端末画面内だけの猫は`noRealCat`とする。

#### 製品ラベル

- `keep`：自分の実猫が主役で、表示候補へ採用したい
- `reject`：製品候補へ採用しない
- `uncertain`：判定保留

`keep`は、アルゴリズムのconfidenceや8%面積閾値を見ず、人間が写真そのものを見て決める。アルゴリズムの条件を人手正解へ流用すると、評価が循環するためである。

### 12.3 純粋な猫検出の混同行列

- **Cat TP**：Pかつ`realCat`
- **Cat FP**：Pかつ`noRealCat`
- **Cat FN**：Nかつ`realCat`
- **Cat TN**：Nかつ`noRealCat`

```text
Cat Precision = Cat TP / (Cat TP + Cat FP)
Cat Recall    = Cat TP / (Cat TP + Cat FN)
Cat F1        = 2 * Precision * Recall / (Precision + Recall)
```

### 12.4 製品としての混同行列

- **Product TP**：Pかつ`keep`
- **Product FP**：Pかつ`reject`
- **Product FN**：Nかつ`keep`
- **Product TN**：Nかつ`reject`

```text
Product Precision = Product TP / (Product TP + Product FP)
Product Recall    = Product TP / (Product TP + Product FN)
Product F1        = 2 * Precision * Recall / (Precision + Recall)
```

V1の主要指標はProduct PrecisionとProduct Recallである。Cat PrecisionとCat Recallは、Vision相当の猫存在判定と製品選別の問題を切り分ける診断値として併記する。

## 13. Coverageとpolicy exclusion

次を混同行列と並べて必ず報告する。

| status | 件数 | 扱い |
| --- | ---: | --- |
| detected | | 混同行列 P |
| noCat | | 混同行列 N |
| unavailableLocally | | coverage gap |
| failed | | coverage gap |
| excludedScreenshot | | policy exclusion |
| excludedBurstDuplicate | | policy exclusion |

分析可能な対象に対するcoverageは、次で記録する。

```text
Analysis Coverage = (detected + noCat)
                  / (detected + noCat + unavailableLocally + failed)
```

スクリーンショットと連写重複は設計上先に除外するため、このcoverageの分母には入れない。`unavailableLocally`と`failed`を自動的にFNへ数えると、猫検出性能と取得・処理失敗を混同するため避ける。

製品全体としての取りこぼしを評価したい場合は、coverage gapに含まれる写真も人手確認したうえで、別名のend-to-end指標として報告する。

## 14. 誤検出taxonomy

Product FPには、主な理由を1つ必須で付ける。複数該当する場合は、表の上にある理由を優先し、補足をnotesへ書く。

| reason | 定義 |
| --- | --- |
| `screenshot` | PhotoKit上のスクリーンショット除外をすり抜けた保存画像 |
| `tvOrScreen` | テレビ、スマートフォン、PC、印刷物などの画面・媒体内だけに猫がいる |
| `illustration` | 絵、漫画、アニメ、ロゴ、置物など |
| `plush` | 猫のぬいぐるみ |
| `otherPersonCat` | 実猫だが自分の猫ではない |
| `smallIncidentalCat` | 自分の猫だが背景の小さな写り込みで、主役ではない |
| `dogOrOtherAnimal` | 犬など別の動物を猫として採用した |
| `noCat` | 猫や猫に似た対象が見当たらない |
| `other` | 上記以外。notes必須 |
| `uncertain` | 人手でも判断できない。指標の分母から除外して件数を併記 |

連写は写真単体のFP理由と分け、burst単位で次を数える。

- **`badBurstRepresentative`**：1枚へ絞る動作自体は正しいが、残した代表より除外側に明らかに良い写真がある。

`badBurstRepresentative`は猫検出のFP/FNへ混ぜず、連写代表選択の品質欠陥として独立報告する。

## 15. 最小サンプル画面を使う暫定測定

### 15.1 detectedの無作為100件でPrecisionを推定する

1. date rangeを「すべて」にする。
2. 全件スキャンを確定まで完走する。
3. 検証JSONを書き出し、`detectionAccuracySample.snapshotIsFinal == true`を確認する。
4. `populationCount`、`sampleCount`、`sampleSeed`、`sampleAlgorithm`を精度記録表へ転記する。
5. 設定の「ランダム100枚を確認」を開く。画面の写真、`reviewNumber / sampleCount`、撮影日時は、同じ`reviewNumber`のJSON itemと対応する。標本はdetected母集団が100件以上なら100件、100件未満なら全件である。
6. 「前へ」「次へ」で写真全体を目視し、画面の`reviewNumber`を外部表へ転記する。レビュー中はJSONのconfidence、area ratio、cat countを見ない。
7. 猫存在ラベル、製品ラベル、Product FP理由を外部表へ記録する。機械のconfidenceやarea ratioを見て人手ラベルを変えない。
8. `uncertain`を分母から除外し、その件数を併記して標本内Precisionを計算する。

```text
Estimated Cat Precision = sample Cat TP / (sample Cat TP + sample Cat FP)
Estimated Product Precision = sample Product TP / (sample Product TP + sample Product FP)
```

detected母集団が100件を超える場合、これはseed固定の決定論的な擬似無作為標本による**推定Precision**であり、全機械陽性の実測値とは表記しない。100件以下ですべてを確認した場合だけ、そのsnapshotのdetected母集団全体のPrecisionとして扱える。アルバムは最大件数、重み付け、日付範囲の影響を受けるため、このPrecision標本の代用にしない。

2026-08-17までにBuild 7の確定snapshotで100件を確認し、`reviewNo 74`だけをProduct `reject`、残り99件を`keep`とした。したがってこの標本のEstimated Product Precisionは99 / 100 = 99.0%である。これはdetected母集団全体の実測値でもRecallでもない。Build 10はscannerとanalysis fingerprintを変更しないため計測再開時にこの標本を再利用する。いずれかが変わった場合は同じ値を流用せず、確定JSONから新しい100件を確認する。

### 15.3 既知の小さな集合でRecallを測る

1. 自分の猫が主役、他人の猫、猫なし、ぬいぐるみ、絵、テレビ、スクリーンショット、小さな写り込み、犬、連写を含む検証集合を作る。
2. アプリを見ずに全写真へ人手ラベルを先に付け、正解件数を固定する。
3. Limited Accessでその集合だけを許可する。
4. 全件確定後のアルバム、診断ログ、検証JSONを保存する。
5. 元の正解表と照合し、Cat TP/FP/FN/TNとProduct TP/FP/FN/TNを数える。
6. screenshot、burst duplicate、Deferred、Failedを別欄へ記録する。

この方法は検証集合内では正確だが、実ライブラリ全体のRecallを保証しない。

### 15.4 陰性を標本調査する場合

実ライブラリ全体のnoCatを目視できない場合は、無作為標本であること、母数、標本数、選び方を記録する。

noCat総数を`N_total`、無作為標本数を`n`、標本中のProduct FNを`k`とした簡易推定は次になる。

```text
Estimated Product FN = N_total * k / n
Estimated Product Recall = Product TP
                         / (Product TP + Estimated Product FN)
```

これは推定値であり、実数のTP/FP/FN表とは分ける。現在のexportにあるseed固定標本は**detectedだけ**で、`noCat`の無作為review queueはまだない。「新しい順の100枚」など便宜的な陰性抽出は偏りがあるため、正式なRecallには使わない。

## 17. 正式な実ライブラリ精度測定に必要な最小追加

現行UIは全detectedとnoCatを写真付きで対応付けて確認できないため、実ライブラリ全体のTP/FP/FNを厳密に測るには、将来次の最小機能を追加する。

1. snapshotのdetected/noCatを既存の写真loaderで1枚ずつ表示する「検出検証」画面
2. `keep / reject / uncertain`、猫存在ラベル、誤検出reasonを保存する操作
3. analysis fingerprint付きの別検証JSONへ保存し、productionのLibrarySnapshot schemaとは分離
4. export済みdetected標本に加え、seed固定の`noCat`無作為review queue
5. TP/FP/FN/TN、coverage、reason別件数、母数、標本数、seedをJSONまたはCSVでexport
6. 共有用exportではlocalIdentifierをhash化し、写真本体を含めない

閾値調整まで行う場合だけ、閾値適用前の最大cat confidence、bounding box、area ratioを別のdetector traceとして保存する。TP/FP/FNを数えるだけなら必須ではない。
