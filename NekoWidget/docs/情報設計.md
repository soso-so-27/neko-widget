# 情報設計

最終更新：2026-09-03

この文書は、機能追加時に画面の置き場所と言葉を決める基準である。技術の構成ではなく、利用者の目的で分類する。

## 製品の中心

> 埋もれていた猫写真が「写真」に並び、時間とともに巡るウィジェットで再会し、残したい一枚を「思い出」に残せる。

スキャン、分類、写真アプリのアルバム、共有サーバーは、この体験を支える手段であり最上位の目的ではない。

中心体験は一人でも成立させる。猫と、その写真を残したい人を主語にし、家族・パートナー・離れて暮らす人・友人との共有は任意の追加価値として扱う。現行の「1つのまどは2人」という技術上の上限を、対象利用者や共通コピーの「ふたり」へ置き換えない。

## 最上位の画面

共有を利用できるreleaseでは、下部タブを次の順の3つとする。共有を提供しないreleaseでは「まど」だけを表示せず、「写真」と「思い出」の意味や位置を変えない。「自動アルバム」は「写真」から開き、独立した下部タブにはしない。

| タブ | 目的 |
|---|---|
| **写真** | このiPhoneで見つけた猫写真を一覧や自動アルバムで見て、対象を整え、残す一枚を選ぶ |
| **思い出** | 自分で残した写真と、月・季節のふりかえりを見て、書き出しへ進む |
| **まど** | 名前付きの非公開なまどを選び、写真を届け合う |

設定は「写真」右上の歯車から開く。`まど`は共有全体の抽象名ではなく、利用者が名前を付けて相手を招待する各共有単位にも使う。下部の「まど」は、その一覧と選択の入口である。

Plusやショップを4つ目の下部タブにしない。Plusは本来の目的を果たそうとした文脈でだけ案内する。物販とPDFの具体的な入口は [課金と商品化の導線](課金と商品化の導線.md) を正本とし、「思い出＞残した写真＞選ぶ」から `PDFで残す` または `本にする` へ進む。実際に作成・注文して再訪できる完成物ができるまで、「つくったもの」を最上位区分として表示しない。

## 用語

| 用語 | 意味 |
|---|---|
| **写真** | このiPhoneで検出した猫写真を見る最上位画面。写真は複製・アップロードせず、写真アプリ内の元写真を読む |
| **自動アルバム** | このiPhoneで見つけた猫写真を、成長・年・写り方など説明可能な分類から探す入口 |
| **まど** | 利用者が名前を付け、信頼できる相手を招待して写真を届け合う非公開スペース |
| **ウィジェット** | 選んだ「このiPhoneの猫写真」または1つのまどを、iPhoneのホーム画面で時間とともに見返す表示。更新間隔は10〜30分の設定値を目安とし、実際の更新時刻はiOSが決める |
| **いまの一枚** | アプリ内の写真選択または共有シートから、送信前に確認して届ける1枚 |
| **思い出の一枚** | 過去写真から巡回する写真 |
| **小さな便り** | 完了した1か月の猫写真から、撮影時刻と構図が近い連続写真を保守的にまとめ、端末内で5〜7枚を選んだ短い写真便り。自動保存・送信はしない |
| **このiPhoneの猫写真** | このiPhoneから読める写真を端末内で確認した、共有ではないWidget写真源 |
| **届いた写真** | 1つのまどへ届き、このiPhone内に期限付きで保持している写真の一覧 |
| **思い出に残す** | このiPhoneにすでにある写真へ端末内の印を付け、「思い出」に並べる操作。写真アプリやiCloudへ新しい写真を作らない |
| **取り込んで残す** | まどから届いた写真を、位置情報を除いて写真アプリへコピーし、通常の思い出・PDF・将来の商品の対象にする操作。確認画面で副作用を明示する |
| **ハートを送る** | 届いた一枚に対する気持ちを、写真を届けた相手へ返す操作。保存はしない |
| **ねこのプロフィール** | 名前、日付、利用者が明示した写真を猫ごとに管理する場所 |
| **写真アプリの「うちの子」アルバム** | 既存互換のため維持するPhotos出力アルバムの固有名 |

「履歴」は送信記録や操作記録にも読めるため、受け取った写真の一覧名には使わない。「共有ボックス」は保存・バックアップを連想させるため使わない。`うちの子`は単独では対象が曖昧なため、既存Photosアルバムの固有名を明記するとき以外は使わない。1ウィジェットに異なる写真源や複数のまどを混ぜない。

## 写真

このiPhoneで検出した猫写真を3列の一覧で直接見られるようにする。一覧の直前には「自動アルバム」を置き、同じ写真を成長・年・写り方から探せるようにする。一覧から開いた写真は同じ検出写真の中を左右に移動できる。写真アクセスの追加、検索対象の写真アルバム、候補から外した写真の復元、ねこのプロフィールはこの画面から開く。自分の元写真を新しく複製しないため、操作名には「アップロード」「インポート」「取り込む」を使わず、「写真を選ぶ」「写真の対象」とする。

「今日の1枚」はウィジェットと写真一覧の役割に重複していたため、写真タブには置かない。「思い出に残す」は一覧から開く写真詳細の操作にする。共有写真と相手への「ハートを送る」は各まどに置き、混ぜない。通常画面ではアイコンだけで未知の操作を説明しない。Widgetのブックマークだけは、写真を隠す文字と状態変化による位置ずれを避けるため、同じ位置・大きさの輪郭／塗りつぶしアイコンを使い、完全な操作名と状態はVoiceOverとアプリ内の写真詳細で伝える。

実際に表示できる猫写真があり、ウィジェットが未設置のときだけ、写真一覧より前に「ウィジェットを置く」を出す。開いた先では、iOSの世代に合う3手順をカルーセルにせず1画面で示す。ホーム画面で追加してアプリへ戻ったときは設置済みを自動確認して案内を閉じる。アプリから直接設置できるようには見せない。写真が0枚、スキャン失敗、写真権限なしの場合は空のWidget設置を先に教えず、「写真」で直す操作を優先する。正常時の処理件数、統計、写真アプリ連携、診断は常設しない。

ウィジェットは写真を主役にし、操作は中立色で写真上に重ねる。対象写真は10〜30分の設定値を目安に巡るが、実際の更新時刻はiOSへ委ねられるため「毎日変わる」「20分ごとに必ず変わる」とは案内しない。思い出の操作は44ptの固定枠にブックマークだけを置き、選択前後で輪郭／塗りつぶし以外の位置・大きさ・背景を変えない。まどから届いた写真は全サイズで同じ位置にブックマークとハートの2操作を置き、常設する操作名や通信状態の文字で写真を覆わない。ハートは押すとHost appを開き、Widgetに共有しない認証情報を使う既存同期で送る。オフライン時の送信待ちはハート右下の小さな時計、サーバー受付済みは塗りつぶしで示し、完全な状態名はVoiceOverとアプリ内詳細で伝える。ハートの受付期限が終わった後も受信から90日までは写真を表示し、ボタンだけを同じ44ptの空き枠へ変えて隣のブックマークを動かさない。写真そのもののタップは保存操作にせず、その写真の詳細を開く。正常な未受信、アプリでの更新が必要な読込異常、削除済みのまどは同じ案内へ潰さない。選択中ではないまどはWidgetから状態を変更せず、写真を保ったまま短い「開く」導線で該当写真へ移動する。取り込みはHost appの確認画面で写真アプリへのコピーを明示してから行う。

「自動アルバム」は、このiPhoneで見つけた猫写真を成長・年・内容別に探して見返す入口であり、「写真」に置く。「思い出」には同じ入口を重複させない。

「小さな便り」は、撮影日が分かる猫写真を完了した月ごとに整理する。近い時刻に撮られ、猫の位置・大きさ・姿勢と端末内解析が十分近い連続写真は保守的に1つへまとめる。候補が5つ以上ある各完了月から最大7枚を選び、「思い出」の「ふりかえり」から開く。直近を大きく表示し、以前の月は重複させず「これまでの便り」へ新しい順に並べる。最新の完了月をまだ開いていない場合だけ「思い出」タブと最新カードに未読を1件表示するが、現在表示している区分を自動で切り替えない。実際にその便りを開いた時点で未読を消す。件数は積み上げず、古い便りを開いても最新の未読は消さない。対象アルバムを変えて同じ年月の構成が変わっても、その月を一度読んだ事実は月単位で共通とする。通知許可やServer同期は使わない。便りは現在このiPhoneで読める写真から再構成する一覧であり、復元可能な作品や写真のバックアップではない。写真は自動保存・共有せず、各写真の「思い出に残す」を押した場合だけ残す。条件未達では撮影を催促しない。

「季節の小さな映画」は完了した暦四半期の別作品とする。十分に異なる場面・撮影日・月がそろう場合だけ作成し、「思い出」の「ふりかえり」から見返す。最新作品をまだ2場面以上見ておらず、編集も書き出しもしていない場合だけ、思い出タブと最新カードへ新着を1件表示するが、現在表示している区分を自動で切り替えない。件数は積み上げず、過去作品には新着を表示しない。動画／Live Photoは期間へ分散し、通常はcut、月の境目だけ短いfadeでつなぐ。専用BGMは消音可能で、元動画の音は混ぜない。1場面だけ外して戻せるが元データは変更せず、明示操作時だけ端末内で安全なMP4を作る。「まど」への自動送信はしない。

## まど

まどは名前、メンバー、最新の一枚、届いた写真、共有設定を持つ。家族関係を前提にせず、画面ではまど名、`相手`、`メンバー`を使う。

1つのまどは信頼できる2人だけに限定する。一方、同じiPhoneには複数のまどを作成・参加でき、「まど」タブの一覧から明示的に選ぶ。写真、資格情報、送信待ち、届いた写真、Widget cache、Deep Linkはまどごとに分離し、不明なまどから別のまどへfallbackしない。通常利用と品質確認は1人1台を基準とし、機種変更時だけ旧・新iPhoneの一時共存を扱う。実装上は本人確認済み端末を最大4台まで登録できるが、4台同時利用を初期版の主要体験や販売上の訴求にはしない。保存形式は既存データとの互換性のため20件まで保持できるが、初期版で利用できるのは1台あたり合計3件までとし、設定中のまどは同時に1件だけにする。既存の超過分は隠したり削除したりしない。

一覧は「接続済みのまど」と「設定中のまど」を分け、各区分を作成日時の古い順で固定する。同期、更新、まどを開く操作では行を並べ替えない。内部のactive IDは資格情報を選ぶためだけに使い、`現在のまど`などの状態として利用者へ見せない。空状態と追加時は同じ「新しいまどを作る」「招待されたまどに参加」「このiPhoneを以前のまどに追加」から先に選び、同じ選択を次画面で繰り返さない。作成は名前入力へ直行し、設定中のまどには仮の名前と「名前を決めて設定を続ける」を表示する。未接続の名前はサーバーへ送らず端末内へ保存し、招待作成後に同じ名前を暗号化した同期情報へ引き継ぐ。接続後の設定入口は「名前・相手・iPhone」とし、名前を変更できる作成端末ではそのことを副文で示す。

通知を受け取れる設定と資格を持つ接続済みの各まどは、新着写真とハートのalertを受け取る。通知本文にはまど名・相手名・写真を出さない。通知が非選択中のまどに届いただけでは、そのまどをbackground同期せず、いま開いているまどやWidgetを変更しない。

通知をタップしたときは、通知対象と端末内で一意に一致するまどへ切り替え、そのまどを認証済み同期してから対象写真を開く。route用のopaqueなまど・写真IDは端末内の照合だけに使い、画面や通常の診断へ表示しない。解決できない通知から現在のまどや別の写真を推測して開かない。対象IDを持たない旧通知だけは、選択中のまどで「届いた写真」または「自分が届けた写真」の区分を開く。旧v2へ戻した場合は、選択中のまど1件だけへ通知する従来契約へ安全に縮退し、非選択中のまどを暗黙に同期しない。

## いまの一枚を届ける

主な送信開始地点は、名前付きのまど内にある「写真を届ける」とする。準備手順ではなく利用者の目的を短く表示し、紙飛行機、十分な高さ、塗りのある独立した主ボタンで履歴や案内と区別する。この操作は「届いた／届けた」の履歴切替より上に固定し、どちらの履歴を見ていても探し直さず送信を始められるようにする。Appleの写真選択画面で1枚を選び、写真・届け先・縮小と位置情報除去を確認してから送る。アプリ内カメラや独立した「送る」タブは作らない。標準カメラ／写真アプリの共有シートは、写真を見ている場所から送れる補助経路として残す。両経路とも同じサイズ上限、metadata除去、短期admission、Host appでの再検証と安全確認を通り、別の送信権限を作らない。

```
名前付きのまど → 写真を届ける → Apple写真選択 → 送信確認
標準カメラ／写真アプリ → 共有 → ねこのまど → 送信確認
```

届けたいまどが1つなら、Share Extensionはその届け先を表示する。複数ある場合は、Host appが発行した期限内の候補だけをShare Extension内に並べ、利用者が1つを明示選択する。新規まどには重複しない既定名を付け、名前変更でも別のまどと同じ名前は保存しない。移行済みデータなどに同名が残る場合は番号だけで区別して送らせず、名前を変更するまでその候補を無効にする。未選択、削除済み、期限切れ、曖昧な旧形式では送信準備を止め、別のまどへ自動で切り替えない。Share Extensionは選んだ写真を端末内へ一時保存するだけで、Host appが選択ID、まど、同意、鍵、写真を再確認してから暗号化・送信する。非選択中のまどへ準備した場合は、完了画面でアプリの「まど」から対象名を開くよう案内する。アプリ内の「まど」には、初回の送り方案内、最後に届けた写真、最近届いた写真、失敗した送信の再試行を置く。

まどを表示対象に選んだウィジェットでは、写真上にまど名だけを控えめに示す。「写真」はこのiPhoneの写真だけを扱い、共有写真を混ぜない。届いた写真は受信から最長90日でWidgetから外し、別のまどやこのiPhoneの写真へ置き換えない。期限内はそのまどの「届いた写真」から見返せ、取り込んだ写真だけが通常の思い出へ加わる。

「自分が届けた写真」は操作ログではなく、写真と配信状態を見返す一覧にする。最新3件から始め、「さらに見る」で20件ずつ開く。一覧は正方形の写真を主役にした2列グリッドとし、アクセシビリティ用の文字サイズでは1列にする。サーバー受付済み／相手端末への到着、日時、ハートは写真上の控えめなバッジで示し、文字中心の横長ステータス行にしない。画像が保持されていない古い送信分は「送信履歴のみ・画像はありません」と明示し、送信失敗と誤解させる「プレビューなし」は使わない。日常画面では「到着」が相手の閲覧を示さないことだけを見出し下で説明する。プレビューが送信したiPhoneだけに最長30日残り、別のiPhoneや再インストール後には表示されないことは「安全とプライバシー」に置く。進行中と失敗だけを写真一覧より先に置き、詳細な結果の消去は「整理」に残す。プレビューは元画像を再描画してmetadataを除いたJPEGで、このiPhoneの送信履歴にだけ保持し、relayへ送らない。1枚64KiB以下、送信結果と同じく最終更新から30日・最大200件で削除する。

## アルバム

説明でき、見返す価値がある分類だけを出す。

- 猫たちと過ごした時間
- 明示した写真だけで作る猫ごとの成長
- 年ごと／年齢ごと
- 人といっしょ
- 猫たち
- どアップ
- すべての猫写真

姿勢を縦横比だけで断定するアルバムは出さない。「猫たちと過ごした時間」は猫を見分けず、検出した猫写真から撮影年ごとに1枚を選ぶため、同じ猫の生物学的な成長とは表現しない。最初と現在は別々の代表写真として選ばず、人物の有無、猫の頭数、猫の位置・大きさ・構図が近い一組を端末内で選ぶ。間の年もその一組との近さを優先し、時間のつながりが見える一本として並べる。これは同じ猫や場所の断定には使わない。利用者が思い出に残した写真、写真アプリのお気に入りは自動的なつながりより優先する。詳細画面は鑑賞を初期状態とし、最古から最新まで一方向の時系列に並べる。各写真は年・時期ラベルだけで単独理解できるようにし、「最初のころ」「いま」「その間」の相対見出しは使わない。最初と最新を大きく、中間を2列で配置し、同じ写真は重複表示しない。年と重複する正確な撮影日は一覧に出さず写真詳細に置く。変更操作は各写真へ常設せず、冒頭の「選び直す」から時期を選ぶ。利用者が選び直した写真は次回以降も固定するが、端末内の表示指定だけを保存し、元写真を変更しない。自動選択の範囲と個体識別をしていないことは「このまとめについて」に置き、鑑賞中へ注意書きを常設しない。猫プロフィールは任意の猫別ページとし、新しい主タブにはしない。代表写真と名前、猫別の写真、直接候補一覧へ進む「写真を選ぶ」、通常Photosアルバム連携、誕生日・迎えた日、管理操作を整理して置く。代表写真は固定でき、誕生日と迎えた日は同時に保存できる。世帯全体・個体別のどちらも、比較できる2時期以上がある場合だけ表示する。

「この子の写真」は、アプリ内で手動確認した写真と、その猫へ利用者が明示的につないだ通常の写真アルバムの和集合とする。AIが個体を推測した写真は入れない。同じ写真を複数の猫へ入れられるため、2匹いっしょの写真を片方だけへ強制しない。

5枚の正解例を使った個体識別実験も、実機の評価30枚で必要な判定率に届かなかったため製品化しない。個体ページや個体別成長へ自動所属を追加せず、世帯全体の成長は個体識別なしで成立させる。

通常の写真アルバム連携は、猫のプロフィールページ内の専用項目から行う。アプリは連携元を読むだけで、写真アプリのアルバムや写真を移動・削除しない。連携を外してもアプリ内で手動確認した写真は残す。これは設定の全体共通の「写真の対象」や、アプリが作る写真アプリの「うちの子」アルバムとは別であり、互いの選択肢や内容を混ぜない。

猫の追加は名前と任意の代表写真で完了し、その猫のページへ進む。既存写真を勝手に割り当てず、複数猫の写る写真は両方へ指定できる。写真指定・名前・日付などは保存成功を待って画面を閉じ、失敗時は選択を保持する。プロフィールと猫別指定はこのiPhone内だけで管理し、機種変更・再インストール時の復元は未提供。2026-09-05の実装範囲と自動識別を延期した根拠は[多頭管理の判断](多頭管理-現行版と自動識別の判断.md)を参照。

## 思い出

「思い出」は、何を見返すかを先に選べるよう、上部の切替で次の2区分から1つだけを表示する。

- **ふりかえり**：直近の「月の便り」を代表写真付きで最上段へ置き、過去の便りと季節のムービーを別区画に分ける。自動生成物を「つくったもの」と呼ばない
- **残した写真**：`思い出に残す`で選んだ写真を、選んだ日時の新しい順に全件表示する。一枚の詳細からJPEGを書き出せる

上部の切替は「ふりかえり｜残した写真」の順に置き、初期区分は「ふりかえり」とする。新着があっても表示中の区分を自動で変えない。「残した写真」は6枚だけのプレビューや「すべて見る」を挟まず、全件を直接グリッド表示する。空の場合は説明文を重ねず、「写真から選ぶ」で最上位の「写真」へ移動する。「かたちにする」は残した写真の文脈操作とし、開いた先で1〜30枚を明示的に選んでPDFを書き出す。「ふりかえり」は直近の月の便り、その直下の「これまでの便り」、季節のムービーを、固有アイコン、短い説明、区切り線で常に同じ順に表示する。写真を分類して探す役割は最上位の「写真」の自動アルバムへ集約し、ここへ重複させない。過去の便りがない場合は区画自体を増やさず、直近の便りだけを見せる。番号は手順に誤認されるため使わない。月の便りがない場合も同じ位置に短い準備状態を残し、季節のムービーがない場合も区画を消さず簡潔な空表示を置く。古い月の便りと新しい季節のムービーを同じ「最新」だと誤認させない。未提供の商品は、詳細や購入へ進めるようになるまで主画面へカードとして置かない。

`つくったもの`は、利用者が明示的に作成・注文し、アプリ内で再訪できる完成物が実装された後の名称として予約する。端末内で自動生成された便りや季節のムービーには使わない。

「写真を書き出す」は現在「思い出」に残っている一枚だけを対象とする。長辺2,048px以下のJPEGを端末内で準備し、位置情報、撮影日時、元のファイル名などの元情報を除いてiOS共有シートへ画像データとして渡す。アプリ自身が管理する書き出し用の一時ファイルは作らず、元写真と「思い出」の状態も変更しない。iOSまたは利用者が選んだ共有先がコピーを作成・保持する場合があり、その共有先のポリシーが適用される。これは非公開なまどへの送信や物理プリントの注文ではない。

31枚目以降も消さず、最初の30枚だけを固定的に扱わない。総枚数を未読通知のような赤いタブバッジで表示しない。物理的な本を注文できない間は「一枚を書き出す」と「選んだ写真をPDFとして共有する」だけを事実どおりに案内する。

招待相手から届いた写真は、まずその非公開なまどの「届いた写真」と、そのまどを選んだWidgetに置く。操作しなければ最長90日・500枚・256MiBまでの一時的な受信一覧であり、Widgetも同じ90日の境界で表示を終える。日常画面では最長90日と「取り込んで残す」だけを短く伝え、枚数・容量などの詳細は「安全とプライバシー」に置く。まど内に保存済みフィルターや第二の保管一覧は作らない。「取り込んで残す」を選んだときだけ、位置情報を除いた写真を写真アプリへ一度コピーし、通常の思い出・PDF・将来の商品と同じ個人コレクションへ加える。iCloud写真の同期は利用者とAppleの設定に従う。

「思い出に残す」と「取り込んで残す」は輪郭のブックマーク、保存済みは塗りつぶしのブックマークで統一するが、届いた写真では確認画面とボタン名で写真アプリへのコピーを明示する。保存済みの印そのものを再タップして解除させず、「思い出から外す」はアプリ内メニューと確認画面から行う。これは個人コレクションから外す操作であり、写真アプリの写真を削除しない。共有解除、ブロック、アプリ削除でも、明示的に取り込んだ写真は写真アプリに残る。相手へは通知しない。相手への反応は別の「ハートを送る」だけにし、ハートから保存を発生させない。

## 設定と診断

通常設定は「写真と表示」「まど」「プライバシーとサポート」「アプリ」に分ける。写真アクセス、対象範囲、ねこのプロフィール、写真の整理、ウィジェット案内、プライバシー、ヘルプだけを置く。暗号化や端末内処理の説明を設定項目のような静的行にはせず、権限・送信確認・プライバシー詳細など必要な場面へ置く。誤って表示候補から外した写真を戻す操作は「写真の整理」に残す。

利用者が写真を見つけ直す「最初から再スキャン」だけは写真設定に置く。精度標本、2048px再試行、JSON、ログ、検出閾値は「診断情報」へ隔離する。bbox、FeaturePrint、deferred、manifestなどの内部語を通常画面へ出さない。

## 無料・Plus・物販の案内

無料、Plus、物販の機能境界と販売開始条件は[ADR-024](ADR-024-無料体験とPlusと物販.md)を正本とする。課金専用タブや常設バナーを作らず、実写真を見つけた後に、次のPlus対象操作を利用者が選んだ場合だけ短い案内を出す。

- 2つ目のまどを自分で作る
- 2匹目のねこのプロフィールを追加する
- 月・一年のムービー、過去作品、1080p、素材編集を使う
- Plus対象の引き継ぎを設定する

招待されたまどへの参加、写真の受信、ハート、通知、思い出に残す、取り込んで残す、通報、ブロック、基本Widget、基本JPEG・PDFでは課金を求めない。Plus案内は、利用者の実写真件数や登録した猫名を端末内で安全に使える場合だけ個人化し、価値を3項目以内に絞る。未実装の価値、復元できない写真、無期限保管を約束しない。

物販は「思い出＞残した写真＞かたちにする」で商品、写真、注文用複製を確認した後、Webのプレビュー・配送先・決済へ渡す。iOS共有シートのPDF共有を注文完了のように見せない。注文機能が完成するまで販売カードや価格を主画面へ置かず、初回注文後だけ「つくったもの」から注文済みの完成物へ再訪できるようにする。

## 成功の判定

主な成功はスキャン枚数やアプリDAUではなく、ウィジェット設置と実写真表示で測る。

- 写真許可から最初の候補までの時間
- 24時間以内のウィジェット設置率
- 最初の非placeholder表示までの時間
- 7日後にウィジェットが残る割合
- ウィジェットから写真を開き、思い出に残した異なる写真数
- 誤写真の除外数／100表示
- 「かたちにする」の利用率とPDF共有完了率
- 一枚の「写真を書き出す」の開始率と共有シート表示完了率
