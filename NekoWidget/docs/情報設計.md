# 情報設計

最終更新：2026-08-24

この文書は、機能追加時に画面の置き場所と言葉を決める基準である。技術の構成ではなく、利用者の目的で分類する。

## 製品の中心

> 埋もれていた猫が毎日「まど」に戻り、残したい一枚へ肉球を押せる。

スキャン、分類、写真アプリのアルバム、共有サーバーは、この体験を支える手段であり最上位の目的ではない。

## 最上位の画面

下部タブは常に次の3つとする。

| タブ | 目的 |
|---|---|
| **まど** | いま表示している一枚を見る |
| **思い出** | 過去の猫写真を見返す |
| **これ好き** | 自分で残した写真を集め、必要な分だけまとめる |

設定は「まど」右上の歯車から開く。共有が実装されても、まずは「まど」の中へ入れ、下部タブを条件付きで増減させない。

## 用語

| 用語 | 意味 |
|---|---|
| **まど** | 写真が巡回する空間。ひとりでも招待相手とでも成立する |
| **名前付きの非公開なまど** | 利用者が名前を付け、信頼できる相手1人と写真を届け合う招待制のまど |
| **ウィジェット** | 1つのまどをホーム画面から見る窓枠 |
| **いまの一枚** | 共有シートから明示的に届ける写真 |
| **思い出の一枚** | 過去写真から巡回する写真 |
| **このiPhoneの猫写真** | このiPhoneから読める写真を端末内で確認した、共有ではないWidget写真源 |
| **ねこのプロフィール** | 名前、日付、利用者が明示した写真を猫ごとに管理する場所 |
| **写真アプリの「うちの子」アルバム** | 既存互換のため維持するPhotos出力アルバムの固有名 |

「共有ボックス」は保存・バックアップを連想させるため使わない。`うちの子`は単独では対象が曖昧なため、既存Photosアルバムの固有名を明記するとき以外は使わない。1ウィジェットは1つのまどだけを表示し、異なるまどを混ぜない。

## まど

表示中の写真を最上位に置き、主要操作は肉球と写真詳細だけにする。

- 自分の過去写真：`思い出から・2022年`
- いま届いた写真：`いま届いた・しずくのまど`
- まどの新着優先期間後：`しずくのまどに届いた一枚`
- 相手から届いた過去写真：`思い出が届いた・2022年`

ウィジェット未設置時は、写真の近くに「ホーム画面にまどを置く」を出す。スキャンや権限に問題があるときだけ、短い修復導線を出す。正常時の処理件数、統計、写真アプリ連携、診断は常設しない。

初期版は名前付きの非公開なまど1つ・2人だけなので、まどの切り替えは表示しない。複数まどは、資格情報、履歴、Widget cache、Deep Linkをspace単位へ分離した後で追加する。

## いまの一枚を届ける

送信開始地点は標準カメラまたは写真アプリの共有シートとし、アプリ内カメラや「送る」タブを作らない。

```
標準カメラ → 写真の共有 → ねこのまど → 送信確認 → 名前付きの非公開なまど
```

初期版のまどが1つなら届け先を選ばせない。複数のまどを持てる段階になった場合だけ選択する。アプリ内の「まど」には、初回の送り方案内、最後に届けた写真、最近届いた写真、失敗した送信の再試行を置く。

新着は2〜4時間または肉球の反応まで優先し、出所を明記する。優先期間後はまどの履歴へ移し、通常の思い出巡回へ戻す。

## 思い出

説明でき、見返す価値がある分類だけを出す。

- この家の猫たちの成長
- 明示した写真だけで作る猫ごとの成長
- 年ごと／年齢ごと
- 人といっしょ
- 猫たち
- どアップ
- すべての猫写真

姿勢を縦横比だけで断定するアルバムは出さない。「この家の猫たちの成長」は猫を見分けず、検出した猫写真から撮影年ごとに1枚を選ぶ。猫プロフィールは全写真を自動判定したようなフィルターにせず、名前、日付、この子だと明示した写真、成長、写真追加を持つ猫ごとのページとして扱う。世帯全体・個体別のどちらも、比較できる2時期以上がある場合だけ成長アルバムとして出す。

「この子の写真」は、アプリ内で手動確認した写真と、その猫へ利用者が明示的につないだ通常の写真アルバムの和集合とする。AIが個体を推測した写真は入れない。同じ写真を複数の猫へ入れられるため、2匹いっしょの写真を片方だけへ強制しない。

5枚の正解例を使った個体識別実験も、実機の評価30枚で必要な判定率に届かなかったため製品化しない。個体ページや個体別成長へ自動所属を追加せず、世帯全体の成長は個体識別なしで成立させる。

通常の写真アルバム連携は、ねこのプロフィール内の「写真を追加」から行う。アプリは連携元を読むだけで、写真アプリのアルバムや写真を移動・削除しない。連携を外してもアプリ内で手動確認した写真は残す。これは設定の全体共通の「写真の対象」や、アプリが作る写真アプリの「うちの子」アルバムとは別であり、互いの選択肢や内容を混ぜない。

## これ好き

肉球を押した写真を上限なく残す場所とする。PDFは保存形式の一つであり、画面の主目的にはしない。

- 肉球を押した日時の新しい順に並ぶ、一続きの写真グリッド
- 1〜30枚を明示的に選ぶ「まとめる」操作
- 選んだ写真だけのPDF共有
- 将来の物理的な本やプリント

31枚目以降も消さず、最初の30枚だけを固定的に扱わない。総枚数を未読通知のような赤いタブバッジで表示しない。物理的な本を注文できない間は「選んだ写真をPDFとして共有できます」と事実どおりに案内する。

招待相手から届いた写真は、既定ではその非公開なまどの履歴に置く。現行v1の「思い出に残す」は恒久保存や個人の「これ好き」への取り込みではなく、このiPhoneのまど内で履歴を優先して残す共有範囲の印とする。写真本体を複製せず、写真アプリやiCloudへ追加しない。印を付けても端末内履歴の最大90日・500枚・256MBという上限を延長せず、共有解除・ブロック・再インストールでは写真と印を一緒に削除する。

受信写真を個人の「これ好き」／PDF／将来の本へ恒久的に取り込む機能は、共有履歴から独立した保存先、削除、容量、同意を設計してから追加する。現行の「思い出に残す」をその機能が実装済みであるかのように案内しない。

## 設定と診断

通常設定には写真アクセス、対象範囲、ねこのプロフィール、写真の整理、ウィジェット案内、プライバシー、ヘルプだけを置く。誤って表示候補から外した写真を戻す操作は「写真の整理」に残す。

再スキャン、精度標本、2048px再試行、JSON、ログ、検出閾値は「詳細・診断」へ隔離する。bbox、FeaturePrint、deferred、manifestなどの内部語を通常画面へ出さない。

## 将来機能の置き場所

| 機能 | 置き場所 |
|---|---|
| まどの作成・招待 | まどの空状態／まど上部 |
| 最初の20枚の確認 | まど作成フロー |
| 過去写真の毎日1枚 | まどごとの設定。既定OFF |
| いまの一枚の送信 | Share Extension |
| 送受信履歴 | まどの履歴 |
| 通報・ブロック・退出 | 写真メニュー／メンバー管理 |
| E2E・保持期間 | セットアップの短い説明＋まど設定の詳細 |
| 2つ目以降のまど・課金 | 新しいまどを作る瞬間 |
| 成長・プロフィール | 思い出 |
| PDF・本 | これ好き |
| 開発検証 | 設定＞詳細・診断 |

## 成功の判定

主な成功はスキャン枚数やアプリDAUではなく、ウィジェット設置と実写真表示で測る。

- 写真許可から最初の候補までの時間
- 24時間以内のウィジェット設置率
- 最初の非placeholder表示までの時間
- 7日後にウィジェットが残る割合
- ウィジェットから写真を開き、肉球を押した異なる写真数
- 誤写真の除外数／100表示
- 「まとめる」の利用率とPDF共有完了率
