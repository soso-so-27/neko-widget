# ADR-023：季節の小さな映画

日付: 2026-08-28
状態: 仕上げ実装・候補CI確認待ち
関連: [ADR-019](ADR-019-しおりと長期保管.md)、[情報設計](情報設計.md)

## 決定

「小さな便り」とは別に、完了した暦四半期の猫写真、動画、Live Photoから、端末内だけで「この季節の小さな映画」を組み立てる。月の便りは5〜7枚を自分の速さで読む体験、季節の映画は3か月の時間の流れを15〜22秒ほどで感じる体験とし、片方をもう片方の再生版にしない。

映画は利用者が編集を始めなくても完成した状態で「今日」に現れる。写真だけの期間も対象にし、実動画またはLive Photoがあれば期間全体のバランスを崩さない範囲で自然に混ぜる。ただし静止画を無理にpan・zoomして動いているように装わず、短いcutまたはfadeでつなぐ。素材条件を満たさない場合は既存の月の便りだけを見せる。

写真だけで条件を満たした時点で、端末内レシピをドラフトとして保存してカードを表示する。動画の端末内解析や、後から端末内で利用可能になった素材を含む走査はその後も続け、同じ四半期のレシピがまだドラフトで、走査開始時に読んだ版と保存中の版が一致し、思い出指定、月・撮影日の分散、動く場面、場面数の順で客観的に良くなる場合だけ、新しい選定結果へ置き換える。同等の選定結果や、一時的に素材を読めなかった走査で作品を入れ替えない。古い走査結果が新しいレシピを上書きすることもない。

カードを開いただけでは固定しない。実際に表示できた2場面を最後まで見たとき、1場面を作品から外したとき、または「動画を保存・共有」を開始したときのうち最初の操作でレシピを固定する。以後の自動走査は上書きしない。固定保存に一時的に失敗した場合も、そのプロセス中は自動更新を止める。旧schemaには視聴・書き出し履歴がないため、既存作品を未視聴と推測せず、移行時にすべて固定して見た目を維持する。

## 採用する体験原則

他製品から借りるのは派手な演出ではなく、次の仕組みである。

- 完成品を自動で用意し、最初に編集作業を求めない
- 連写や短時間の似た場面をまとめ、同じ構図を続けない
- 期間の一部へ偏らず、撮影日と月を分散する
- アプリで「思い出に残す」と選んだ素材を最優先し、写真アプリの「お気に入り」はその次の補助信号として扱う。ただし、それだけで全体を占めさせない
- 見る前に確認画面や二つ目の再生ボタンを挟まない
- 編集可能範囲は、元写真へ影響しない1場面の除外と取り消しに絞る

猫について「喜んでいる」「寂しそう」など、画像から確かめられない感情や物語を自動で付けない。「ふたり」「家族」も作品名へ固定せず、1人、多頭、友人との利用を狭めない。

### 調査根拠

- みてねは対象期間の写真・動画を、人物、公開範囲、コメント等で評価し、期間全体から偏らないよう自動選定している。動画は一部を切り出す。[みてねヘルプ：生成方法](https://help.family-album.com/hc/ja/articles/360038852633-1%E7%A7%92%E5%8B%95%E7%94%BB%E3%81%AF%E3%81%A9%E3%81%AE%E3%82%88%E3%81%86%E3%81%AB%E3%81%97%E3%81%A6%E4%BD%9C%E3%82%89%E3%82%8C%E3%82%8B%E3%81%AE%E3%81%A7%E3%81%99%E3%81%8B)
- 配信条件は対象写真・動画10点以上で、連写など撮影間隔の近い素材、極端に短い動画、破損素材等を除く。実動画だけを必須にはしていない。[みてねヘルプ：生成条件](https://help.family-album.com/hc/ja/articles/360038853413-1%E7%A7%92%E5%8B%95%E7%94%BB%E3%81%8C%E9%85%8D%E4%BF%A1%E3%81%95%E3%82%8C%E3%81%AA%E3%81%84%E3%81%AE%E3%81%A7%E3%81%99%E3%81%8C)
- 素材単体の評価だけでなく、撮影日時の分散と写真・動画比率を作品全体で整える点を採用する。[MIXI：みてねの生成技術](https://mixi.co.jp/sustainability/materiality/innovation/mitene/)
- 再生は利用者のタップから開始し、停止可能にし、元の縦横比を守る。[Apple Human Interface Guidelines：Playing video](https://developer.apple.com/design/human-interface-guidelines/playing-video)

## 生成条件

対象は直近の完了した暦四半期とし、次をすべて満たす場合だけ作品を出す。

- 近い場面をまとめた後に、異なる候補が10場面以上
- 6つ以上の撮影日に分散
- 四半期内の2か月以上に分散
- 完成作品は8〜12場面
- 実動画またはLive Photoがある場合は、一部の時期へ偏らない範囲で優先し、写真との比率を作品全体で整える
- 動く場面が多い場合は、思い出指定と6撮影日・2か月の分散を守りながら場面数を減らし、鑑賞部分を22秒以内に収める

動画は端末内で取得できる代表フレームをVisionで確認し、猫を検出できたものだけを候補にする。写真、動画、解析結果をServerへ送らない。iCloudから自動ダウンロードして条件を水増しせず、取得できない素材はその回の候補から外す。生成失敗や素材不足で、月の便り、思い出、過去作品を削除しない。

候補の `isMemory` は、写真・Live Photo・動画のいずれでもアプリ内の「思い出」だけを意味する。写真アプリの「お気に入り」は別の補助信号として保持し、`isMemory` に読み替えない。現行UIでは通常動画を「思い出」にする操作がないため、動画の `isMemory` を推測で立てず、写真アプリのお気に入りだけを補助信号として使う。

準備済み判定には、対象写真の思い出・お気に入り状態と、対象動画の識別子・撮影日・編集日・長さ・お気に入り状態を含める。動画のフレーム解析はこの判定のために重複実行しない。network無効の取得で動画が端末内にないと分かった場合だけ、同じ前面滞在中にループせず、次にアプリが前面へ来たときに1回再試行する。これにより、あとから端末へ届いた素材を検討できる一方、取得不能素材で連続再解析しない。

写真の対象アルバムを利用者が選んでいる場合、動画も同じアルバム内だけを対象にする。選択済みアルバムを確認できないときは、全ライブラリへ自動で広げず作品を隠す。PhotoKitの動画・Live Photo取得は5秒で打ち切り、応答しない素材が作品全体を止めないようにする。

## 表示と操作

- 「今日」には完成した作品だけを、代表画像、「季節の作品」という固定分類、期間を含む作品名、場面数、長さ、控えめな再生記号を持つ1枚のカードとして置く。視聴済み状態を保存しない初期版では、時間が経っても残る「できました」は表示しない。
- カードの下には `次は10月ごろ、7月–9月を振り返ります` のように、次の作品時期と対象期間だけを1行で置く。回数や生成閾値を通常画面へ出さない。
- 情報ボタンを開いた場合だけ、「このiPhoneで利用できる猫の写真と動画」「似た写真をまとめる」「撮影日の分散」「思い出と動く場面を優先」「写真が少ない季節は作らない」「端末外へ送らない」を短い行で説明する。写真アプリの保管機能を置き換えるのではなく、端末内の猫専用編集として案内する。
- カード全体のタップを再生意思とし、タップ後すぐ冒頭から再生する。
- 最初の画像が実際に表示できてからBGMと尺の計測を始め、再生中は次の2場面だけを端末内で先読みする。読み込めない1場面で作品全体を止めない。
- 再生画面は黒を基調にし、原本の縦横比を守る。猫を切る強いcrop、ランダムなzoom、回転、派手なtransitionは使わない。
- 利用者は再生・一時停止・終了をいつでも操作できる。背景へ移ったら一時停止する。
- 通常は短いcut、月が変わる場所だけ0.2秒ほどのfadeにする。月表示は年を繰り返さず「5月」のように画面左下へ約0.8秒だけ添える。「視差効果を減らす」が有効な場合は即時cutにする。
- 権利を本アプリが持つ控えめなBGMを1曲だけ使う。利用者がカードを開いて音をONにしている明示的な再生なので `.playback` とし、消音モード中も聞こえるようにする。音のON/OFFを記憶し、初期値はON、アプリ内とMP4の音量はともに55%とする。元動画やLive Photoの音は混ぜず、音源を読めない場合も無音で再生を続ける。
- 「…」から「この作品から外す」を選べる。元の写真・動画、思い出、猫判定には影響せず、直後に元へ戻せる。8場面未満にはできない。
- 最初の2場面を実際に見終えるまでは自動生成ドラフトである。誤ってカードを開いただけでは固定せず、2場面の読み込みに成功して再生時間が経過した時点で固定する。読み込めず飛ばした場面は数えない。
- 最後は「この季節も、ここまで」とし、見返しと、明示的な「動画を保存・共有」を置く。送信、購入、保存を自動では行わない。
- 書き出すMP4にも、鑑賞時と同じ最初の作品名・期間、月が変わる箇所の約0.8秒の月表示、最後の「この季節も、ここまで」を含める。BGMは書き出し全体の終了時刻までつなぎ、アプリ内と同じ音量から最後の1秒で消えるようにする。

初期版には、BGM選択、filter、字幕、手動の並べ替え、切り出し位置、表示時間、相手への送信、商品購入を含めない。端末内の鑑賞体験が成立した後に、必要性を実利用で判断する。

## 見返し・保存・プライバシー境界

- 完成した作品は「思い出」の「季節の作品」から見返せる。ただし保存するのは、四半期、PhotoKit識別子、再生位置、除外した場面、ドラフトを固定した日時と理由という小さな再生レシピだけである。
- レシピはアプリ専用の `Application Support/SeasonalMovies/v1/catalog.json` に完全ファイル保護・バックアップ除外で置く。写真原本、サムネイル、完成MP4は履歴として複製しない。Widget、共有Extension、App Groupへレシピを渡さない。
- 読み込み失敗、未対応schema、破損を「履歴なし」とみなして上書きしない。自動再走査で、視聴・編集・書き出しにより固定した既存作品を作り直さない。視聴状態を持たなかったversion 1レコードは固定済みとしてversion 2へ遅延移行し、移行ファイルを書けない場合も読み込みと固定扱いを続ける。
- 「動画を保存・共有」を押した場合だけ、ローカルにある素材から720×1280・24fps・H.264をアプリ専用一時領域で作る。位置情報、元ファイル名、撮影日時、元動画の音声は持ち越さない。音がONなら本アプリ所有のBGMだけを収録する。
- 通常の動画素材は動きを保って書き出す。初期版のLive Photoは、鑑賞時は動きを再生するが、MP4書き出しでは静止画として扱う。Live Photoの動画成分取得は素材構成と失敗時処理が大きく増えるため、実利用で必要性を確認してから別途扱う。
- 完成MP4は標準共有シートへ渡す。共有完了・キャンセル・失敗で一時ディレクトリを削除し、プロセス再起動時にも残骸を削除する。利用者が写真アプリ、Files、他アプリへ保存した複製は、その保存先の管理となる。
- 自動生成・再生・書き出しでiCloud素材を自動ダウンロードしない。端末にない素材がある場合は、元データを変更せず書き出しを中止する。

## 月の便り・思い出・将来の出口との関係

| 場所 | 役割 |
|---|---|
| 月の小さな便り | 完了した1か月を静止画で、自分の速さで読む |
| 季節の小さな映画 | 完了した3か月を短く見て、端末内の季節作品として見返す |
| 思い出 | 利用者が明示的に残した写真を蓄積する |
| かたちにする／つくったもの | 将来、完成した作品や物理商品を見返す出口 |

映画の再生や自動選定だけで、素材を「思い出」へ追加しない。作品を将来「つくったもの」へ保存する場合も、元の写真・動画の保管契約とは分けて案内する。
