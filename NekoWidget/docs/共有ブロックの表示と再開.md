# 共有ブロックの表示と再開

2026-09-08。利用者から「ブロックしてまどを解除」はブロックするのか、取り消すのか分からないという指摘があり、表示の修正と誤操作からの再開手段を実装した。Build 133には含まれない。以下は配布前の候補仕様。

## 利用者の操作

- 共有画面の確認ボタンは「ブロックする」。その相手との写真共有を終了し、そのまどの受信写真と古い共有鍵をこのiPhoneから削除する。
- 設定の「ブロックした共有」で、このiPhoneの新しい版で行ったブロックを一覧にする。まど名と日付を表示し、「ブロックを解除」から確認して取り消せる。
- 解除後は「ブロック解除済み・共有は停止中」。送受信、送信待ち、通知を自動再開しない。削除した写真は復元しない。
- 「新しいまどで共有を始める」を別途押すと、空のまどか新しいまどで既存の招待・双方確認へ進む。以前の共有鍵、相手の承認、同意状態を引き継がない。既存のまど数・設定中のまどの制限を守る。
- 通信結果が不明な場合は成功表示を出さず、同じ解除操作を再試行できる情報を残す。

## 保存と通信の範囲

ブロック対象は既存のまど内の参加者IDであり、アカウント全体・人物全体の永続ブロックではない。

ブロック送信前に32バイトのランダムな取り消し専用トークンと固定リクエストIDを保存する。アプリ本体の専用Keychainサービスを使い、端末のロック解除中のみ取得できる。端末間同期・バックアップ復元・Share Extensionへの共有を行わない。通常の共有終了では残し、インストール全体の共有削除時に消去する。解除確定後はトークンを消去し、まど名・日付・解除済み状態を端末内に残す。

既存の署名付きblock APIに任意の `withdrawalId` と `withdrawalTokenHash` を追加。サーバーは平文トークンを保存せず、既存ブロックと取り消し権限を同じトランザクションで作成する。新しい `POST /v2/blocks/{withdrawalId}/withdraw` はトークンの一致するブロックだけを取り消す。処理済み応答を再取得でき、失効済みの参加者・端末・配送・鍵世代・通知を戻さない。写真配信OFFでも取り消し可能。

ブロック成功応答の喪失やローカル保存失敗があった場合、解除確定後に旧まどの削除を完了させてから端末内の解除を確定する。インストール、まどID、参加者、保存状態を照合し、選択中の別まどや同じ枠の新しい共有を削除しない。削除途中の失敗は既存の復旧処理に委ね、再試行用のトークンを残す。

## 制限

- Build 133以前や別のiPhoneで行ったブロック、再インストールで失った権限は後から復元しない。画面にも明記する。
- サーバー上の旧まどが失効・削除された場合は取り消しを認証できず、成功したとは表示しない。
- ブロック送信自体がサーバーに届かなかった場合の記録は「結果未確認」のまま保持する。サーバーで取り消しを確認できない限り解除済みにはしない。
- 本機能だけでは共有を再開しない。新しい招待を渡し、双方が確認した後に初めて新しい共有となる。

## 検証と配布順

- サーバー：型チェック、取り消し・既存ブロックの対象テスト6件が成功。別トークン、入力不正、同時再試行、登録競合のロールバック、旧配送の非復活、失効・削除後の拒否を含む。
- アプリ：既存のruntime self-testに `moment-block-withdrawal-lifecycle` を追加。Keychainの再利用、通常の共有終了後の保持、応答喪失後の旧まど削除、別まどと置き換え後の共有の保護、トークン削除、新規招待前の未接続状態、インストール全体の削除を確認する。実行結果は候補CIで確定する。
- 独立レビューの「応答喪失後にローカル削除を飛ばせる」指摘を修正し、修正箇所の再確認で追加指摘なし。
- 配布前にサーバーのmigration `0026_moment_block_withdrawals.sql` と対応Workerを先に適用する。旧アプリのblockリクエストは引き続き受け付ける。新アプリを旧Workerへ先に配布しない。
- 現在の公開Support／CommunityはBuild 133の操作案内を維持。新しい版の配布時に「ブロックする」「設定 → ブロックした共有 → ブロックを解除」へ揃える。公開ページの変更も別途配布に合わせる。
- 今回は候補の実装・CIまで。サーバー適用、TestFlight配布、外部招待、審査提出は実施しない。実機確認は次のまとめた配布後に、テスト用まど1つでブロック→解除→新しい招待を確認する。
