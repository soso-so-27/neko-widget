# 製品構造

作成：2026-08-21／現況更新：2026-08-26
**機能を足すか迷ったとき、まずここを見る。**

画面上の置き場所と言葉は **[情報設計.md](情報設計.md)** を正本とする。

現行のrelease candidateでは、名前付きの非公開なまどを複数持ち、各まどを2人で使い、本人確認済みのiPhoneを1人最大4台まで追加できる。Share ExtensionからHost appを経由する一枚送信、「届いた写真」「自分が届けた写真」、写真別の「ハートを送る」、恒久的な「思い出に残す」、思い出一枚のプライバシーに配慮したJPEG書き出し、共有Widget、通知を受け取れる接続済みの各まどへの汎用APNs alert経路まで実装している。非選択中のまどへの通知だけでは同期やWidget更新を行わず、利用者がタップしたときに対象まどへ切り替えて同期する。通報・ブロック・共有解除も実装している。一方、production moderation、APNs資格情報とruntimeの環境別設定、実APNs smokeを含む一般公開gateはreleaseごとに完了確認が必要である。物理的な本・プリントの注文、非選択中のまどのbackground同期、3人以上、一方向チャンネル、外部TestFlight、App Store公開は未実装または未完了である。

---

## 1. 製品はふたつの流れでできている

```
【過去の流れ】　発掘・蓄積・差別化
　既にある写真　→　ホームに出る　→　思い出に残す　→　溜まる　→　単写真JPEG／PDF／将来の本

【現在の流れ】　即時・相互性
　いま撮る　　　→　名前付きの非公開なまどへ届く　→　「届いた写真」に並ぶ　→　ハートが返る

【出口】
　思い出　　　　→　一枚をJPEGで書き出す・PDFにまとめる（実装済み）／本・プリント注文（未実装）
```

**どちらか一方では弱い。**

| | 強み | 弱み |
|---|---|---|
| 過去だけ | **誰もやっていない**（Appleは壁紙、Locketは今だけ） | **社会的機構がゼロ。** そして燃料（写真）が枯れる |
| 現在だけ | **実証済み**（Locket 80M DL）。課金理由が明確 | Locketと同じ土俵。過去の資産を使えない |
| **両方** | **Locketにない過去の深さ ＋ Locketが証明した即時性** | 配分の設計が必要 |

## 2. 燃料の枯渇問題（この議論での最大の発見）

```
見るのが楽になる　→　撮る動機が減る　→　カメラロールが増えない　→　井戸が枯れる
```

**製品が自分の燃料を消費して、補充しない。**

5年後に撮影が減っていたら、「忘れていた写真」は尽きる。同じ写真が回るだけになる。

**現在の流れは、この構造問題への答えでもある。** 撮る理由（家族に届く）を製品の中に作る。

### ただし「促し」と「報酬」は別物

| | 判定 |
|---|---|
| **「今日は撮っていません」と催促する** | **✕ 手間の押し付け** |
| **撮ったものが即座に家族の窓に届く** | **○ 動機のある行為** |

**促さない。報酬を置く。**

## 3. 各機能がどこに属するか

| 機能 | 流れ | 状態 |
|---|---|---|
| **ウィジェット** | **両方の表示面** | 実装済み |
| 思い出に残す | 過去 | 実装済み |
| 一枚を書き出す | 過去の出口 | 実装済み。現在「思い出」に残っている一枚だけを、長辺2,048px以下・位置情報等の元情報なしのJPEGとしてiOS共有シートへ渡す |
| **本・物販** | **過去の出口** | **未実装 ← 最大の穴** |
| 自動アルバム | 過去（並行する枝） | 実装済み。「すべての猫写真」と説明可能な分類だけを表示 |
| **共有** | **現在** | 複数まど、各まど2人、1人最大4台まで実装。一般公開運用は未完了 |
| 撮って届ける（共有シート） | 現在 | まどが1つならその届け先を表示し、複数ならShare Extension内で明示選択する。新規まどの既定名と以後の名前変更は重複させず、移行で残った同名候補は名前変更まで選択不可にする。選んだadmission IDをHost appが再検証し、安全確認を挟んで一枚だけ送る。別のまどへ自動fallbackしない |
| 新着・ハート通知 | 現在 | 通知を受け取れる接続済みの各まどへ対象付きalertを登録する。非選択中のまどは通知だけで同期・Widget更新せず、タップ時に対象まどへ切り替えて同期する。旧v2では選択中の1まどだけへ安全に縮退する。非選択中のbackground同期は後続。資格情報、runtime設定、実送信smokeはreleaseごとの運用gate |
| 猫の写真を撮るのを促す | — | **作らない**（促しは手間） |

### 流れのつながり

```
届ける　　　　　→　現行では自分の「思い出」へ自動では残さない
思い出に残す　　→　自分の「思い出」に入り、PDF・将来の本の対象になる
相手から届く　　→　「思い出に残す」で写真アプリへ取り込む／「ハートを送る」で相手へ反応する
```

「思い出に残す」は本の原稿候補を選ぶ自分向けの操作である。届いた写真では位置情報を除いた一枚を写真アプリへ取り込み、通常の思い出へ統合する。「ハートを送る」は写真を届けた相手への反応だけで、保存を伴わない。送受信やハートだけで写真を自動保存しない。

## 4. 出口は段階的に実装する

```
ウィジェット　→　思い出に残す　→　溜まる　→　単写真JPEG／PDF／将来の本
```

**思い出に残した先に、写真を見返し、用途に応じて持ち出す出口が必要。**

一枚をほかのアプリで使うJPEG書き出しと、複数枚をまとめるPDFは実装済みである。物理的な本・プリントの注文は、価格、決済、発送、解約時の扱いを含む別の商取引機能として未実装のまま分離する。

### 出口が見える状態は、今すぐ作れる

| 手 | コスト | 効果 |
|---|---|---|
| **「思い出」から写真を選んでPDFにまとめる** | **実装済み** | **枚数が増えても、必要な写真だけを出口へ送れる** |
| **「思い出」の一枚をJPEGで書き出す** | **実装済み** | **位置情報等の元情報を除き、利用者が選んだ共有先へ渡せる** |
| 単品プリント（1枚から作れる） | 未実装 | 注文、決済、製造、発送を伴う別の出口 |
| 年次まとめ | 1年待つ | — |

JPEGとPDFは無料の書き出しであり、物理注文や有料の長期保管とは混ぜない。共有シートで「プリント」を選べる場合も、それはiOSまたは選択先の機能であって、本アプリ内の注文機能が完成したことを意味しない。

## 5. 解決した衝突

| 衝突 | 解決 |
|---|---|
| 保存と反応の意味が混ざる | **自分のための「思い出に残す」と、相手への「ハートを送る」に分ける。** アイコンだけで意味を説明せず、同じ記号を流用しない |
| アプリ内カメラは標準カメラに勝てない（猫は待たない） | **アプリ内カメラを作らない。共有シート（Share Extension）で送る** |
| 写真アプリでキュレーションさせるのは核と矛盾 | **作らせない。既に持っている人に検知して提案するだけ** |
| 多頭で年齢アルバムが破綻する | **世帯の成長は猫を見分けず撮影年で1本。個体別は手動確認か明示的に連携した写真アルバムだけ** |

### 新しく確立した原則

> **設定を1回お願いするのはいい。キュレーションをお願いするのは駄目。**

壁紙の案内は前者（アルバムを作り続けるのは我々）。写真アプリでアルバムを作らせるのは後者。

> **促さない。報酬を置く。**

## 6. 未解決の衝突

| 衝突 | 検討中 |
|---|---|
| **窓の意味が曖昧になる** | 「3年前の今日」と「さっき撮った」が同じ枠に出る。**「いつ変わるか分からない」問題の再来**。→ 送られたものは一定時間優先し、「さっき」と分かる表示に |
| **過去の発掘が脇に追いやられる** | 即時性のほうが刺激が強い。**差別化の核が薄まる可能性**。配分の設計が必要 |
| アルバムを作り込むほど「開かせない」が薄まる | 用途が違う（日常 vs 見たいとき）ので致命傷ではないが、比重に注意 |
| 共有で製品の性質が変わる | 「静かなローカルの道具」から「サービス」へ。サーバー・運用・プライバシー申告 |

詳細はすべて **[共有設計.md](共有設計.md)** に移した。要点だけ：

| | |
|---|---|
| 採用 | **D案。** 長辺2048px／追記のみ／受領後7日・未受領30日／E2E |
| 見積 | 月$9〜11（1万人・1日1枚） |

## 8. 優先順位

```
1　オンボーディング　　　　　　　　　配れる状態を作る（決定済み）
2　「思い出」から写真をまとめる　　　　保存に目的を与える
3　共有　＋　撮って届ける　　　　　　本人2台の内部受入まで完了。一般公開運用は未完了
4　アルバム（bbox分類まで）　　　　　実装済み
5　単写真JPEG書き出し　　　　　　　 実装済み。物理的な本・プリント注文は後続
─────────────────────────
作らない　撮影の促し（催促）
作らない　自動個体識別（5-shot実機評価でNo-Go）
後回し　　専用モデル、フォロー、公開SNS
```

**3を一般へ配る前に、production moderation、監視、公開policy、App Store申告を完成させる。独立緊急OFFはflag・候補config・local dry-runまで実装済みだが、事前承認済みversionをactive version条件付きで切り替える実停止は未実装であり、対象productionでの訓練とともにrelease blockerとする。**

## 9. 検証の状態（正直に）

| | 状態 |
|---|---|
| **他人が使ったことがあるか** | **ゼロ人** |
| 本人が使って嬉しいか | **確認済み**（「既に嬉しい」「妻に見せたくなる」） |
| 即時共有に価値があるか | **本人所有2台で往復・Widget表示を確認済み。本人以外では未検証** |
| 思い出に残すが使われるか | **本人利用では確認済み。一般利用者では未検証** |
| 本が買われるか | **未検証**（本が存在しない） |

**方針として、オンボーディング・共有・アルバム・入力の仕組みが揃うまで、他のテストユーザーには出さない。** それまでは本人＋古いiPhoneの2台で検証する。共有は2台必要なので、開発上も自然な順番。
