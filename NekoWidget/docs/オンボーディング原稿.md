# オンボーディング原稿

作成：2026-08-19／現行構成へ更新：2026-09-10

この原稿は実装済みオンボーディングの利用者向け文言を管理する。

---

## 当時の課題（Build 14。現行では解消済み）

| 画面 | 状態 |
|---|---|
| 何のアプリかの説明 | **なし** |
| 写真アクセスの許可 | `PhotoPermissionView` あり |
| スキャンの進捗 | `ScanStatusView` あり |
| **ウィジェットの置き方** | 当時なし。現行は実装済み |
| 「思い出に残す」の説明 | 写真詳細の操作名と結果で案内。独立したオンボーディング画面にはしない |

**ウィジェットの案内がないため、渡された人は製品の核を一度も体験できない。**
ウィジェットの追加はOS側の5ステップ操作で、やったことがない人が多い。
**そしてアプリから自動で追加するAPIは存在しない。案内するしかない。**

---

## 全体の方針

- **最大4画面。それ以上増やさない。** 4画面目は実際に表示できる猫写真がある場合だけ
- **機能の一覧を見せない。** 「何が起きるか」だけ
- **「本が作れます」と言わない**（本は出口、入り口では言わない）
- **「家族と共有」を前面に出さない**（単身の人が離脱する）
- **写真アクセスはスキップできる。** スキップ時は写真が必要な説明を続けずアプリへ入り、「写真」と設定に許可・ウィジェット案内へ戻る導線を残す

## 1画面目：何のアプリか

更新：2026-10-22。1 画面目の仕事は説明ではなく、写真の許可を押してもらうことと、押すまでに離脱させないこと（LP を見て来る人は、何のアプリかは分かっている）。

```
　　［12 の窓。3 つに黒猫（ToolCat の絵）］

　　このiPhoneの中の猫を、全部見つけます。
　　写真はiPhoneの中だけで探します。外には送りません。

　　　　　　　　［猫を探す］
　　　　　　　　　あとで
```

**ポイント**
- 次に起きることを 1 行で言い、不安（写真が外に出る）に 1 行で答え、押してもらう。機能の違いは LP の仕事
- 「選択した写真のみ」の注意書きは置かない（価値が半減する選択を勧めない。許可の窓に選択肢はある）
- ボタンを押すと 2 画面目に進み、そこで iOS の写真の許可がすぐ出る（自前の説明ページで止めない）
- 「整理します」「容量が空きます」は言わない（後者は事実ではない）

## 2画面目：写真アクセスの許可

```
　　　このiPhoneの猫の写真や動画を
　　　端末内で見つけます。

　　　・解析はすべてこの端末の中で行います
　　　・写真や動画を開発者のサーバーへ自動送信しません
　　　・写真や動画を消したり変更したりしません

　　　　　［写真へのアクセスを許可］

　　　　　あとで（スキップ）
```

写真共有を有効にした限定Buildでは、上の3行だけを次に差し替える。

```text
　　　・解析はすべてこの端末の中で行います
　　　・写真共有は別に同意した後、選んだ縮小1枚だけを暗号化して送ります
　　　・原本の自動送信・削除・変更はしません
```

**ポイント**
- **不安を先に潰す。** 全ライブラリを読む許可を求めるので、ここで信頼を得る必要がある
- 「すべての写真へのアクセス」を推奨するが、**「選択した写真のみ」でも動く**ことを添える
- 既存の `NSPhotoLibraryUsageDescription` は合格しているので、文言はそれと揃える

## 3画面目：見つかっていく → 結果（第一印象）

更新：2026-10-21（10/21 レビュー、案 A）。探している途中から猫が「見つかっていく」のを見せる。

```
　　猫を探しています　　　　　　いま 32枚

　　［見つかった写真の 3×3 の格子。空きは薄い窓］

　　［進捗の細い線］
　　アプリを開いている間、新しい写真から順に調べます。

　　　　　　　［まどを置く］
　　　　　　　　写真を見る
```

探し終わると見出しが「猫の写真が見つかりました　128枚」になり、進捗の線が消える。

**ポイント**
- 数字を読ませるのではなく、自分の猫が並んでいくのを見せる。ここが第一印象
- 「まどを置く」が主。「写真を見る」は最初の 1 枚を開いて写真タブへ入る
- 0枚またはスキャン失敗では、空のWidget設置を教えず「写真」の修復導線へ進む（既存の分岐のまま）
- 全件で20〜60分かかるので、待たせない設計であることを 1 行で伝える
---

猫写真が見つかった結果画面の次ボタンは「ウィジェットの置き方へ」。今見つけた写真をホーム画面で楽しむ案内へ進むことを伝える。0枚・スキップ・権限限定の既存の分岐は維持し、最初に表示する写真を特定の一枚に固定する約束はしない。

## 4画面目：ウィジェットの置き方 ★最重要

**表示できる猫写真がある場合、ここが欠けていると製品が成立しない。**

```
　　　ホーム画面に、
　　　猫写真をひとつ。

　　　見つけた猫写真を、自分のホーム画面でも楽しめます。
　　　追加はホーム画面で行います。

　　　1　ホーム画面の何もないところを長押し
　　　2　「編集」→「ウィジェットを追加」
　　　3　「ねこのまど」を探し、好きな大きさで追加

　　　追加してアプリへ戻ると、自動で確認します。

　　　　　［手順を確認した］

　　　　　　　　あとで
```

### 1画面の手順

- iOS 18以降は **左上の「編集」→「ウィジェットを追加」** と表示する
- iOS 17は **左上の「＋」をタップ** と表示する
- 検索とサイズ選択は **「ねこのまど」を探し、好きな大きさで追加** の1手順にまとめる
- アプリからホーム画面への直接設置やWidget galleryの直接表示は案内しない

### 実装上の必須事項

- **設定画面から、いつでもこの案内を開き直せること**（一度スキップした人が戻れる）
- **表示できる猫写真があり、ウィジェットが未設置のときは、ホーム画面に「ウィジェットを置く」の導線を出す**
  （置いていない人は製品を体験していないので、そこを埋めるのが最優先）
- ホーム画面で追加してアプリへ戻ったときは、設置済みを自動確認して案内を閉じる
- カルーセル、動画、GIFは使わず、3手順を1画面で見せる

## 実装後に必ず確認すること

1. **写真アクセスをスキップするとアプリへ入り、「写真」と設定から許可・4画面目の案内へ戻れるか**
2. **ウィジェットが未設置のとき、ホーム画面に導線が出るか**
3. iOS 17とiOS 18以降で、2番目の手順が正しく切り替わるか
4. 0枚だった場合に、既存の空状態の案内へ正しく分岐するか

## 配布はオンボーディング実装後

**オンボーディングが入るまで、他人には配らない。**

理由：**ウィジェットの案内がない状態で渡すと、許可 → スキャン → 枚数を見る → 終わり**になり、
**製品の核（ホーム画面で猫写真が時間とともに巡る）を一度も体験せずに削除される。**

外部TestFlightへ進む前に、対象BuildのBeta App Review、共有環境の安全gate、写真・暗号化の申告がすべて揃っていることをBuild単位で確認する。過去Buildの承認や公開リンクの存在だけでは、次のBuildを配布できる根拠にしない。
