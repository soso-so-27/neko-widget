# 多頭管理：現行版と自動識別の判断

決定日：2026-09-05。対象：`codex/multi-cat-management`。

## 結論

猫ごとの写真・プロフィール管理を仕上げる。猫の自動個体識別は今回提供しない。猫登録を必須にせず、独立タブや全画面共通の猫切替も増やさない。

猫を検出すること、個体を見分けること、利用者が写真を指定することは別機能である。モデル候補の存在だけで「自動で分かれます」と案内しない。

## 今回の体験

| 場所 | 操作・役割 |
| --- | --- |
| 写真／設定 → ねこのプロフィール | 猫の一覧。登録しなくても既存機能は使える |
| 猫を追加 | 名前と任意の写真1枚で追加し、その猫のページへ進む |
| 猫のページ | 猫別の写真を見る／写真を選ぶ。既存の通常Photosアルバム連携は副操作 |
| プロフィール | 代表写真を固定、名前を編集、誕生日と迎えた日を両方保存 |
| 写っている猫を選ぶ | 複数枚をまとめて指定。1枚に複数の猫を指定でき、未選択のままでもよい |
| 自動アルバム | 既存の「みんな」を初期表示。必要な時だけ登録した猫へ絞る |

追加時の写真選択は12枚に限定しない。他の猫に指定済みの写真も選べる。プロフィール写真の変更は、その猫に指定済みの写真から選ぶ。写真を追加しただけで固定代表が変わることはない。

写真指定、名前、日付、追加、削除は永続保存の結果を待つ。失敗した場合は成功扱いで画面を閉じず、入力・選択を保持する。猫の指定画面に全写真からの除外操作を混ぜない。既存の写真メニューの全体除外は別操作として残す。

両方の日付を持つ場合は、成長・時間表示の基準を利用者が選べる。既存の基準は、もう一方の日付を追加しただけでは変えない。猫名が同じでも内部UUIDで区別し、名前の一意性を要求しない。

## データの境界

- 既存のschema 3へ任意フィールドを追加。旧データのUUID・所属・除外・単一日付を保つ。全写真を最初の猫へ自動割当しない。
- 誕生日／迎えた日は独立した値。既存の`lifeReference`は表示基準として維持し、明示的に両日を消した時は旧日付を復活させない。
- 代表写真は明示された所属のあるPhotoKit IDだけを保存。代表変更で所属は追加しない。所属を外した時は代表指定を解除するが、一時的な写真アクセス不能だけで解除しない。
- 写真は複製・移動・削除しない。既存の手動所属と通常Photosアルバム連携を再利用する。
- プロフィールと所属はこのiPhone内。共有相手・別端末へ自動同期しない。既存のbackup除外も変えないため、再インストール／機種変更でのプロフィール復元は提供しない。別途、明示的な復元設計が必要。
- 旧バイナリへのダウングレード後に保存すると、新フィールドを旧バイナリが落とす可能性はある。通常の旧版→新版アップデートと混同しない。

## 自動個体識別を延期する根拠

既存の[ADR-016](ADR-016-猫個体5-shot分離実験.md)の実機評価はNo-Goのまま。今回、同じ実験の再実行やユーザー写真の外部送信は行わない。

| 候補 | 確認した根拠 | 判断 |
| --- | --- | --- |
| [PetFace](https://github.com/mapooon/PetFace) | 個体識別用のデータ・コード・重みを公開。ただし全て非商用研究限定と明記 | 商用アプリ同梱候補から除外 |
| [open-noodle/pet-recognition-small](https://huggingface.co/open-noodle/pet-recognition-small) | DINOv2-small＋個体識別用512次元射影。Apache-2.0表記。ONNX重み89,227,604 bytesが公開 | 次回の技術試作候補。現時点で採用しない |

第二候補の確認revision：`9dd4c915be29a81b116b3e30eb996c59d0e7ede0`。[公開ファイル情報](https://huggingface.co/api/models/open-noodle/pet-recognition-small/tree/main/recognition)を確認しただけで、今回重みはダウンロードしていない。

作者が挙げる学習元は[Cat Individual Images](https://www.kaggle.com/datasets/timost1234/cat-individuals)（CC BY 4.0）と[Dogs of the World](https://www.kaggle.com/datasets/lextoumbourou/dogs-world)（CC0）、基盤は[DINOv2-small](https://huggingface.co/facebook/dinov2-small)（Apache-2.0）。公開条件の確認であり、学習の再現・元画像の権利・配布表記の監査完了ではない。猫データにSNS由来の画像が含まれるという説明もある。

作者のTop-1約91.3%は、家庭内5枚登録・知らない猫の拒否・iPhone上の性能を証明しない。Core ML版や射影のPyTorch checkpointは公開一覧で確認できず、変換成功も未確認。[Appleの変換ガイド](https://apple.github.io/coremltools/docs-guides/source/convert-pytorch.html)はPyTorchからの直接変換を推奨し、[旧ONNX変換器は保守終了](https://apple.github.io/coremltools/docs-guides/source/faqs.html)。不可能と断定せず、端末実装の検証が別に必要と判断する。

Apple Photosの個体グループは[公開PhotoKit subtype一覧](https://developer.apple.com/documentation/photos/phassetcollectionsubtype)から取得できる前提を置けない。通常アルバムを利用者が明示的につなぐ既存方式を維持する。

## 次回の小さなGo／No-Go

1. 第二候補だけの配布条件と変換経路を確認。変換前後の数値一致、最低対応iPhoneの時間・メモリ・サイズを実測する。変換に合理的な経路がなければここで止める。
2. 各猫5枚の登録と、別撮影場面の未使用写真で少数評価する。読み取り・切り抜き失敗も未判定として分母に残す。閾値は評価前に固定。既存ADRのprecision 95%以上・coverage 70%以上に届くかを測る。
3. 合格しても一般提供の承認ではない。家庭を分離した未知データ、別猫trial、似た毛柄、複数猫、成長・照明・横顔を含む独立評価へ進む。既存ADRの一般提供条件も維持する。
4. 最初の提供形態は確認できる「候補」。間違いを戻せること、確認の手間が手動より減ることを評価する。機械候補を確定所属へ直接書き込まない。

今は新たなモデル実行基盤・候補DB・クラウドAPI・自動学習を追加しない。既存のUUID、複数所属、明示確認の書き込み境界を将来も使う。

## 検証範囲

旧schema 3読込、複数猫所属、両日保持・基準維持・明示削除、固定代表写真と所属解除、Limited Photos時の保持、候補写真の全件選択と重複排除を対象テストへ追加。iOSコンパイルと既存移行・保存テストは候補SHAのCIで確認する。自動識別の精度検証や実機での見た目確認と、コンパイル合格は区別する。
