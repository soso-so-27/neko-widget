# ADR-013：bbox姿勢アルバムを実機評価で撤回する

日付: 2026-08-20
更新: 2026-08-21
状態: 一部採用・姿勢アルバムへの利用は撤回

## 背景

関節点ベースの姿勢分類は、実機896枚のうち猫と骨格を対応付けられた730枚に対し、関節品質を通過したのが83枚、最終分類が1枚だった。閾値を一括で緩めると誤分類を増やすため、製品アルバムの判定には使わない。

一方、猫検出時の個体別bounding boxは既存写真896枚すべてで利用できた。Build 19では保存済みboxの正規化座標における `width / height` を、次の体勢名へ割り当てた。

- `2.0以上`: ねてる
- `0.9以上1.1以下`: まるまり
- `0.9未満`: おすわり
- `1.1より大きく2.0未満`: 分類しない

実機では「ねてる」136枚、「まるまり」129枚、「おすわり」276枚となったが、目視すると立つ、歩く、人と写る、縦横の構図が違うだけの写真が大量に混在した。bboxは姿勢を表す情報ではなく、画像の向きにも影響されるため、件数を増やせても意味のある体勢分類にはならなかった。

## 最終決定

1. 関節点を姿勢アルバムの判定に使わない。
2. `VNDetectAnimalBodyPoseRequest` と再試行導線を廃止する。
3. 新規スキャンでは `VNRecognizeAnimalsRequest` が返した個体別bounding boxを保存する。
4. 既存データは、保存済み `postureInstances[].boundingBox` を個体別boxへローカル移行する。単頭写真だけはunion boxをfallbackにできる。多頭写真のunion boxは使わない。
5. bbox比率は診断分布としてだけ保持し、`ねてる／まるまり／おすわり`を製品アルバムへ表示しない。
6. bbox面積は構図を表すため、`どアップ`にだけ利用できる。
7. bboxの保存・移行・診断のためにPhotoKitやVisionを再実行しない。

## アルバムとしての組み立て

検出済みの全猫写真を母数とし、Widget用の面積8%条件では絞らない。空のアルバムを省き、次の価値軸へ戻す。

- 時間
  - 日付未設定または多頭の「みんな」: 撮影年ごと
  - プロフィール作成後の「みんな」: 各猫の確認済み所属だけから `むぎの成長` のような個体別カードを並べ、猫を混ぜた1本の成長アルバムは作らない
  - 誕生日設定済み: `成長`、`子猫のころ`、`◯歳のころ`
  - 迎えた日設定済み: `成長`、`お迎えしたころ`、`いっしょに暮らして◯年`
- かわいさ
  - `どアップ`: 個体box面積が50%以上
- 特別
  - `人といっしょ`: 猫写真で人物の顔を検出
  - `猫たち`: 猫の検出数が2以上。2匹に限定せず、プロフィール数でも隠さない
  - `おでかけ`: 既存の端末内位置判定
  - `猫の日`: 2月22日に撮影された写真

誕生日や迎えた日より前の写真を、その基準による期間アルバムへ入れない。プロフィール未設定の「みんな」では、個体の日付を混ぜず撮影年を使う。

## 比率の意味

診断値は実測時と同じ、Vision正規化座標の `width / height` を `vision-normalized-width-height-v1` として固定する。画像のピクセル縦横比は補正しない。この値を製品上の体勢名へ再び割り当てない。

## 互換性

旧 `CatPostureTag`、姿勢診断、pose instanceのCodable fieldは過去snapshotを復号するため残すが、現行のアルバム生成には使わない。旧 `postureRepair` は読込時に解除し、新たなscan purposeとして起動しない。

## 検証条件

- bbox診断の境界値 `0.9 / 1.1 / 2.0` が既存仕様どおりである
- 個体別boxがある場合はそれを最優先する
- 多頭unionを個体boxとして使わない
- profileのsubject box不一致時に推測しない
- 旧snapshotがローカル移行だけでcurrentになる
- body-pose requestがscannerへ再導入されていない
- `ねてる／まるまり／おすわり`が現行一覧に出ない
- 撮影年、成長、誕生日、迎えた日基準の期間アルバムが復元される
- 人との同写と複数猫が別ID・別条件になる
- 3匹以上の写真も`猫たち`へ入り、2匹と断定しない
- 0件のアルバムを表示しない
