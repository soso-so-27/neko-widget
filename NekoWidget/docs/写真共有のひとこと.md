# 写真共有の任意のひとこと

2026-09-08。Build134のブロック改善とは別の本線バッチ。写真を届ける際、その一枚について短く伝えられるようにする。

## 初版の範囲

- まど内の写真選択後、「写真を確認」で任意入力する。100文字まで、改行2個まで。前後の空白を除き、空白だけなら文字なし。長すぎる入力を黙って切り詰めず、その場で案内して送信を止める。
- 写真の下に表示する。届けた一覧から詳細を開いて全文を読める。届いた写真も詳細で全文を読める。大きな文字とキーボード表示時はスクロールできる。
- 空欄の送信を維持する。猫登録・共有・文字入力を必須にしない。
- 写真・届け先の確定と同時にひとことを固定する。キャンセルや次の写真選択で前の入力を引き継がない。宛先が変わった場合は既存の確認境界で送信を止め、写真を選び直す。失敗再試行は同じ写真・宛先・ひとことを用いる。

## 保存・互換性

- 既存の暗号化manifestへoptional captionを追加。写真のハッシュ・宛先context・暗号化鍵とともに保護し、サーバー平文の新項目や新migrationは作らない。ログや通知本文へ載せない。
- protocol version 2のまま。新しいアプリはcaptionなしの旧写真を読める。Build134以前は未知のcaption項目を無視して写真を受け取る。旧版で文字が表示されるとは案内しない。
- 端末内の保護された準備・送信・受信記録で、対応する写真と同じ保持・削除条件に従う。写真の失効や削除で行だけ残す場合もcaptionを消す。画面を開いたまま状態が変わっても、削除済み文字を表示し続けない。
- 100文字の判定はSwiftのCharacter単位。結合文字が極端に大きくなる入力にはUTF-8で4,096 bytesの上限も適用する。改行形式を揃えて保存する。
- 写真アプリへの保存、思い出への写真取り込み、Widgetは写真のみ。文字を写真へ焼き込まない。OS共有拡張の文字入力・文字だけの送信・送信後編集は初版に追加しない。
- 相手端末への到着は既読ではない。任意の文字を読んだ証拠には使わない。

## 完了条件と検証

文字あり／なし、新旧manifest、上限と改行、異なる写真・contextの取り違え拒否、準備再試行、取消・失効・削除を対象の既存テストで確認する。送信済み一覧の並び替え・件数制限でもcaptionが元の一枚から移らないことを確認する。コアとUIを別担当がレビューし、候補SHAのiOSビルドと共有runtimeを確認する。現在使える価値として紹介するのは配布後とし、実機での表示・入力確認はCIと区別して記録する。

一般公開・外部招待・審査・課金開始、猫個体識別研究をこのバッチの条件にしない。
