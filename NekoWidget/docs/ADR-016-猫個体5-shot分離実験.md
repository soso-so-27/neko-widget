# ADR-016：猫個体UIより先に5-shot＋正解付き評価を行う

日付: 2026-08-21
状態: Experiment

## 背景

Build 18の「似た写真をまとめて確認」は、保存済みの個体別bboxを使っていたが、約900件を教師なしk-medoidsで最大20群へ強制分割し、低確信を`unknown`へ逃がさなかった。実機では何十回も分岐が必要になり、個体分類を完了できなかった。

したがって「bbox切り抜きを追加する」実験ではなく、各猫5枚の正解例を使う教師あり判定と、低確信を`unknown`へ退避する方式を測る。ただし学習用10枚だけでは精度を測れないため、別に正解付き評価30枚を用意する。

## 標本

2プロフィールに限定し、各猫20枚、合計40枚を利用者がラベル付けする。

- 各猫の最初の5枚：学習用。合計10枚
- 各猫の残り15枚：答えを隠して判定する評価用。合計30枚
- 製品化した場合に利用者へ求める予定の入力は各猫5枚のまま。40枚は実験の精度測定だけに使う
- 評価用には時期・明るさ・姿勢を散らし、暗い、後ろ姿・横顔、遠い、一部が隠れた写真を意図的に含める
- 個体別bboxと現在のdetector instanceが対応できる単頭写真だけを使う。多頭写真のunion bboxは使わない
- 同一asset、同一burst、30秒以内の撮影、ほぼ同一のcropは同じepisodeとして扱う
- 40枚は40個の独立episodeでなければ計測不能とする。学習と評価で同じepisodeを共有しない
- 写真や特徴量を読み取れない評価例は除外や差し替えをせず`unknown`として分母30に残す

## 比較する方式

同じ学習10枚・評価30枚で次を比較する。

1. FeaturePrint Revision 2、個体bboxの各辺を10%拡張（Build 18と同じ前処理。比較用baseline）
2. FeaturePrint Revision 2、余白を足さないexact bbox
3. exact bboxのHSV色ヒストグラムとHellinger距離

分類は、対象プロフィールの学習5枚との距離のうち近い3枚の中央値を使う。次の両方を満たさなければ所属を決めず`unknown`にする。

- 最良プロフィールへの距離が、そのプロフィールの基準半径の1.25倍以内
- 最良距離 ÷ 次点距離が0.70以下

閾値はprotocol v2として計測前に固定する。評価30枚を見た後で閾値や標本を変更し、同じ30枚を合格判定へ再利用しない。

## 指標

評価30枚に対し、方式ごとに次を集計する。

- `assigned = correct + wrong`
- 正解率（precision）=`correct / assigned`
- 判定できた割合（coverage）=`assigned / 30`
- `unknown = 30 - assigned`
- 各猫15枚について同じcorrect / wrong / unknown / precision / coverage
- confusion matrix
- 誤判定した評価写真の端末内サムネイル

丸めた百分率だけでなく、必ず`correct / assigned`と`assigned / 30`を併記する。`18 / 19 = 94.736...%`を表示上95%へ丸めても合格にしない。判定は整数の交差乗算で行う。

未ラベル候補へ読み取り専用で適用したcoverageは補助情報として出せるが、正解率を計算せず、採否条件にも使わない。

## 事前に固定する判断

評価30枚を全件処理し、各猫15枚の内訳も確認したうえで、利用者が先に固定した全体指標で判断する。猫別の数字は偏りを見つけるために表示するが、今回の停止条件へ後付けしない。

1. exact bbox FeaturePrintが全体で正解率95%以上、判定率70%以上なら、5-shot FeaturePrint＋unknownを次の製品実装候補にする
2. exact bbox FeaturePrintの全体正解率は95%以上だが全体判定率が70%未満で、色ヒストグラムが全体で正解率95%以上、判定率70%以上なら、色方式を「見た目が十分違う家庭」限定の候補にする
3. exact bbox FeaturePrintの正解率が95%未満、または色方式も条件を満たさないなら、個体識別を実装せず「この家の猫たち」の成長1本で止める

30枚ではcoverage 70%以上はassigned 21枚以上を意味する。assignedが21〜30枚の範囲ではwrongは最大1枚までである。猫別15枚のprecision、coverage、confusionも必ず表示し、一方の猫だけで数字を稼いでいないかを実機判断材料にする。

色方式を採るには、上記に加えて色ヒストグラムの`最小別猫距離 ÷ 最大同猫距離`が1.5以上であることを求める。10%拡張FeaturePrintはbaselineであり、製品方式の合格候補にはしない。

この評価30枚は3方式の選択にも使うため、一般家庭での最終精度を証明する独立test setではない。製品UIを一般提供する前に、家庭を分離した未使用集合と、少なくとも300件の独立した別猫trialでfalse accept 0件を別途確認する。

## 実装境界

- Build 22では「設定＞詳細・診断」からだけ起動する
- 実験はmembership、参照写真、除外、ライブラリsnapshot、アルバム、Widgetを変更しない
- 自動予測を教師へ戻さない
- 写真取得は`networkAccessAllowed = false`
- FeaturePrint、ヒストグラム、距離行列はメモリ内だけで、終了時に破棄する
- 誤判定写真の対応表は非Codableな端末内状態だけに保持し、画面を閉じる／取消時に破棄する
- 写真、crop、PhotoKit identifier、プロフィール名／UUID、撮影日時、bbox、誤判定ordinal、個別距離、特徴量をログ・JSON・共有・Workerへ出さない
- 共有できるのは集計件数、率、個別標本へ逆引きできない距離分位点と色分離比、method、protocol version、理由コードだけ

実機数値が出るまでは状態を`Experiment`のままにし、結果を理由に個体所属を自動変更しない。
