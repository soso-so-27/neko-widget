# 複数猫：写真から始める導線

更新日：2026-09-10
状態：候補のiOSビルド・起動確認は成功。操作確認で見つかった2点を修正し、再検証中。配布は未実施。

## 今回の範囲

- 「猫ごとの写真」を開き、猫を選ぶと写真一覧を表示する。名前・誕生日・アルバム連携などは右上の設定へ置く。
- 猫の追加は写真1枚の選択から始め、名前を付けて確定する。「写真はあとで」も選べる。
- 写真一覧は閲覧を初期状態とし、編集は「選択」から開始する。写真をタップすると全体を表示する。
- 「この子の写真を追加」では選択した写真を既存の追加処理で明示的に登録する。別の猫の所属は置き換えない。
- 一緒に写っている猫は既存の複数選択画面で選べる。保存成功後だけ一覧へ戻り、失敗時は選択を残す。
- 「候補○枚」という、個体識別済みと誤認される表示を外す。

保存形式、所属モデル、写真取得処理、共有、Widget、課金、ONNXモデルは変更しない。
自動の個体識別や候補グループの通常画面への公開は行わない。

## 次の候補機能の判断基準

目標は「プロフィール登録を増やす」ことではなく、猫別に見返すための確認作業を減らすこと。
共有チャットのアイデアは仮説として扱い、既存の失敗を繰り返さない。

- [ADR-016](ADR-016-猫個体5-shot分離実験.md)の実機結果を再利用する。既存のFeaturePrint＋矩形領域を未検証の新方式として再実装しない。
- 写真全体を固定グループ数へ強制分割しない。まとまりにくい写真は未分類に残す。
- 「似ているグループ」と「同じ猫」を区別する。同じ猫の別の姿勢が別グループでもよい。
- 所属は確認後だけ確定する。既存の手動確定を自動で上書きしない。
- 自動判定の正確さと、候補を確認する時間・修正回数を分けて評価する。手動より楽にならない方式は公開しない。
- 美的評価による代表写真の提案と、背景を除く切り抜きは、個体識別とは独立した改善候補とする。
- 今回これらの候補生成・美的評価・背景切り抜きの新規実装はしていない。

### 初回のSimulator操作で見つかった問題

- CI `34361768306`：写真を選んでも命名画面で未選択へ戻り、作成直後が0枚になった。Boolによるシート表示と別管理の写真IDを、写真ID付きのIdentifiableリクエストによる表示へ変更。命名画面のStateもリクエスト単位にする。
- 同CIの既存送信テスト：生成画像の先読みがPhotoKitへ架空IDを渡し、写真アクセスのOSダイアログで操作が妨げられた。DEBUGの生成画像IDを先読みから除き、空ならPhotoKitを呼ばない。PhotoWindow fixtureの通常サービス・起動cleanup・設定リセットも抑止。Releaseの写真取得動作は変えない。
- 新しい猫の画面と修正箇所の独立レビューを実施。写真の所属・失敗時の選択保持・Release境界に未解決の阻害点なし。実機の個体識別精度を示す検証ではない。
