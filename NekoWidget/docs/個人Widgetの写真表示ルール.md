# 自分の猫写真をWidgetで楽しむための表示ルール

2026-09-10。対象は自分の写真ライブラリのWidget。親しい相手から届く写真のWidget、猫の個体識別、写真原本の編集とは分ける。

## 現在の選定と表示

| 段階 | ルール |
| --- | --- |
| 写真の対象 | 本人の写真へのアクセス、対象範囲・期間・除外、現在の検出設定とWidget適格性を尊重する。取得できない写真をダウンロードして穴埋めしない |
| 候補の優先 | 過去30日以内にWidget用として選定した写真を後回しにする。各区分では「思い出に残した」写真やPhotosのお気に入りの既存の重みを維持する |
| 一巡の枚数 | 端末で利用できる候補を最大20枚まで用意し、それぞれ1回ずつ巡回する。少数の写真を20枠まで水増ししない。1枚だけならその1枚を表示する |
| 巡回の続き | Widgetは予定時刻を基準に候補の続きへ進む。1回に渡す将来の表示は最大2件。複数枚の切り替え間隔は既存の設定（既定20分）を維持し、OSの実行を20分ちょうどとは保証しない。1枚の場合は同じ写真を保ち、予定間隔を推定できない時の既存20分基準で再読込を要求する |
| 思い出に残す操作 | 操作した写真への結果表示を維持する。保存操作による短い表示優先は、通常の巡回と別の意図的な例外 |
| 写真の収まり | 写真面を埋め、猫の検出位置を活かす。小・大で周囲の余白が入り切らない時も、写真中央へ戻して猫を落とさない。検出位置がなければ中央。猫全体が枠より大きい場合に全身を保証するルールではない |

## 今回直す問題

従来は、例えば19枚を20枠に繰り返して入れるため、`A…S、A｜A…` と一巡の境界で同じ写真が続いた。3枚では20枠の中でA・Bが7回、Cが6回となった。個人manifestは利用できる写真を一度ずつ保持し、Widget側も旧版の水増しmanifestを重複なしで読む。写真ID、初回の予定日時、各サイズのキャッシュとの対応は保持する。

小・大の切り抜きでは、猫の周囲に確保する余白だけが枠を超えた場合にも、猫の位置を使わず中央を切り抜いていた。既存の猫中心の切り抜きをローカル表示用の一時planとして使う。共有用に保存する元のrenderPlans、rendererVersion、暗号化・受信のgeometryは変更せず、ローカルキャッシュのrevisionだけ更新する。

## 確認範囲

- 実コードの巡回ポリシーで1〜20枚、旧版の重複、順序・日時・各サイズ画像の対応、欠損で絞られた候補、最大20枚を確認する。
- 合成した端寄りの被写体で、小・大の実JPEGが意図した側を残すことを確認する。周囲の余白だけが超過する場合、猫自体が大きい場合、検出位置なし・無効を区別する。
- 既存の写真保持・共有境界・候補CIを維持する。撮影時の似た写真の連続や、新旧の配分をこの変更で改善済みとはしない。

`lastShownAt`と`shownCount`はキャッシュ選定時の記録であり、利用者が実際に見た回数ではない。選定結果の好み、普段の写真での構図、設置済みWidgetの実際の更新は別の体験品質の確認として残す。

根拠：`PhotoSelectors.swift`、`WidgetCacheBuilder.swift`、`WidgetManifest.swift`、`NekoWidgetTimelineProvider.swift`、[Timelineの負荷制限](ADR-008-高解像度WidgetのTimeline負荷制限.md)。
